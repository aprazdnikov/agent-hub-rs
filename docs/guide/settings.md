## Окно и трей

| Вкладка | Что там |
|---|---|
| **Статус** | Состояние бота и ошибка, «Запустить» / «Остановить», версии agent-hub и агентов; для Qwen — источник ключа, для Hermes — собственная настройка с непроверенным входом; число активных сессий |
| **Темы** | Темы с бэкендом, директорией, сокращённым session_id (клик копирует полный) и статусом; «Stop» и «Reset» |
| **Лог** | Последние 500 строк, фильтр уровня, автопрокрутка, «Открыть папку логов», кнопки для `rejected update` |
| **Настройки** | Разделы с боковым меню, отдельные страницы агентов и проверка полей; «Сохранить» активна, только когда ошибок нет |

Светлая и тёмная темы автоматически следуют настройкам системы, в том числе при смене
темы во время работы приложения.
В Linux тема считывается через [XDG Desktop Portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Settings.html);
автоматическое переключение требует поддержки портала окружением рабочего стола.

Настройки разделены на **Telegram и доступ**, **Рабочие каталоги**, **Агенты**, **Проекты**,
**Действия**, **Голосовые сообщения**, **Запуск и обновления**. В узком окне раздел выбирается
из выпадающего списка. В разделе «Агенты» вкладка «Общие» содержит агента по умолчанию
и таймауты, а каждый агент имеет свою страницу параметров.

Переключение разделов сохраняет несохранённые правки в общем черновике. Кнопки «Сохранить»
и «Отменить изменения» закреплены внизу; они применяются ко всем разделам. Счётчики рядом
с разделами и агентами показывают ошибки, а «Исправить ошибки» открывает страницу с первой
ошибкой. При подстановке chat_id или user_id из лога открывается «Telegram и доступ».

Значок в трее: **зелёный** — бот подключён, **серый** — остановлен или не настроен,
**красный** — ошибка. Подсказка показывает число активных сессий. Меню: «Открыть»,
«Запустить/Остановить бота», пункт обновления, «Выход».

Закрытие окна прячет его в трей, бот продолжает работать. Полный выход — «Выход» в меню
трея: работающие темы получат «⏹ Остановлено». Если значка в трее нет, закрытие окна
завершает приложение. Второй экземпляр не запустится — он сообщит, что agent-hub уже работает.

## Автозапуск при входе

В «Настройки → Запуск и обновления → Автозапуск приложения» доступны «Включить», «Выключить» и «Проверить
состояние». Изменение применяется сразу для текущего пользователя, отдельно от
«Сохранить» и без перезапуска бота. По умолчанию приложение ничего не регистрирует.
Статус считывается из ОС; после изменения системных настроек нажмите «Проверить состояние».

| ОС | Регистрация |
|---|---|
| Linux | `$XDG_CONFIG_HOME/autostart/io.github.aprazdnikov.agent-hub.desktop`, по умолчанию `~/.config/autostart/`; отключение перекрывает одноимённую системную запись через `Hidden=true` |
| Windows | Значение `Agent Hub` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; учитывается отключение через «Приложения → Автозагрузка» или диспетчер задач |
| macOS | `~/Library/LaunchAgents/io.github.aprazdnikov.agent-hub.autostart.plist`; учитываются запрет launchd и разрешение фоновых программ |

Если Windows отключила запись или macOS требует разрешения фоновой работы, интерфейс
покажет это вместо успешного включения. Изменённый путь требует явного повторного
включения из нужной копии приложения. Встроенное обновление на прежнем пути сохраняет
регистрацию. Чужие или повреждённые файлы регистрации не перезаписываются.

При автозапуске (`--autostart`) готовое к работе приложение сворачивается на Linux
и скрывает окно на Windows/macOS при доступном трее. Без настроек или без трея окно
остаётся открытым. Повторный автозапуск тихо завершается, если экземпляр уже работает.
Linux-композитор может ограничивать сворачивание окна; приложение остаётся доступным
через панель задач. Автозапуск хаба не подключает VPN и не запускает пользовательские действия.

Реализация следует [XDG Autostart](https://specifications.freedesktop.org/autostart/latest/),
[Windows Run](https://learn.microsoft.com/windows/win32/setupapi/run-and-runonce-registry-keys)
и [Apple LaunchAgents](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html).

## Настройки и файлы

| Параметр | По умолчанию | Применяется |
|---|---|---|
| Токен бота, chat_id группы, разрешённые user_id | — | сразу: бот перезапускается, активные сессии прерываются (окно спросит подтверждение) |
| Корень рабочих каталогов | — | с новой сессии |
| Агент по умолчанию (`claude`, `codex`, `qwen`, `hermes`) | `claude` | с новой сессии |
| Путь к `claude` | из `PATH` | с новой сессии |
| Модель | из настроек Claude Code | с новой сессии |
| Режим разрешений (`default`, `acceptEdits`, `plan`, `bypassPermissions`) | `default` | с новой сессии |
| Лимит расходов на задачу, $ | без лимита | с новой сессии |
| Путь к `codex` | из `PATH` | с новой сессии |
| Модель Codex | из настроек Codex | с новой сессии |
| Песочница Codex (`read-only`, `workspace-write`, `danger-full-access`) | `workspace-write` | с новой сессии |
| Одобрения Codex (`untrusted`, `on-request`, `never`) | `on-request` | с новой сессии |
| API-ключ OpenAI | нет (вход `codex login`) | с новой сессии |
| Путь к `qwen` | из `PATH` | с новой сессии |
| Модель Qwen | из настроек Qwen | с новой сессии |
| Одобрения Qwen (`plan`, `default`, `auto-edit`, `yolo`) | `default` | с новой сессии |
| Base URL и API-ключ Qwen | нет (собственная настройка qwen) | с новой сессии |
| Путь к `hermes` | из `PATH` | с новой сессии |
| Профиль Hermes | выбирает Hermes | с новой сессии |
| Модель Hermes | из настроек Hermes | с новой сессии |
| Ожидание подтверждения, с | 600 | с новой сессии |
| Фоновые задачи, с | 1800 | с новой сессии |
| Каталог снимков | `~/.agent-hub` | сразу |
| Проверять обновления | да | сразу |

В `settings.toml` это таблицы `[agents]` (`default`), `[codex]` (`cli`, `model`, `sandbox`,
`approval`), `[qwen]` (`cli`, `model`, `approval`, `base_url`) и `[hermes]` (`cli`, `profile`,
`model`) и `[snapshots]` (`dir`); API-ключ OpenAI хранится в
системном хранилище ключей (`agent-hub` / `openai-api-key`), ключ Qwen — там же (`agent-hub` /
`qwen-api-key`), не в файле. При запуске бота обязателен только агент по умолчанию; если
второй недоступен, бот работает, а на вкладке «Статус» видна причина. Там же — версия каждого
агента, способ входа в Codex и источник ключа Qwen.

Если Telegram недоступен при запуске (например, сеть ещё не поднялась), бот повторяет
подключение сам: через 5 с, затем с удвоением паузы до 5 минут.

Где хранятся данные:

| Что | Windows | macOS | Linux |
|---|---|---|---|
| Настройки (`settings.toml`) | `%APPDATA%\agent-hub\config\` | `~/Library/Application Support/agent-hub/` | `~/.config/agent-hub/` |
| Токен бота, API-ключи OpenAI и Qwen | Диспетчер учётных данных | Связка ключей | Secret Service (GNOME Keyring, KWallet) |
| Привязки тем (`topics.json`) | `%APPDATA%\agent-hub\data\` | `~/Library/Application Support/agent-hub/` | `~/.local/share/agent-hub/` |
| Названия тем (`topics.titles.json`) | `%APPDATA%\agent-hub\data\` | `~/Library/Application Support/agent-hub/` | `~/.local/share/agent-hub/` |
| Последние ответы (`topics.results.json`) | `%APPDATA%\agent-hub\data\` | `~/Library/Application Support/agent-hub/` | `~/.local/share/agent-hub/` |
| Последние проекты (`topics.projects.json`) | `%APPDATA%\agent-hub\data\` | `~/Library/Application Support/agent-hub/` | `~/.local/share/agent-hub/` |
| Снимки сессий | `~\.agent-hub\snapshots\` (или из настроек) | `~/.agent-hub/snapshots/` | `~/.agent-hub/snapshots/` |
| Логи (`logs/`, 14 дней) | `%APPDATA%\agent-hub\data\logs\` | `~/Library/Application Support/agent-hub/logs/` | `~/.local/share/agent-hub/logs/` |

Настройки 0.5.0 содержат таблицу `[snapshots]`, которую 0.4.x не читает: после возврата на 0.4.x уберите её из `settings.toml`, а снимки останутся на диске.

Формат `topics.json` совпадает с Python-версией agent-hub — файл можно скопировать.
Названия хранятся отдельно в `topics.titles.json`; отсутствие этого файла не мешает запуску.
Прежние версии продолжают читать привязки сессий, но не обновляют файл названий.
`topics.projects.json` содержит последние ID проектов; отсутствие файла означает пустую историю.
Повреждённый `topics.json`, `topics.titles.json` или `topics.projects.json` не перезаписывается: бот не стартует,
а в окне видно путь к файлу и причину. Если название не удалось записать во время работы,
бот предупреждает об этом в теме; новое имя остаётся в памяти до перезапуска.

## Обновления

agent-hub проверяет [Releases](https://github.com/aprazdnikov/agent-hub-rs/releases) при
запуске и раз в сутки. Найдя новую версию, показывает баннер в окне и пункт в меню трея.
Установка — только по кнопке «Установить»: приложение скачивает файл своей платформы, сверяет
SHA-256 и заменяет себя; затем кнопка «Перезапустить» (если есть активные сессии, окно спросит
подтверждение). Проверку можно выключить в «Настройках».

На macOS внутри `.app` обновляется только `Contents/MacOS/agent-hub`, без замены всего
пакета: версия в Finder (`Info.plist`) и иконка останутся от первоначальной установки.
Чтобы обновить их, скачайте новый `.app.zip` и замените приложение после выхода из него.
Подписанный пакет потребует отдельного механизма обновления; текущая упаковка не добавляет
подпись пакета и не меняет путь исполняемого файла или источник обновлений.

Контрольная сумма лежит в том же релизе: она защищает от повреждённой загрузки, но не от
компрометации GitHub-аккаунта. Подпись релизов пока не делается.
