# Агенты и лимиты

[Документация](../README.md) · [О проекте](../../README.md)

Для локальной задачи выберите установленный CLI в поле «Агент для новых задач».
В теме Telegram команда `/new агент путь` создаёт сессию, а `/backend агент`
меняет исполнителя темы со сбросом контекста. Назначение другого исполнителя
сохранённой задаче доступно в её параметрах. [Требования к CLI](getting-started.md#требования)

## Claude Code

Запустите `claude` в терминале и выполните вход. В **Настройки → Агенты → Claude Code**
можно указать путь к CLI, модель, режим разрешений и лимит расходов на задачу.
При пустой модели действует выбор самого Claude Code. Права, инструкции проекта
и разрешения на инструменты берутся также из его обычных настроек.
[Разрешения и вопросы](messages.md#подтверждение-действий)

## Codex

Установите Codex CLI, например командой `npm i -g @openai/codex`. В теме Telegram
используйте `/new codex <путь>` или `/backend codex`.

Выберите способ входа в Codex.

- подписка ChatGPT: выполните `codex login` в терминале один раз;
- API-ключ OpenAI: укажите его в «Настройки → Агенты → Codex». Ключ используется, только если входа нет или это уже вход по ключу; вход по подписке ChatGPT не заменяется (для перехода на ключ — `codex logout`).

Права Codex задаются в «Настройки → Агенты → Codex»: песочница (`read-only`, `workspace-write` — по умолчанию, `danger-full-access`) и одобрения (`untrusted`, `on-request` — по умолчанию, `never`). Одобрения команд и правок приходят в тему кнопками, как у Claude. В итоге хода Codex показывает число токенов в сессии; фоновых задач у Codex нет.

## Qwen

Для установки через npm выполните `npm i -g @qwen-code/qwen-code` с Node.js 22+.
Хаб поддерживает Qwen Code от 0.25.0. Команда `/new qwen <путь>` создаёт сессию
Qwen Code в текущей теме. В обычной сессии доступны одобрения кнопками, `send_file`,
вопросы с вариантами, фото и число токенов по итогам хода. Дополнительные сообщения
Qwen забирает между вызовами инструментов.

Настройте собственный доступ к модели одним из двух способов.

- собственная настройка `qwen`: выполните `qwen` в терминале и `/auth`, или заполните `~/.qwen/settings.json`, или задайте переменные окружения;
- «Настройки → Агенты → Qwen Code»: OpenAI-совместимый base URL и API-ключ (например, DashScope). Ключ хранится в системном хранилище ключей и передаётся только процессу `qwen` (как `OPENAI_API_KEY`).

Режим одобрений — `plan`, `default` (по умолчанию), `auto-edit`, `yolo`. Отправка файла инструментом хаба (`send_file`) тоже спрашивает разрешение кнопкой, как любой инструмент (кроме `yolo`). «Разрешить всегда» не предлагается.

Если задан base URL хаба, а модель в настройках пуста, `qwen` получит `OPENAI_MODEL` из окружения, в котором запущен agent-hub.

## Hermes

`/new hermes <путь>` создаёт сессию Hermes в текущей теме, `/backend hermes` переключает тему
со сбросом контекста. Хаб запускает `hermes acp` через stdio: Telegram остаётся транспортом
agent-hub, отдельный Hermes gateway не запускается.

В «Настройки → Агенты → Hermes» задаются путь к CLI, необязательные профиль, модель и режим
одобрений. Пустой профиль
оставляет выбор самому Hermes; заданный передаётся как `--profile NAME`, без смены его
постоянного профиля. Модель применяется к сессии через ACP. Вход, провайдер, память, скиллы
и собственные MCP-серверы остаются в управлении Hermes; хаб не записывает его ключи или
конфигурацию. Для браузерных инструментов и прочих зависимостей используйте настройку Hermes.

Ответы и вызовы инструментов переводятся в события хаба. Запросы разрешений проходят через
кнопки Telegram; хаб выбирает только предложенное разовое разрешение, не «разрешить всегда».
Файлы и вопросы передаются через защищённый MCP-сервер хаба (`send_file`, `ask_user`);
вопросы ограничены пятью за вызов и четырьмя вариантами каждый.

Режим одобрений задаётся в «Настройки → Агенты → Hermes» или командой `/mode` и
применяется при каждом запуске сессии, включая восстановленную:

- `default` (по умолчанию) — спрашивает перед каждой правкой файла;
- `accept_edits` — правки в рабочем каталоге и во временных директориях без вопроса;
- `dont_ask` — правки файлов без вопроса на всю сессию;
- `yolo` — `dont_ask` плюс запуск с глобальной опцией `--yolo`, которая снимает вопросы
  об опасных командах.

Ни один режим не снимает вопросов о чувствительных путях (`.git`, `.ssh`, файлы с секретами)
и о правилах запрета самого Hermes — эти кнопки разрешений остаются и при `yolo`. Режим,
которого нет у установленного Hermes (например, `accept_edits` в сборке до 0.22.3),
прекращает разговор с перечислением доступных режимов вместо неясной ошибки ACP.

Новые сообщения во время хода ждут в очереди хаба до его окончания: это **не досылка
между инструментами**, как у Qwen. `/stop` отменяет ход и завершает процесс. Сохранённая
сессия восстанавливается через `session/load`; ошибка восстановления не создаёт новую
сессию молча — используйте `/reset`. Токены берутся только из результата prompt, если Hermes
их сообщил; заполненность контекста не выдаётся за расход токенов.
Фоновые задачи после завершения хода интеграция Hermes не поддерживает.

## OpenCode

Установите CLI, например командой `npm i -g opencode-ai`.
`/new opencode <путь>` создаёт сессию OpenCode в текущей теме, `/backend opencode` переключает
тему со сбросом контекста. Хаб запускает `opencode acp` через stdio — тот же транспорт ACP,
что и у Hermes; отдельный сервер OpenCode не запускается.

В «Настройки → Агенты → OpenCode» задаются путь к CLI и необязательная модель в формате
`провайдер/модель` (например, `anthropic/claude-sonnet-4`); пустая модель оставляет выбор
конфигурации OpenCode. Модель применяется к сессии через `session/set_model`. Вход,
провайдеры и разрешения инструментов остаются в управлении OpenCode (`opencode auth login`,
`opencode.json`); хаб не записывает его ключи и конфигурацию. Агент режима (build/plan и
пользовательские) выбирает сам OpenCode — хаб его не переключает.

Ответы и вызовы инструментов переводятся в события хаба; запросы разрешений приходят
кнопками Telegram, и хаб выбирает только предложенное разовое разрешение. Файлы и вопросы
передаются через защищённый MCP-сервер хаба (`send_file`, `ask_user`). Новые сообщения во
время хода ждут в очереди до его окончания; `/stop` отменяет ход. Сохранённая сессия
восстанавливается через `session/load`; ошибка восстановления не создаёт новую сессию
молча — используйте `/reset`. Токены берутся только из результата prompt
(`usage.totalTokens`); оценочная заполненность контекста (`usage_update`) не подменяет их.

История сессии остаётся в хранилище OpenCode. Команды снимков `/save` и
`/restore` для него недоступны. Передать сводку беседы в другую тему можно через
`/handoff`, а у сохранённой задачи — [сменить исполнителя](tasks.md#передать-другому-агенту-и-проверить-контекст).
Проверка в «Настройки → Диагностика → Состояние» проверяет CLI и версию ACP.
Для проверки входа к провайдеру выполните короткое поручение.

## Pi

Установите CLI, например `npm i -g @earendil-works/pi-coding-agent`, и выполните вход в
подписку: `pi auth login openai-codex` (устройство и браузер) или ключ Token Plan в
`~/.pi/agent/auth.json`. `/new pi <путь>` создаёт сессию Pi, `/backend pi` переключает тему
со сбросом контекста. Хаб запускает `pi --mode rpc` — у Pi собственный JSONL-RPC поверх stdio,
не ACP: команды и события идут одной JSON-строкой в каждую сторону.

В «Настройки → Агенты → Pi» задаются путь к CLI и необязательная модель в формате
`провайдер/модель` (например, `qwen-token-plan/qwen3.8-max`); пустая модель оставляет выбор Pi.
Подписки, модели и ключи остаются в `~/.pi/agent/` — хаб их не читает, не копирует и не пишет.

Режим Pi — уровень размышления: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`. Набор
объявляет сама модель, поэтому `/mode high` для модели без `high` отклоняется с причиной, а не
молча подменяется. Отдельного режима одобрений у Pi нет: хаб ставит свой гейт
(`[pi] approval = default | yolo`), который спрашивает разрешение на `bash`, `edit` и `write`
до исполнения инструмента.

Ответы и вызовы инструментов переводятся в события хаба; вопросы, файлы и подтверждения
приходят через расширение Pi и защищённый MCP-сервер хаба на `127.0.0.1`. Новые сообщения во
время хода уходят агенту как `steer`, `/stop` прерывает ход через `abort`. Идентификатор сессии
выдаёт Pi: хаб узнаёт его из `get_state` и возвращает при продолжении через `--session`.
Токен usage берётся из `get_session_stats`.

Снимки: `/save` пишет HTML-экспорт сессии (`export_html`), `/restore` принимает этот файл как
`--session <путь>`. Импорт прежней истории в другую машину не проверялся. Квоты подписок Pi
не сообщает. Проверка в «Настройки → Диагностика → Состояние» проверяет CLI и версию; вход
хаб не пробует, чтобы не писать лишние сессионные файлы.

## Лимиты подписок

`/limits` в теме или в общем чате показывает, сколько израсходовано лимитов подписок:

```
📊 Лимиты подписок · 16.10 14:05
Claude (Max)
  5 часов     ▓▓▓▓▓▓░░░░ 62% · сброс в 17:30
  7 дней      ▓▓░░░░░░░░ 18% · сброс пн 09:00
  7 дней Opus ▓░░░░░░░░░  9%
Codex (ChatGPT Plus)
  основное  ▓▓▓▓░░░░░░ 41% · сброс в 16:10
  недельное ▓░░░░░░░░░ 12% · сброс чт 11:00
Qwen, Hermes, OpenCode, Pi — квоты подписки агент не сообщает
```

- Данные спрашиваются у самих CLI при каждой команде и нажатии «🔄 Обновить»; фонового опроса нет, одновременно идёт один опрос.
- Claude — короткий запуск `claude` без поручения, с пустым списком источников настроек и запросом `get_usage` при входе через подписку claude.ai. Если экспериментальный API не ответил, карточка покажет последние известные значения или причину ошибки.
- Codex — короткий `codex app-server`, только при входе через ChatGPT.
- Для Qwen, Hermes, OpenCode и Pi хаб показывает, что данные о квотах отсутствуют.
- Каждый агент отвечает не дольше 20 с; без ответа показываются последние значения из живых сессий с пометкой «(на ЧЧ:ММ)».
- В карточке — только агенты, CLI которых найден; агент по умолчанию — первым. Время — в часовом поясе компьютера.
