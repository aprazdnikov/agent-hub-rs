# Консольный режим

[Документация](../README.md) · [О проекте](../../README.md)

Консольный режим запускает тот же хаб без окна, без значка в трее и без бота
Telegram: разговор с агентом идёт строками в терминале. Он нужен машине без
дисплея — серверу, контейнеру или Raspberry Pi, — и работе по SSH.

## Запуск

```bash
agent-hub --cli
```

Хаб берёт те же настройки, что и окно: `settings.toml`, ключи из системного
хранилища и рабочий каталог по умолчанию. Ключ `--tui` делает то же самое.
Запускается один экземпляр: если уже открыто окно или другой терминал, хаб
сообщит об этом и выйдет.

| Ключ | Значение |
|---|---|
| `--backend <имя>` | исполнитель вместо агента по умолчанию (`claude`, `codex`, `qwen`, `hermes`, `opencode`, `pi`) |
| `--dir <путь>` | рабочий каталог разговора (по умолчанию — текущий) |
| `--help` | список команд разговора |

Настройки должны быть заполнены заранее — в консоли хаб не умеет просить токен
бота и путь к ключам, это делает окно. Если файл настроек ещё не создавался,
один раз запустите хаб с окном (или заполните `settings.toml` вручную), далее работайте в терминале.

## Разговор

Обычная строка — сообщение агенту. Во время хода набранный текст уходит агенту
как уточнение, а `/stop` прерывает ход.

| Команда | Что делает |
|---|---|
| `/mode <значение>` | режим исполнителя: для Claude — права, для Codex — `песочница/одобрения`, для Qwen и Hermes — одобрения, для Pi — уровень размышления |
| `/model <провайдер/модель>` | модель следующего хода |
| `/status` | модель, режим и рабочий каталог |
| `/stop` | прервать текущий ход (печатает `· ход прерван`) |
| `/help` | список команд |
| `/quit` | выйти (или `Ctrl-D`) |

Вызовы инструментов печатаются строкой `· инструмент · что он делает`, ответы —
прямо в поток терминала. Когда агент просит разрешение, хаб спрашивает
в той же сессии: `y` разрешает, всё остальное — отказ. Пока вопрос открыт,
строки принадлежат ему: ответ не превратится в уточнение хода. Файлы, которые
агент готовит, печатаются путём на диске: в консоли нет чата, куда их приложить.

Ход, который исполнитель не смог сделать, виден строкой `⚠`: недоступная модель,
истёкшая подписка, лимит провайдера. Молчания с нулём токенов не бывает —
Pi пишет причину отказа внутрь сообщения ассистента, и хаб её показывает.

Разговор продолжается в той же сессии исполнителя, что и в Telegram или окне:
идентификатор сессии хаб помнит между ходами одного запуска. Захотите новый
контекст — начните хаб заново или смените каталог (`--dir`).

## Raspberry Pi

На Raspberry Pi 4 и 5 (64-битная ОС) хаб собирается из исходников обычной
командой `cargo build --release -p hub-app` — GUI-слой в консоли не участвует,
поэтому X11, Wayland и браузер не нужны. Дальше достаточно установить CLI
агента и войти в него от своего имени:

```bash
export PATH="$HOME/.local/bin:$PATH"
agent-hub --cli --backend pi
```

Для `pi` подписки живут в `~/.pi/agent/`, для остальных агентов — в их
собственных каталогах; хаб их не читает. Если агент должен работать без
оператора в терминале, удобнее держать запущенным окно на другой машине и
говорить с теми же проектами через Telegram.

## Что режим не делает

- Не поднимает окно, трей и бота Telegram: «Входящие» и сохранённые задачи
  остаются в окне на другой машине.
- Не просит недостающие настройки и ключи — только сообщает, какого поля нет.
- Не принимает вложения: голосовые и картинки в консоль не входят, путь файла
  от агента печатается текстом.
