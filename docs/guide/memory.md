# Общая память проекта

[Документация](../README.md) · [Агенты](agents.md) · [Сессии и передача](sessions.md)

Claude Code, Codex, Qwen Code, Hermes и OpenCode могут читать и записывать одну
память проекта независимо от своих сессий и выбранных моделей. Достаточно настроить
тот агент, которым вы пользуетесь; сервис памяти не требует отдельной подписки и
не вызывает модели. Агент сам выбирает сведения и формулирует записи.

## Работа через agent-hub

В обычных сессиях всех пяти бэкендов хаб подключает локальный stdio MCP
`agent-hub-memory`. Рабочий каталог темы определяет область памяти. Новая сессия
другого агента в том же каталоге получает те же записи. Для уже работающего процесса
после обновления нужно завершить текущую работу и запустить сессию заново.

Когда память включена, перед запуском агент получает выдержки из четырёх последних активных
записей и поручение искать контекст задачи и сохранять значимые решения и результаты с источниками.
Агент выбирает подробности. Общий исполнитель после окончания попытки сам записывает её
состояние, количество пройденных проверок, наличие ревью и ссылку на историю попытки.
Ремонт и ревью входят в одну такую запись. Ошибка записи показывается в статусе запуска.

Для задачи откройте в чате **Параметры → Агент и память → Память задачи**.
Для обычной сессии Telegram откройте **Темы Telegram → Параметры → Память темы**.
В Telegram используйте `/memory topic on|off|inherit` и
`/task memory ID РЕВИЗИЯ on|off|inherit`. Для новой попытки приоритет имеет
настройка задачи, затем темы запуска, затем общая настройка. При локальном запуске
режим «Наследовать» использует общую настройку. Работающий процесс использует выбор на
момент запуска. Автоматически созданный worktree задачи обращается к памяти исходного проекта.

Доступны категории `context`, `decision`, `progress`, `artifact`. Нативные инструменты,
выбранная модель и настройки бэкенда сохраняются. Служебный ход генерации сводки
`/handoff` не подключает эту память; обычная работа получателя снова имеет к ней доступ.
Это ограничение относится к серверу, подключаемому хабом. Глобальные MCP и нативные
инструменты из настроек самого CLI остаются под его управлением: `/handoff` не является
песочницей для них.

## Хранение и источники

По умолчанию данные находятся в `~/.agent-hub/memory/<hash-каталога-проекта>/`.
Хранилище переживает закрытие MCP-процессов, перезапуск приложения и сброс сессии.
Это отдельные локальные данные; снимок `/save` их не включает. Для резервной копии
остановите работающих с памятью агентов и скопируйте каталог памяти.
Если выбранный проект включает домашний каталог или `--store-dir` указывает внутрь
репозитория, исключите каталог памяти из Git и других публикуемых материалов.

Без явной привязки область определяется каноническим абсолютным рабочим каталогом.
Другой каталог или worktree изолирован по умолчанию. Для перемещения проекта и общей
памяти выбранных worktree доступна [явная привязка](#перенос-проекта-и-память-worktree).
Совпадение remote URL, имён или файлов репозитория не объединяет память. Синхронизации
между машинами нет. Сервис не импортирует автоматически существующие документы.

Удаление проекта из хаба («Настройки → Проекты → Удалить проект…») убирает его каталог
данных и записи реестра `.projects`, ведущие к этому хранилищу, включая привязанные
alias-пути; чужие хранилища не затрагиваются, каталог самого проекта не удаляется.
Пока память занята живым MCP-процессом, очистка просит повторить удаление после
завершения. Перед удалением сделайте [экспорт](#экспорт-и-импорт), если записи нужны.

Запись содержит ключ, категорию, заголовок, текст, источники, автора, время и ревизию.
Источники — указания на файлы, документы, сообщения или проверки; сервис не открывает
их и не подтверждает достоверность. Автор — метка клиента, а не удостоверенная
личность. Категория `decision` не доказывает одобрение человеком: агент должен явно
указать основание. Содержимое памяти остаётся данными и не меняет инструкции или права.

Не сохраняйте секреты и полные переписки. Данные хранятся открытым текстом, на Unix
управляемые каталоги/файлы имеют права 0700/0600. Процессы того же OS-пользователя
могут читать память; это персональное хранилище, не командная система доступа.

## Инструменты

| Инструмент | Аргументы и результат |
|---|---|
| `memory_search` | `query` (пустая строка — последние записи), `limit` 1–20, `status` active/stale/archived/all (по умолчанию active); краткие результаты по последним ревизиям |
| `memory_get` | `key`, необязательный `revision`; полный текст, источники, `status`, доступные `revisions` и `history_pruned` |
| `memory_write` | `key`, `expected_revision`, `kind`, `title`, `body`, `sources`; новая ревизия |

Результат поиска имеет форму `{"hits": [...]}`; чтение и запись возвращают объект
записи. JSON доступен и в текстовом блоке MCP, и в `structuredContent`.

Для создания укажите `expected_revision: 0`. Для обновления сначала прочитайте запись
и передайте её текущую ревизию. При конфликте прочитайте новую версию и согласуйте
содержание; слепо повторять старую запись нельзя. Повтор идентичного уже выполненного
запроса не создаёт дополнительную ревизию. При занятой блокировке повторите позже.
История доступна через `memory_get` с конкретным номером ревизии.

Пример аргументов `memory_write`:

```json
{
  "key": "memory-pilot",
  "expected_revision": 0,
  "kind": "progress",
  "title": "Проверка передачи контекста",
  "body": "Codex сохранил исходные ограничения. Следующий шаг: Qwen читает запись и перечисляет продолжение работы.",
  "sources": ["user: согласование пилота в текущем диалоге"]
}
```

Лимиты на проект: 500 ключей, 32 ревизии на ключ, файл до 8 МиБ. Текст записи —
до 16384 байт UTF-8, заголовок — 256 байт, 1–8 источников до 2048 байт каждый.
Ключ — 1–64 ASCII-буквы, цифры, `_` или `-`. Поиск — до 512 байт, excerpt — до
400 символов. По умолчанию превышение лимита возвращает ошибку без удаления.
Ручное управление и явно включаемая автоматическая очистка описаны ниже.

## Подключение вне Telegram

Используйте **новую собранную версию** `agent-hub` и абсолютный путь проекта:

```bash
/absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor codex
```

Это stdio MCP: программа ждёт JSON-RPC в stdin и отвечает в stdout. Окно, Telegram
и авторизация моделей для такого запуска не нужны. `--store-dir /absolute/path/store`
меняет каталог хранения; для обмена данными у клиентов должны совпадать оба каталога.

Команды регистрации ниже изменяют настройки соответствующего CLI; приложение
само их не выполняет. Имя внешнего сервера можно выбрать отдельно для каждого проекта.
Проверьте область конфигурации своего клиента, чтобы не обращаться из другого проекта
к явно закреплённой здесь памяти.

```bash
claude mcp add --transport stdio --scope project project-memory -- /absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor claude

codex mcp add project-memory -- /absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor codex

qwen mcp add --scope project --transport stdio project-memory /absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor qwen

hermes mcp add project-memory --command /absolute/path/agent-hub --args --memory-mcp --project-dir /absolute/path/project --actor hermes
```

Синтаксис сверён с `--help` установленных CLI 2026-11-15. Hermes может выполнить
проверку сервера при добавлении. Встроенное подключение хаба использует зарезервированное
имя `agent-hub-memory`; для ручной настройки выше выбрано другое имя.
Команды с `--scope project` выполняйте из каталога нужного проекта.

Для OpenCode добавьте сервер в существующий `opencode.json` проекта, сохранив другие
настройки и серверы. Формат `mcp.servers` проверен загрузчиком OpenCode 1.19.5
без модельного запроса и соответствует [документации OpenCode](https://opencode.ai/docs/mcp-servers/#config):

```json
{
  "mcp": {
    "servers": {
      "project-memory": {
        "type": "local",
        "command": [
          "/absolute/path/agent-hub",
          "--memory-mcp",
          "--project-dir", "/absolute/path/project",
          "--actor", "opencode"
        ]
      }
    }
  }
}
```

## Первый пилот

1. В теме Codex попросите сохранить цель, подтверждённые ограничения и следующий шаг
   реальной работы с указанием источников.
2. Создайте свежую тему Qwen или Hermes с тем же рабочим каталогом.
3. Попросите восстановить контекст из памяти, назвать источники и предложить продолжение.
4. Проверьте, что агент различает подтверждённые решения и предположения.

Такую же проверку можно провести в двух локальных задачах одного каталога.
Обращение к модели расходует лимиты выбранного агента. Сохранённую запись и её
источники можно проверить в меню проекта без вызова модели.

## Просмотр и управление без модели (MEM-02)

В дереве слева откройте меню **«…»** у проекта и нажмите **«Память проекта»**. Список записей выбранного каталога загрузится автоматически. Просмотр работает при
остановленном боте и отключённом подключении памяти к агентам. Пустой просмотр
не создаёт хранилище. Путь к хранилищу, число ключей и объём доступны по наведению на счётчик записей.
Поиск учитывает ключ, заголовок, текст и источники. Откройте запись из списка
либо откройте «Инструменты памяти» и введите ключ. Номер `0` означает последнюю
ревизию. Для прежней записи укажите её фактический номер из истории.

В Telegram используйте команду в теме с выбранным каталогом:

```text
/memory
/memory search mem01-pilot
/memory get mem01-pilot-quick-check
/memory get mem01-pilot-quick-check 1
```

Кнопки открывают записи, предыдущую/последнюю ревизию и страницы списка.
Длинный текст доставляется несколькими сообщениями без обрезания.
После смены каталога откройте меню заново: старые кнопки не действуют в другой
области. Автор и источники остаются метаданными, а не удостоверенным одобрением.

Переключатель **«Подключать память к агентам по умолчанию»** доступен в **«Настройки → Агенты → Общие»**. То же значение можно менять через `/memory`. В Telegram изменение требует
подтверждения кнопкой. Это значение по умолчанию для тем и задач;
в `settings.toml` — `[memory] enabled = true`, по умолчанию включена.

Изменение действует при следующем запуске процесса агента, включая продолжение
сохранённой сессии. Уже работающий процесс сохраняет прежнее подключение:
дождитесь его завершения или штатно остановите задачу, затем продолжите.
Сохранённая настройка и состояние текущего процесса показываются отдельно.
Ручные MCP самостоятельных CLI не затрагиваются. Отключение не удаляет данные,
а повторное включение возвращает доступ к тем же записям.


## Жизненный цикл памяти (MEM-03)

В разделе **«Инструменты памяти → Показать состояние и записи»** доступны фильтр,
история с фактическими номерами, архивирование, отметка устаревания и удаление.
Архив и устаревшие записи скрыты из обычного поиска. Прямое чтение по ключу
доступно; архивную запись агент не может менять до возврата в активные.
Архивирование не освобождает место и не изменяет номер ревизии.

**Ручная очистка — рекомендуемый режим по умолчанию.** Выберите старые ревизии
в карточке или удаление целой записи, проверьте предварительный просмотр и
подтвердите. Экспорт доступен отдельной кнопкой до подтверждения. Без экспорта
приложение не сможет восстановить удалённое. Последнюю ревизию отдельно
удалять нельзя: для этого требуется удаление целой записи.

**Автоматическая очистка** включается отдельно для выбранного проекта кнопкой
«Включить автоочистку» после предупреждения. Само включение ничего не удаляет.
При следующей записи сохраняются последние 32 ревизии; при превышении 8 МиБ
удаляется старейшая история всех записей, включая архивные. Последняя версия
каждого ключа сохраняется. Если этого недостаточно, запись целиком отклоняется.
Номера версий не сбрасываются: после r32 следующая — r33. Режим применяется
и к уже открытым MCP-процессам при следующей записи. Выключение автоочистки не
возвращает удалённые версии. Автоматические копии каждой очистки не создаются.

Удалённый ключ оставляет компактную отметку: запоздалый агент не может его
воскресить. Предел — 4096 отметок, входящих в общий размер 8 МиБ. Они не входят
в 500 живых ключей. Восстановление содержимого — импорт под новым ключом.

### Экспорт и импорт

Экспорт сохраняет один JSON с доступной историей, состояниями и источниками;
уже очищенную историю он не восстанавливает. Выберите **новый файл**: существующий
файл не перезаписывается. Импорт ограничен 16 МиБ, итоговое хранилище — 8 МиБ.
Архивы и источники из JSON не открываются и не исполняются.

Перед импортом показаны исходный и целевой проекты, новые/совпадающие записи
и конфликты. Перед выбором доступны обе записи, источники, состояния и история
каждой стороны (в Telegram — кнопка сравнения или `/memory compare КЛЮЧ`).
Конфликты по умолчанию пропускаются; можно выбрать новый ключ для
входящей копии. Существующая расходящаяся история не заменяется. Повтор импорта
не создаёт дубликат, даже если импортированную копию уже обновляли. Совместимая
история требует хотя бы одной общей совпадающей ревизии; все пересечения должны
совпадать. Импорт применяется целиком, не запускает очистку и не включает
политику автоочистки из файла.

В Telegram:

```text
/memory status
/memory filter archived
/memory policy auto
/memory policy manual
/memory archive КЛЮЧ
/memory stale КЛЮЧ
/memory activate КЛЮЧ
/memory prune КЛЮЧ 1 2
/memory delete КЛЮЧ
/memory export
/memory import
/memory compare КЛЮЧ
/memory copy ИСХОДНЫЙ_КЛЮЧ НОВЫЙ_КЛЮЧ
/memory cancel
```

Изменения требуют отдельного подтверждения кнопкой. Экспорт отправляется только
после предупреждения, что память увидят участники группы. После `/memory import`
тот же пользователь присылает один JSON-файл в ту же тему в течение 10 минут.
Импортируемый файл не передаётся модели. Обычные вложения остаются обычными
вложениями; отменить ожидание можно `/memory cancel`. Старые кнопки и смена
проекта требуют нового предварительного просмотра. Одновременно удерживается
один предпросмотр переноса; новый импорт/пересоздание заменяет предыдущий.

### Новое поколение и переход с v1

Если достигнут предел отметок удаления, используйте **«Новое поколение…»**:
сначала сохраняется и проверяется полный экспорт, затем выбираются сохраняемые
ключи и подтверждается сброс. Несохранённые записи и отметки удаления удаляются
атомарно. Старые MCP-процессы больше не могут писать: запустите новые процессы
и новые агентские сессии. В Telegram начало — `/memory reset`, после отправки
экспорта доступен выбор кнопками или `/memory reset-keep КЛЮЧИ`; без ключей
сохраняемых записей не будет. Последнее подтверждение обязательно.

Чтение старого v1 не меняет файл. Перед первым изменением создаётся проверенная
копия `memory.v1.backup.json` рядом с `memory.json`, затем атомарно записывается v2.
Копия не перезаписывается; при несовпадении миграция останавливается. Рекомендуется
завершить работу старых агентов перед обновлением: старый бинарник отвергает v2.

Для отката остановите все процессы, сохраните отдельный экспорт/копию текущего
v2 и вручную восстановите `memory.json` из `memory.v1.backup.json`. Изменения,
сделанные после миграции, в v1-копии отсутствуют. Файл v2 нельзя просто пометить
номером версии 1. Отмена предварительного просмотра не выполняет очистку.


## Перенос проекта и память worktree

В меню целевого проекта откройте **«Память проекта → Инструменты памяти»**, затем раскройте
**«Перенос проекта и общая память worktree»**. Введите абсолютный путь источника:

- **«Перенести привязку»** — подключить прежнюю память к новому каталогу и отключить
  старый путь. Работает и после физического перемещения: укажите прежний канонический
  абсолютный путь, показанный ранее в состоянии памяти. Символьный псевдоним пути
  после удаления исходного каталога не позволяет восстановить его идентичность.
- **«Подключить общую память»** — оставить оба каталога подключёнными. Общими станут
  **все** записи, история, статусы, отметки удаления и политика очистки. Последующие
  изменения и удаления видны всем. Чаты, рабочие файлы, разрешения и сессии не общие.

Нажмите предварительный просмотр, проверьте источник, назначение и режим, затем
подтвердите. Если у назначения уже есть snapshot (даже без живых записей) или
привязка, операция отклоняется. Для переноса отдельных знаний и разрешения конфликта
используйте экспорт/импорт. Автоматического слияния, отвязывания и повторного
использования отключённого пути нет. При необходимости перенести общую память далее
выберите один из её действующих путей источником; остальные привязки сохранятся.

Самостоятельный CLI использует тот же механизм, без запуска GUI:

```sh
./target/debug/agent-hub --memory-project move \
  --from /absolute/old/project --to /absolute/new/project
./target/debug/agent-hub --memory-project share \
  --from /absolute/main-checkout --to /absolute/selected-worktree
```

Первый вызов только показывает preview. Повторите **ту же команду**, добавив
`--confirm ТОКЕН_ИЗ_ВЫВОДА`. Токен зависит от обоих путей, режима, реестра и состояния
исходной памяти: изменение записи требует нового preview. `--store-dir /absolute/path`
выбирает отдельное хранилище и должно совпадать у управления и `--memory-mcp`.
Пути с пробелами заключайте в кавычки. MCP-инструментов изменения привязки нет.

В GUI и `/memory status` перечислены связанные каталоги (до 10 в отображении).
Все пять бэкендов и самостоятельный `--memory-mcp --project-dir ...` используют
эту привязку; дополнительных настроек каждого harness не требуется.

### Данные, обновление и восстановление привязок

Стабильный ID остаётся хешем **исходного** канонического пути. Snapshot и резервная
копия v1 физически остаются на месте: перенос не переписывает записи и источники.
В экспорте `project` сохраняет исходную идентичность; это не обязательно текущий cwd.
Реестр находится в `~/.agent-hub/memory/.projects/memory.json` (или внутри своего
`--store-dir`), вне репозитория. Предел — 4096 путей и 1 МиБ. Он использует те же
файловые операции и атомарную замену, что хранилище памяти. На Unix синхронизируются
также каталоги; Windows использует существующий переносимый файловый слой без
эквивалентной гарантии fsync каталогов и защиты Unix от гонок с подменой ссылок.

Перед первым использованием привязок завершите процессы **старой версии приложения
и MCP-сервера**. Старые бинарники не знают реестр; использовать их после привязки
нельзя. В текущей версии смена привязки блокирует дальнейшие обращения через
устаревшие Store/Reader. Начните новые агентские сессии после переноса/подключения.
Уже завершённые записи не откатываются. Работающие старые версии автоматически
не останавливаются.

Сбой до публикации реестра оставляет прежнюю привязку; после публикации действует
новая. Повтор подтверждения не создаёт копий, но может вернуть «назначение занято»
или «привязка изменена»: сначала проверьте состояние целевого проекта. При ошибке после замены реестра приложение отдельно сообщает, что результат
публикации/сохранность не подтверждены, и указывает целевой каталог: привязка уже
могла примениться. Проверьте его состояние перед повтором. Ошибка записи
не требует переноса snapshot вручную. Частичный `.memory.tmp` не считается реестром.
При повреждённом реестре обращения завершаются ошибкой, без скрытого переключения.

Для резервной копии остановите клиентов и копируйте **весь каталог памяти вместе
с `.projects`**. Для восстановления реестра остановите всех клиентов и восстановите
его из этой копии; удаление реестра не является отвязыванием и лишает систему сведений
о связях. Альтернатива восстановления содержимого — проверенный экспорт/импорт в
новый изолированный проект. Копия репозитория сама по себе память не переносит.

## Пакет контекста следующему агенту

Пакет собирает **выбранные записи целиком**, с точными ревизиями и источниками,
вместе с вашим кратким поручением. Он не вызывает модель, не переносит разрешения
и не меняет служебный `/handoff`. Передайте готовый текст выбранному агенту обычным
сообщением — в новой сессии хаба или самостоятельного CLI.

В GUI:

1. Откройте «Память проекта» из меню нужного проекта и найдите запись.
2. Откройте нужную ревизию и нажмите **«Добавить ревизию в пакет контекста»**.
   Повторите для остальных записей (до 20 разных ключей).
3. Раскройте **«Инструменты памяти → Пакет контекста следующему агенту»**. Заполните цель, ограничения,
   состояние, следующий шаг и источники этих формулировок. Если сведений нет,
   явно напишите «неизвестно» или «нет». Источники — по одному на строке, до 8.
4. Нажмите **«Собрать пакет для проверки»**, просмотрите предупреждения и полный текст.
5. Нажмите **«Проверить свежесть и скопировать пакет»**, затем вставьте его выбранному
   агенту. При изменении формы, состава, бюджета или памяти потребуется пересборка.

Черновик сохраняется при смене поискового запроса, но очищается при смене проекта.
Все четыре поля поручения обязательны, до 4096 байт UTF-8 каждое; источник до 2048 байт.
Выбранная старая ревизия не заменяется новой молча. Пакет явно предупреждает об
исторических, устаревших и архивных записях. Если выбранной ревизии больше нет,
сборка завершается ошибкой без частичного результата.

В Telegram `/memory context` показывает форму. Пример (укажите реальные ключ и ревизию):

```text
/memory context
Записи: pilot@1 decision@3
Цель: Продолжить проверку памяти
Ограничения: Не менять код и не публиковать изменения
Состояние: Памятка создана, требуется проверка
Следующий шаг: Сверить памятку с руководством
Источник: user: текущее поручение
Источник: docs/guide/memory.md
Бюджет: 16384
```

Каждое поле — отдельной строкой; `Источник:` можно повторять. После предварительного
просмотра нажмите **«Проверить и получить текст пакета»**. В группе содержимое будет
доступно её участникам. Большой пакет приходит нумерованными частями; используйте
только полный набор. При ошибке отправка останавливается, сообщение об успешной
выдаче не появляется. Не собирайте один пакет из частей разных повторных выдач.
Отмена — `/memory cancel`; смена проекта отменяет ещё не завершённую отправку.
Уже отправленные части не отзываются. Таймаут — 30 секунд на всю выдачу.

Бюджет считается **в байтах UTF-8 текста пакета**, включая заголовок, JSON, источники
и предупреждения. По умолчанию 16384, допускается 1024–65536. Это не число модельных
токенов. Транспортные подписи частей Telegram в бюджет не входят. При превышении
приложение показывает нужный размер: увеличьте бюджет либо явно уберите записи.
Ограничения и текст записей автоматически не сокращаются.

Источники **не проверяются** и не открываются: наличие ссылки не доказывает наличие
файла, актуальность сведений или согласие человека. Получателю нужно проверить
существенные источники и текущие ревизии; отсутствие источника не означает отказ
пользователя. Проверка свежести действует на момент выдачи — скопированный текст
остаётся снимком, а память после этого может измениться. Сам пакет не сохраняется
в MCP-память или файлы проекта автоматически.

## Процедура продолжения работы

В «Инструментах памяти» раскройте «Процедура: продолжить работу по памяти», прочитайте текст и нажмите
«Скопировать процедуру». В Telegram используйте `/memory procedure` в теме:
бот выдаст один шаблон `continue-work@1`, даже если проект темы ещё не выбран.

Передайте шаблон агенту вместе с конкретными проектом, ключом памяти и поручением.
Он предлагает сверять текущую ревизию и фактический прогресс, чтобы не переносить
устаревший список оставшихся шагов. Просмотр и копирование ничего не запускают
и не меняют; права исходной сессии не переносятся, запись памяти разрешается
поручением пользователя. Нативные skills CLI продолжают действовать.
