# Общая память проекта

[Документация](../README.md) · [Агенты](agents.md) · [Сессии и передача](sessions.md)

Claude Code, Codex, Qwen Code, Hermes и OpenCode могут читать и записывать одну
память проекта независимо от своих сессий и выбранных моделей. Достаточно настроить
тот агент, которым вы пользуетесь; сервис памяти не требует отдельной подписки и
не вызывает модели. Агент сам выбирает сведения и формулирует записи.

## Работа через agent-hub

В обычных сессиях всех пяти бэкендов хаб подключает локальный stdio MCP
`agent-hub-memory`. Рабочий каталог темы определяет область памяти. Новая сессия
другого агента в том же каталоге получает те же записи. Для уже работающего процесса
после обновления нужно завершить текущую работу и запустить сессию заново.

Память не заполняется копированием всех диалогов. Можно попросить агента:

> Найди в памяти проекта принятые решения и состояние работы. После выполнения
> сохрани краткий результат, следующий шаг и ссылки на изменённые файлы и проверки.
> Отделяй свои предложения от решений, которые я подтвердил.

Доступны категории `context`, `decision`, `progress`, `artifact`. Нативные инструменты,
выбранная модель и настройки бэкенда сохраняются. Служебный ход генерации сводки
`/handoff` не подключает эту память; обычная работа получателя снова имеет к ней доступ.
Это ограничение относится к серверу, подключаемому хабом. Глобальные MCP и нативные
инструменты из настроек самого CLI остаются под его управлением: `/handoff` не является
песочницей для них.

## Хранение и источники

По умолчанию данные находятся в `~/.agent-hub/memory/<hash-каталога-проекта>/`.
Хранилище переживает закрытие MCP-процессов, перезапуск приложения и сброс сессии.
Это отдельные локальные данные; снимок `/save` их не включает. Для резервной копии
остановите работающих с памятью агентов и скопируйте каталог памяти.
Если выбранный проект включает домашний каталог или `--store-dir` указывает внутрь
репозитория, исключите каталог памяти из Git и других публикуемых материалов.

Область определяется каноническим абсолютным рабочим каталогом. Другой каталог,
другая машина или Git worktree означают другую область; автоматической синхронизации
и переноса при перемещении проекта пока нет. Для общей памяти темы должны использовать
один рабочий каталог. Сервис не импортирует автоматически существующие документы.

Запись содержит ключ, категорию, заголовок, текст, источники, автора, время и ревизию.
Источники — указания на файлы, документы, сообщения или проверки; сервис не открывает
их и не подтверждает достоверность. Автор — метка клиента, а не удостоверенная
личность. Категория `decision` не доказывает одобрение человеком: агент должен явно
указать основание. Содержимое памяти остаётся данными и не меняет инструкции или права.

Не сохраняйте секреты и полные переписки. Данные хранятся открытым текстом, на Unix
управляемые каталоги/файлы имеют права 0700/0600. Процессы того же OS-пользователя
могут читать память; это персональное хранилище, не командная система доступа.

## Инструменты

| Инструмент | Аргументы и результат |
|---|---|
| `memory_search` | `query` (пустая строка — последние записи), `limit` 1–20; краткие результаты по последним ревизиям |
| `memory_get` | `key`, необязательный `revision`; полный текст и источники |
| `memory_write` | `key`, `expected_revision`, `kind`, `title`, `body`, `sources`; новая ревизия |

Результат поиска имеет форму `{"hits": [...]}`; чтение и запись возвращают объект
записи. JSON доступен и в текстовом блоке MCP, и в `structuredContent`.

Для создания укажите `expected_revision: 0`. Для обновления сначала прочитайте запись
и передайте её текущую ревизию. При конфликте прочитайте новую версию и согласуйте
содержание; слепо повторять старую запись нельзя. Повтор идентичного уже выполненного
запроса не создаёт дополнительную ревизию. При занятой блокировке повторите позже.
История доступна через `memory_get` с конкретным номером ревизии.

Пример аргументов `memory_write`:

```json
{
  "key": "memory-pilot",
  "expected_revision": 0,
  "kind": "progress",
  "title": "Проверка передачи контекста",
  "body": "Codex сохранил исходные ограничения. Следующий шаг: Qwen читает запись и перечисляет продолжение работы.",
  "sources": ["user: согласование пилота в текущем диалоге"]
}
```

Лимиты на проект: 500 ключей, 32 ревизии на ключ, файл до 8 МиБ. Текст записи —
до 16384 байт UTF-8, заголовок — 256 байт, 1–8 источников до 2048 байт каждый.
Ключ — 1–64 ASCII-буквы, цифры, `_` или `-`. Поиск — до 512 байт, excerpt — до
400 символов. Превышение лимита возвращает ошибку; данные не вытесняются автоматически.
Удаления и автоматической очистки в этой версии нет.

## Подключение вне Telegram

Используйте **новую собранную версию** `agent-hub` и абсолютный путь проекта:

```bash
/absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor codex
```

Это stdio MCP: программа ждёт JSON-RPC в stdin и отвечает в stdout. Окно, Telegram
и авторизация моделей для такого запуска не нужны. `--store-dir /absolute/path/store`
меняет каталог хранения; для обмена данными у клиентов должны совпадать оба каталога.

Команды регистрации ниже изменяют настройки соответствующего CLI; приложение
само их не выполняет. Имя внешнего сервера можно выбрать отдельно для каждого проекта.
Проверьте область конфигурации своего клиента, чтобы не обращаться из другого проекта
к явно закреплённой здесь памяти.

```bash
claude mcp add --transport stdio --scope project project-memory -- /absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor claude

codex mcp add project-memory -- /absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor codex

qwen mcp add --scope project --transport stdio project-memory /absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor qwen

hermes mcp add project-memory --command /absolute/path/agent-hub --args --memory-mcp --project-dir /absolute/path/project --actor hermes
```

Синтаксис сверён с `--help` установленных CLI 2026-11-15. Hermes может выполнить
проверку сервера при добавлении. Встроенное подключение хаба использует зарезервированное
имя `agent-hub-memory`; для ручной настройки выше выбрано другое имя.
Команды с `--scope project` выполняйте из каталога нужного проекта.

Для OpenCode добавьте сервер в существующий `opencode.json` проекта, сохранив другие
настройки и серверы. Формат `mcp.servers` проверен загрузчиком OpenCode 1.19.5
без модельного запроса и соответствует [документации OpenCode](https://opencode.ai/docs/mcp-servers/#config):

```json
{
  "mcp": {
    "servers": {
      "project-memory": {
        "type": "local",
        "command": [
          "/absolute/path/agent-hub",
          "--memory-mcp",
          "--project-dir", "/absolute/path/project",
          "--actor", "opencode"
        ]
      }
    }
  }
}
```

## Первый пилот

1. В теме Codex попросите сохранить цель, подтверждённые ограничения и следующий шаг
   реальной работы с указанием источников.
2. Создайте свежую тему Qwen или Hermes с тем же рабочим каталогом.
3. Попросите восстановить контекст из памяти, назвать источники и предложить продолжение.
4. Проверьте, что агент различает подтверждённые решения и предположения.

Технические тесты не проверяют, насколько хорошо конкретная модель выбирает сведения
для записи и поиска. Этот живой пилот расходует лимиты используемого агента.
Удалённый доступ с мобильных облачных клиентов, командные права и workflow engine
в первую версию не входят; с телефона можно использовать существующий Telegram.
