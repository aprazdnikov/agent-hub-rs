## Темы и сессии

- **Новая тема = новая сессия** в корне рабочих каталогов. Если приложение было выключено,
  когда создавали тему, сессия создастся при первом сообщении.
- **Обычное сообщение в теме** — очередная реплика в сессии. Контекст сохраняется.
- **Названия тем** сохраняются между перезапусками и обновляются при переименовании
  в Telegram. Переименование сохраняет текущую сессию, в том числе во время работы.
  Если бот ещё не получал название старой темы, в окне остаётся `#id` до события переименования.
- **Общая тема (General)** не используется — бот попросит создать отдельную тему.
- **Пока агент работает**, новые сообщения в теме уходят в ту же сессию: агент прочитает их
  после текущего шага. Разные темы работают параллельно.
- **Фоновые задачи** агента не теряются: после ответа приходит
  `✅ Готово · ходов: N · ⏳ в фоне задач: N, пришлю результат`, сессия остаётся открытой, и
  когда задача закончится, агент сам пришлёт результат. Если задачи не уложились в таймаут
  фоновых задач (по умолчанию 30 минут), бот сообщит, какие именно, и закроет сессию.
  `/stop` прерывает и фоновые задачи.

Во вкладке **«Темы»** доступны поиск по названию или каталогу без учёта регистра,
фильтры по бэкенду и состоянию, счётчик результатов и сброс фильтров.
Фильтры сохраняются при обновлении списка и переключении вкладок до закрытия приложения.
Для каждой темы:

- **Telegram** открывает тему через системный обработчик ссылок. **Ссылка** копирует
  адрес, если удобнее открыть его вручную; для доступа нужно состоять в группе.
- **Открыть** под каталогом запускает файловый менеджер. Отсутствующий каталог и ошибки
  запуска показаны над списком; полный путь и название доступны по наведению.
- **Stop / Reset** останавливают работу или сбрасывают контекст выбранной темы;
  сброс по-прежнему требует подтверждения.

Ссылки строятся по ID супергруппы и темы согласно
[формату Telegram](https://core.telegram.org/api/links#forum-topic-links).
Если ID не позволяет построить ссылку, кнопки Telegram и копирования недоступны.
Открытие выполняется в фоне. На Linux/macOS также отображается ошибка завершения
системной программы; Windows Explorer не даёт надёжного кода результата, поэтому
проверяются каталог и запуск процесса. Хаб не может подтвердить, что Telegram открыл тему.

## Команды

| Команда | Что делает |
|---|---|
| `/new [backend] [путь]` | Новая сессия в этой теме: сброс контекста, опционально бэкенд и директория (без бэкенда — агент по умолчанию из настроек) |
| `/backend [claude\|codex\|qwen\|hermes\|opencode]` | Сменить агента в этой теме (контекст сбрасывается); без имени — показать сессию |
| `/handoff [агент]` | Подготовить и проверить сводку, затем продолжить задачу другим агентом в новой теме |
| `/cwd <путь>` | Сменить рабочую директорию (контекст сбрасывается) |
| `/reset` | Начать разговор заново в той же директории |
| `/stop` | Прервать выполняющуюся задачу |
| `/status` | Состояние запуска, длительность, последняя активность, бэкенд, каталог, ID сессии и параметры |
| `/limits` | Лимиты подписок Claude и Codex: процент по окнам, время сброса, тариф; кнопка «🔄 Обновить». Работает в теме и в общем чате группы |
| `/actions` | Кнопки запуска и остановки пользовательских команд на ПК; работает в теме и в общем чате |
| `/projects` | Выбрать сохранённый проект для темы: каталог и бэкенд; сброс контекста после подтверждения |
| `/model [ID\|inherit]` | Показать модель и источник настройки; предложить модель для темы или вернуть наследование |
| `/mode [режим\|inherit]` | Выбрать режим работы текущего бэкенда; изменение после подтверждения |
| `/doctor` | Проверить каталог, наличие CLI и HTTP/TCP-ресурсы выбранного проекта |
| `/last` | Повторно получить последний сохранённый текстовый ответ этой темы |
| `/outbox` | Очередь доставки этой темы: состояние, повтор и удаление |
| `/save [имя]` | Снимок сессии темы в каталог снимков; без имени — `<название темы>-ГГГГММДД-ЧЧММ` |
| `/saves` | Последние 30 снимков: имя, бэкенд, каталог, дата, название темы |
| `/restore <имя> [каталог]` | Продолжить сессию снимка в этой теме; прежняя тема сессии сбрасывается |
| `/help` | Справка |

При каждом подключении меню Telegram **заменяется целиком**, без объединения со старым
списком BotFather. Парсер, меню и `/help` используют один реестр команд. Запись проверяется
чтением обратно; ошибка или общий тайм-аут 30 с попадают в лог предупреждением и не мешают
работе бота.

Синхронизируются меню группы, её администраторов и пользователей текущего allowlist:
общий язык, `ru`, `en`, с русскими описаниями. Глобальное меню и другие группы не меняются.
Bot API не позволяет перечислить произвольные старые языковые/пользовательские scopes;
другие локализации и пользователи вне allowlist не управляются.

Пути — абсолютные, с `~` или относительные от корня рабочих каталогов. Выйти за пределы корня
нельзя, в том числе через симлинки.

```
/new shop/backend
/new claude ~/Projects/agent-hub
/cwd shop/frontend
```

## Состояния задач

В `/status` и на вкладке **«Темы»** видны подготовка, выполнение, ожидание разрешения,
ожидание ответа, фоновые задачи, завершение и остановка процесса, а затем итог:
завершено, остановлено или ошибка. Если процесс закончился без подтверждённого
результата, это явно указано. Источник состояния — события бэкенда и открытые запросы
к пользователю; текст ответов для этого не анализируется.

Длительность запуска включает подготовку и ожидания, фиксируется после окончания.
Последняя активность показывает тип события и сколько секунд прошло с его получения.
Указывается число ожидающих разрешений и вопросов; разрешения имеют приоритет при
одновременных запросах. После ответа, тайм-аута или отмены ожидание снимается, даже
если Telegram ещё обновляет карточку. Число фоновых задач — последнее сообщённое
бэкендом; новые ходы внутри того же процесса снова показываются как выполнение.

Занятость темы отделена от подробного состояния: пока процесс не окончен, **Stop**
доступен и при ожидании пользователя, а **Reset** недоступен. В GUI фильтр этапа
сочетается с поиском, фильтром бэкенда и занятости; полный текст ячейки виден по наведению.
Hub проверяет изменения состояний каждые 250 мс при активных задачах, счётчики времени в GUI обновляются
раз в секунду; дополнительных сообщений о прогрессе в Telegram нет.

Хранится только последний запуск каждой темы в памяти текущего бота. Переименование
и смена модели с сохранением контекста оставляют его видимым; новый запуск заменяет,
сброс или смена контекста очищают. После перезапуска бота и восстановления снимка
показано **«Нет данных»**. Итог выполнения не означает доставку ответа в Telegram:
недоставленные результаты по-прежнему доступны через `/outbox`.

## Что приходит в тему

- текст ответов агента: Markdown переводится в разметку Telegram (жирный, курсив, код, блоки
  кода, ссылки, цитаты; заголовки — жирным, списки — строками с маркерами, таблицы — строками
  «ключ: значение» или карточками). Длинные ответы делятся на несколько сообщений; если
  Telegram не примет разметку, сообщение уйдёт обычным текстом;
- `📍 Прогресс задачи` — обновляемая карточка со состоянием, длительностью, числом
  инструментов и кнопкой остановки текущего запуска. Имена инструментов показываются
  без аргументов; ответы, разрешения и вопросы приходят отдельными сообщениями;
- `✅ Готово · ходов: N · $0.42` — задача завершена;
- `❌ …` — ошибка агента, `⏹ Остановлено` — после `/stop` или выхода из приложения.

По умолчанию включён компактный прогресс. В «Настройки → Telegram и доступ → Прогресс задач»
можно выбрать подробный: каждый вызов инструмента снова приходит как `🔧 Tool: …`.
Режим применяется к следующим запускам без перезапуска бота. В `settings.toml`
подробный режим записывается как `progress = "detailed"` в `[telegram]`; отсутствие
поля означает компактный. Перед откатом на версию без этой настройки удалите поле.

Карточка обновляется не чаще раза в 5 секунд, с общим пределом одного запроса
карточек в секунду. Ограничение Telegram может задержать обновление. При ошибке
карточки выполнение и сохранение ответа продолжаются, а следующие сообщения об
инструментах переходят в подробный вывод. Удаление кнопки после завершения выполняется
по возможности; оставшаяся старая кнопка не остановит новую задачу. Карточки не
восстанавливаются после перезапуска; актуальное состояние доступно через `/status`.
