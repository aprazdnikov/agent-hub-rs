# Переносимая память проекта

Пользователь выбрал первую версию общей памяти для своей разработки. Поддерживаются
все существующие агенты: Claude Code, Codex, Qwen Code, Hermes и OpenCode. У пользователя
настроены Codex, Qwen Code и Hermes, но это не ограничивает поддержку продукта.
Основание: обсуждение Company Brain, разрешение «Давай делать» и уточнение
«нужно чтобы поддерживало все агенты которые уже есть». Это локальная персональная функция.

## Подход

Рассмотрены: общая память; память с полноценным управлением задачами; командная
платформа с ролями и workflows. Для первой версии выбран тонкий слой памяти без
собственных LLM-вызовов. Состояние работы пока является записью памяти.

Библиотека `hub-memory` хранит версионируемые записи и предоставляет stdio MCP.
Режим `agent-hub --memory-mcp --project-dir <absolute-path>` работает до запуска
GUI, Telegram, single-instance lock и keyring. Один и тот же бинарник используется
в приложении и при самостоятельном подключении внешнего harness. Отдельные
MCP-процессы обращаются к общему хранилищу; постоянный демон не требуется.

Хранилище по умолчанию: `~/.agent-hub/memory`. Область проекта определяется
каноническим абсолютным каталогом; имя каталога хранения — SHA-256 пути. Перенос
проекта и разные Git worktree пока означают разные области памяти. Данные не
попадают автоматически в репозиторий. `--store-dir` позволяет задать другой корень.

## Данные и операции

Категории: `context`, `decision`, `progress`, `artifact`. Запись имеет стабильный
ключ, заголовок, текст, источники, автора, время и номер ревизии. Источники — ссылки
или текстовые указания; сервис их не открывает. Автор — диагностическая метка
клиента, не удостоверенная личность. Запись типа decision сама по себе не является
доказательством одобрения человеком. Инструкции MCP требуют различать предложения
и принятые решения, указывать основания, не сохранять секреты и полные диалоги.

Три инструмента: `memory_search`, `memory_get`, `memory_write`. Поиск по последним
ревизиям, по тексту и метаданным, без embeddings или inference. Читать отдельную
старую ревизию можно через `memory_get`. Запись требует `expected_revision`:
0 создаёт запись, известная текущая версия обновляет. Повтор идентичного запроса
возвращает уже записанный результат; устаревшее отличающееся изменение отвергается.

Ограничения: ключ 1–64 ASCII alnum/underscore/hyphen; заголовок до 256 байт;
текст до 16384 байт; 1–8 непустых источников до 2048 байт каждый; автор до 128 байт;
запрос поиска до 512 байт, выдача 1–20 элементов, excerpt до 400 символов;
500 ключей, 32 ревизии на ключ, 8 МиБ файла на проект. Превышения отвергаются,
история не удаляется молча. Лимит строки JSON-RPC — 1 МиБ.

## Целостность и границы

Межпроцессный lock защищает read-modify-write. Занятость возвращается явно без
бесконечного ожидания. Запись заменяется атомарно; повреждённый или неизвестный
формат не перезаписывается. На Unix управляемые каталоги/файлы приватны (0700/0600).
Симлинки и неподдерживаемые типы файлов в управляемом хранилище отвергаются.

Это не песочница от других программ того же пользователя. Содержимое памяти
является данными, не полномочиями или инструкциями более высокого приоритета.
Удалённый HTTP, OAuth, командные ACL, автоматический импорт истории, планировщик,
автоматическое одобрение решений и запуск моделей не входят в первую версию.

## Интеграция и проверка

Codex получает MCP через конфигурацию thread/start и thread/resume; Qwen/Hermes/OpenCode —
через ACP session/new и session/load; Claude Code — через --mcp-config при новом
запуске и --resume. Текущие инструменты хаба сохраняются.
Служебная генерация /handoff не получает доступ к памяти, включая восстановление
Codex thread с ранее подключённым сервером. Пользовательские MCP не заменяются.

Критерий технической готовности: два независимых процесса видят общие записи после
перезапуска, сохраняют источники и историю, обнаруживают конфликт обновлений;
payloads всех пяти адаптеров подключают сервис на новой и восстановленной сессии.
Проверки выполняются локально без платных модельных ходов. Качество самостоятельного
выбора и использования памяти реальными моделями — отдельный пользовательский пилот.
