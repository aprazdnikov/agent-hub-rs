# Обновление GUI — дизайн

> Дата решения: 2026-11-22. Статус: утверждено владельцем-product, ожидает плана реализации.
> [Каталог документов](../README.md) · [Порядок этапов](../history.md).
> Утверждённые макеты: [чат](assets/gui-refresh/chat.html), [входящие и действия](assets/gui-refresh/inbox.html), [сайдбар и результат](assets/gui-refresh/sidebar-review.html) (открывать в браузере; светлая тема, текущая палитра).

## Цель

Сделать десктопный GUI хаба удобнее в ежедневной работе: читаемая переписка вместо «простыни», действия задачи без похода в «Параметры» и вложенных раскрытий, читаемые состояния задач. Навигация, расположение зон и палитра сохраняются — меняется подача, не структура.

## Границы

**Цели**
- Переписка задачи: визуальное разделение ролей, статусы, время, сворачивание длинных ответов.
- Входящие: ответ на вопрос и решение по разрешению прямо на карточке, без шага «раскрыть».
- Действия задачи: главное по состоянию — кнопкой в шапке чата; редкое — меню «⋯».
- Сайдбар: состояния задач читаются с первого взгляда; счётчик внимания у проекта.
- Экран результата: вкладки-секции вместо стопки вложенных раскрытий.
- Фаза 2: тот же язык в разделах Темы, Новая задача/Правила, Настройки, Память.

**Не-цели**
- Менять навигацию (вкладки, сайдбар, расположение зон), палитру, типографику, горячие клавиши.
- Менять логику команд, протоколы агентов, Telegram-мост, хранение настроек.
- Markdown-рендеринг ответов агентов (текст остаётся plain text с переносами).
- Редизайн трея, окна обновлений, мастера первого запуска.

**Анти-цели**
- Потерять поведение в узком/низком окне (compact-режимы уже есть и должны пережить редизайн).
- Сломать обратную совместимость файлов задач и настроек.
- Убрать подтверждения опасных действий (удаление, перезапуск при активных сессиях, выход при сохранении).
- Регресс доступности: фокус-кольца, тултипы, клавиатурная отправка.

## Ограничения

- Стек: `eframe`/`egui` 0.36, без новых зависимостей.
- Линты воркспейса: `warnings = deny`, clippy pedantic deny, запрещены `unwrap/expect/panic/indexing_slicing`.
- Темы: светлая и тёмная следуют ОС (`theme::configure`); каждый новый цвет обязан иметь тёмный вариант.
- Тесты GUI кликают по текстам кнопок (`click_text` в `gui/tasks.rs`, `gui/topics.rs`); перенос кнопок в меню требует обновить сценарии, а не удалить проверки.
- `Run` сериализуется с `deny_unknown_fields`: новые поля только с `serde(default)`.
- Лимиты не меняются: поручение 16 КиБ, название 256 байт, замечание 2048, 32 запуска, 32 файла.

## Фаза 1 — экраны

### Чат задачи (`gui/tasks/workspace.rs`, `gui/tasks/result.rs::transcript`)

- Шапка: breadcrumb (как сейчас), заголовок + чип состояния задачи, справа главное действие и «⋯» (ниже). Подзаголовок weak: `агент · цель · память`.
- Переписка: пузыри по ролям. Шапка пузыря: «Вы» или точка+имя агента, чип состояния запуска (`RunState::label`), время справа (small weak). Тело — plain text с переносами, selectable.
- Время: `HH:MM` локальное из новых полей `Run` (раздел «Данные»). У старых запусков без дат время не показывается.
- Сворачивание: тело ответа агента длиннее 8 строк свёрнуто по умолчанию, градиентное затухание + «Развернуть»/«Свернуть»; состояние per-run хранится в `result::View`. Сообщения пользователя не сворачиваются (свой текст, важно редактирование поручения). Вызов исполнителя: порог можно тюнить, поведение по умолчанию — как указано.
- Футер пузыря агента: чипы «N файлов», «проверки X/Y» (если есть). Ссылка «Результат →» — только у последнего проверяемого запуска (открывает его результат); у более старых пузырей ссылки нет, их содержимое доступно во вкладке «История». Diagnostic — error-цветом внутри пузыря.
- Композер: поле и кнопка «Отправить»/«Запустить» в одной рамке (радиус 12), кнопка у правого края по нижнему краю поля; подсказка Ctrl+Enter — под рамкой. Поле растёт с 1 строки до 8 (~160px), дальше внутренняя прокрутка. Существующие `shortcut`, `char_limit`, черновики и конфликт-баннер сохраняются.
- Панель решения (`local_panels`) при активном вопросе остаётся внизу вместо композера (как сейчас), но оформляется карточкой.
- Compact (высота < 360px): пузыри и шапка сохраняются, подзаголовок в одну строку (как сейчас); инлайн-кнопка результата сохраняется.

### Входящие (`gui/tasks/attention.rs`, `gui/tasks/local.rs`)

- Группы «Ждут вашего ответа» / «Результаты на проверку» с счётчиками; фильтр проектов — без изменений.
- Элемент — карточка: иконка-плашка 26px слева (?, ⚠, ✓ по типу), заголовок strong + meta small weak (`проект · агент`), чип типа справа.
- **Вопрос**: текст вопроса и варианты ответа (чипы-переключатели, single/multiple как сейчас) прямо на карточке; поле «Ответ или свой вариант» + «Отправить ответ» (primary) + «Отказаться» (ghost) — на карточке. Несколько вопросов — стопкой в той же карточке. Кнопки «Ответить»/«Свернуть» и состояние `Inbox::expanded` для вопросов убираются. Логика `Editor` (drafts, pending, feedback) сохраняется.
- **Разрешение**: «Разрешить действие «tool»?» + summary monospace, свёрнутое до 3 строк с «Подробнее»; кнопки «Разрешить один раз» (primary) / «Отклонить» сразу.
- **Результат/ошибка/очередь/Git**: summary weak + чипы проверк/файлов для Review; кнопка действия справа («Проверить», «Открыть проверку», «Разобрать запуск», «Проверить Git», «Открыть очередь») — существующий маппинг `Attention → Tab` сохраняется.
- Узкое окно (< 440px): кнопка действия под содержимым (как сейчас).
- Пустое состояние и feedback-строки — без изменений.

### Шапка задачи и меню действий (`gui/tasks/workspace.rs`)

Главная кнопка по состоянию (утверждено):

| Состояние | Кнопка в шапке |
|---|---|
| Выполняется, локально | «Остановить» (danger-outline, шлёт существующий `LocalStop`) |
| Выполняется, тема Telegram | чип «Выполняется» + «Открыть тему» (существующий opener); остановки нет — сессии моста управляются в «Темы» |
| Нужна проверка | «Открыть результат» (primary) + «Принять» (secondary, существующий `Request::Status` Accepted) |
| В очереди | «Снять с очереди» (существующий `Unqueue`) |
| Ошибка / прерван | «Разобрать запуск» (открывает вкладку Проверки) |
| Черновик | кнопка у композера, как сейчас |

«Принять» в шапке — предложение исполнителя дизайна, принято владельцем как частое действие; подтверждение не добавляем (действие обратимо через статус).

Меню «⋯»: Параметры задачи · Правила проекта · Контекст следующего запуска · очередь (по состоянию: «В очередь» и «В очередь в отдельном worktree» — оба варианта с существующими условиями видимости и валидации; либо «Снять с очереди») · В архив / Восстановить · Удалить… (существующий confirm). Пункты шлют существующие `Request`; страница «Параметры» остаётся для настроек (агент, Git, память, executor controls).

### Сайдбар (`gui/tasks/sidebar.rs`)

- `Mark::paint`: точки 8px по токенам выше; running пульсирует (repaint ~1s только при наличии выполняющихся задач); тултип с текстом состояния сохраняется.
- Заголовок проекта: бейдж-счётчик задач, требующих внимания (по `Attention`/живым запросам этого проекта), справа от имени; ноль — не показывать.
- Выделение выбранной строки, поиск, меню проекта, фильтры — без изменений.

### Экран результата (`gui/tasks/result.rs`)

- Вкладки-секции вместо `CollapsingHeader`-стопки: **Сводка** (result, diagnostic, чипы файлов и проверок), **Изменения · N файлов**, **Проверки · X/Y**, **Файлы · N**, **История · N**. Одна секция открыта за раз. В `result::Tab` добавляется вариант `Files` (остальные уже есть); deep-link из входящих сохраняет переход на нужную вкладку.
- «Изменения»: существующий diff-вьюер с аннотациями строк без изменений.
- «История»: список попыток, одна ступень раскрытия на попытку (вложенные «Сохранённые изменения» остаются внутри попытки).
- Нижняя панель «Принять результат» / «На доработку» закреплена (как сейчас).

## Данные: время запусков

`Run` получает `started_at: Option<jiff::Timestamp>` и `finished_at: Option<jiff::Timestamp>` с `serde(default, skip_serializing_if = "Option::is_none")`.

Единственные точки записи — API книги задач в `hub-core/src/tasks.rs`:
- `begin(id, revision, next)` (~729, push ~774) — `started_at`;
- `finish(id, run, state)` (~845) — `finished_at`;
- `recover()` (~861) — переводит зависшие запуски в `Interrupted` **без** `finished_at`: время завершения неизвестно, время загрузки приложения не должно выдаваться за него.

Часы инжектируются вызывающей стороной по конвенции репозитория (`render_limits(..., now, tz)`, `quotas.apply(update, Timestamp::now())`): `begin` и `finish` получают параметр `Timestamp`, вызывающие передают `Timestamp::now()`. Вызовы: `hub-app/src/local_execution.rs` (239, 353, 445, 530) и `hub-telegram/src/hub/tasks.rs` (668, 677, 714), плюс тесты. `Run` в `hub-telegram/src/hub.rs` (~1303) — собственная структура живого запуска моста, к датам книги задач отношения не имеет и не меняется.

Старые файлы загружаются без дат (время скрыто). Новые файлы со старым приложением несовместимы по `deny_unknown_fields` — допустимо, откат не поддерживается (зафиксировать в релизных заметках). Отображение — локальное время `HH:MM` (`jiff::tz::TimeZone::system()`, уже используется), дата в тултипе при отличии от сегодня. Пузырь пользователя показывает `started_at`, пузырь агента — `finished_at`.

## Фаза 2 — разделы (тот же язык)

Порядок утверждён: Темы → Новая задача/Правила → Настройки → Память.

- **Темы Telegram** (`gui/topics.rs`): строки → карточки входящих. Шапка: имя + чип состояния (работает/свободна) + чип этапа при работе; meta `проект · бэкенд`; кнопки «Telegram» и «⋯» на карточке. В меню: память темы (существующий переключатель), параметры/прогресс текстом, копирование ссылки и session_id, открытие папки, сброс/удаление с существующими подтверждениями. Раскрытие «Параметры» inline убирается. Поиск и фильтры (backend/state/phase) остаются как есть.
- **Новая задача** (`gui/tasks/workspace.rs::new_task`, `context.rs`): селекторы «Проект / Где запустить / Агент» компактной строкой; поле поручения с авторостом (компонент чата); название — видимое опциональное поле с подсказкой вместо `collapsing`; причина блокировки — подсказкой у кнопки «Начать задачу»; «Сохранить черновик» secondary. **Правила проекта** (`gui/tasks/rules.rs`): группы-карточки, единые отступы.
- **Настройки** (`gui/settings.rs`, `settings/navigation.rs`): навигация 8 разделов сохраняется; секции (`ui.strong`-заголовки) оформляются карточками-группами; панель сохранения закреплена снизу с индикатором несохранённых изменений (существующие `has_unsaved`/`save_status`); блоки агентов — карточка на агента.
- **Память** (`gui/memory.rs`, `gui/memory/*`): «Инструменты памяти» и прочие `collapsing` → секции/вкладки по образцу результата; пакет контекста — карточка; опасные операции (удаление ревизий, перенос) — с существующими подтверждениями.

## Инварианты поведения

- Команды и эффекты (`Request`/`Effect`/`Command`) не меняются; GUI только переставляет контролы. Единственное изменение сигнатур — параметр времени в `begin`/`finish` книги задач (раздел «Данные»); логика команд и эффектов та же.
- Сохранение: guard-модалы выхода/перезапуска, баннеры сохранения — без изменений.
- `scroll_body` с резервом нижних панелей и clip-rect остаётся; компактные и узкие раскладки переживают редизайн.
- Фокус-кольца и клавиатурная навигация (тест `navigation_label_stays_inside_its_hover_and_focus_ring`), Ctrl+Enter, черновики поручений и конфликт-баннер.
- Тёмная тема: все новые компоненты читаются в обеих темах (тест паритета).

## Тесты

- Обновить click-through сценарии под новые позиции кнопок (меню «⋯», карточки входящих), сохранив проверки эффектов.
- Новые: serde-совместимость `Run` без дат; сворачивание/разворачивание длинного ответа; авторост композера в пределах 8 строк; счётчик внимания проекта; паритет новых токенов в тёмной теме; `recover()` не проставляет `finished_at`.
- Тесты времени передают фиксированный `Timestamp` (инъекция часов), без `Timestamp::now()` в assertions.
- Существующие тесты `theme`, `attention`, `local`, `result` (diff-аннотации) должны проходить без ослабления.

## Порядок работ

Фаза 1: токены и общие компоненты → данные времени → чат → входящие → шапка/меню → сайдбар → вкладки результата.
Фаза 2: Темы → Новая задача/Правила → Настройки → Память.
Каждый шаг — компилируется, тесты зелёные, визуальная проверка в светлой и тёмной темах.

## Что остаётся исполнителю

Механика egui-раскладок (пузыри через `allocate_ui_with_layout`, меню, вкладки), расписание repaint для пульсации, точные пороги сворачивания, тюнинг тёмных оттенков в рамках палитры, миграция тестов, формулировки релизных заметок о несовместимости отката.

## Вызовы исполнителя дизайна (после ревью строителем)

Ревьюер-строитель поднял 5 вопросов; все закрыты без изменения утверждённого объёма:

1. **Часы и точки записи** — инъекция `Timestamp` в `begin`/`finish` по конвенции репозитория; `recover()` оставляет `finished_at` пустым (иначе время загрузки выдавалось бы за время завершения crashed-запуска). Якорь `hub.rs:1303` из первой редакции был ошибочным (там собственный `Run` моста) — исправлено.
2. **«Остановить» для тем Telegram** — кнопки нет: per-task остановка моста не существует, а добавлять её запрещает не-цель «не менять Telegram-мост». Вместо неё «Открыть тему».
3. **«Результат →» у старых пузырей** — ссылки нет: просмотр произвольного старого запуска — новая возможность, а не перестановка контролов. Старые запуски доступны во вкладке «История» (как сейчас).
4. **Вкладка «Файлы»** — в `result::Tab` добавляется вариант `Files` (утверждение «enum достаточно как есть» было фактически неверным).
5. **Очередь в меню** — оба варианта («В очередь», «В очередь в отдельном worktree») с существующими условиями; ничего не выбрасывается.

Также зафиксировано: бейдж внимания проекта зеркалит состав входящих; «Открыть результат» дублируется инлайн только в compact-режиме; состояние сворачивания per-run — `transcript` получает `&mut result::View`.
