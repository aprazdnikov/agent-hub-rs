# MEM-07 — задачи и ручные запуски

Подтверждено пользователем 2026-11-21: ручной запуск и восстановление; без очереди
и параллельных задач. MEM-08 (сеть/команда) отложен, 1.0.0 остаётся локальным + Telegram.

Задача имеет собственный ID, проект, выбранного агента, поручение и историю запусков.
Telegram-тема — место выполнения, не идентификатор задачи. Создание не запускает модель.
GUI и `/task` используют общий актор хаба. Запуск требует работающего бота и выбранной
темы того же проекта/агента; получение разрешений остаётся в существующем интерфейсе.

Перед запуском сохраняется номер попытки и состояние «Выполняется». Повтор команды
с прежней ревизией не запускает вторую попытку. Одновременно разрешён один управляемый
запуск задачи; обычные независимые чаты сохраняют прежнее поведение. После сбоя
незавершённые попытки помечаются «Прервана», автоматического повтора нет. Продолжение
требует явного действия и указания следующего шага после проверки прежних эффектов.
Нельзя гарантировать exactly-once внешних действий агента после аварии; гарантия хаба —
не повторять запуск автоматически и не объявлять неизвестный результат успешным.

Состояния попытки: running, completed, failed, interrupted. Успех запуска не приёмка
задачи пользователем. Сохраняются итоговый текст и диагностический статус; полная
переписка не копируется. Поручения и итоговые ответы сохраняются без фильтрации
секретов; пользователь не должен включать их в эти тексты.

Хранение: отдельный версионируемый sidecar рядом с topics.json, общий writer — актор.
Атомарная публикация до запуска; ошибка записи блокирует запуск, неопределённость
не разрешает повтор без перечитывания. Задачи не входят в память проекта и Move/Share
не переназначают их автоматически. Файлы повреждённой/неизвестной версии не заменяются.

Сначала подготовить модель и тесты переходов; затем файловый порт и интеграцию с
событиями запуска/результата; затем GUI/Telegram и проверки восстановления.


## Итоговые границы реализации

TaskBook v1: 100 задач, 32 попытки, 16 КиБ поручение/шаг, 64 КиБ результат.
Физический JSON до 8 МиБ + 1 КиБ служебного резерва. Активная попытка резервирует
место до публикации, recovery старого заполненного файла допускает компактное
форматирование без потери текста. Один writer использует существующую блокировку
экземпляра приложения; Unix fsync каталога, Windows — прежняя атомарная замена
без заявления эквивалентной гарантии при отключении питания.

GUI scope включает тему, проект и backend; ответ старого scope отбрасывается,
черновики создания очищаются при смене scope, следующий шаг привязан к ревизии.
Telegram сохраняет свободный текст с переносами; выдача ограничена четырьмя
параллельными карточками, с проверкой доступа перед каждой частью и отменой при shutdown.
Если предыдущая карточка выдаётся, повтор команды не выполняет новую мутацию.
