# MEM-02: просмотр и управление памятью

Статус: утверждён пользователем; реализован локально, ручная приёмка обоих интерфейсов ожидается.

## Цель и выбранный подход

Пользователь выбрал оба интерфейса сразу: Telegram и настольное приложение.
Без вызова модели можно определить область памяти, найти запись, прочитать
источники и историю, увидеть заполнение, отключить и вернуть подключение.
Основание — MEM-01: поиск по ключу оказался неудобен, способ подключения
и свежесть состояния были неочевидны.

Рассмотрены Telegram с переключателем только в приложении (меньше интерфейсов),
только Telegram (доступ с телефона), оба интерфейса (выбор пользователя).
Оба интерфейса используют общие операции и сохранённое состояние.

## Настольное приложение

Новая вкладка «Память», доступная и при остановленном боте:

- Выбор проекта из известных каталогов тем/профилей и выбор существующей папки.
  Каталоги объединяются по каноническому пути. Выбор папки не меняет каталог темы.
- Путь проекта и полный путь хранилища. Если памяти ещё нет, отдельное пустое
  состояние; просмотр не создаёт каталогов, файлов и записей памяти.
- Глобальный переключатель «Подключать память к агентам» с явной подписью
  «Для всех проектов в этом приложении». Его состояние доступно также в настройках.
- Список последних записей с поиском по ключу, заголовку, тексту и источникам;
  пагинация, точное открытие по ключу, обновление по кнопке.
- Карточка: ключ, категория, заголовок, текст, источники, автор, время и ревизия.
  Выбор исторической ревизии без её изменения; счётчик ревизий относительно 32.
- Заполнение: количество ключей из 500, размер сохранённых данных из 8 МиБ.
  Размер — байты файла данных, не произвольная сумма файлов каталога.
- Отдельные состояния загрузки, пустых результатов, отсутствующей ревизии,
  ошибок доступа/диска, повреждения/версии формата, блокировки и конфигурации.

Файловые операции выполняются вне UI-потока. Результат старого запроса не может
заменить данные после выбора другого проекта. Ошибка обновления не выдаётся за
пустое хранилище; прежний результат помечается устаревшим.

## Telegram

`/memory` работает в теме с известным рабочим каталогом, не запускает агента
и не входит в его очередь заданий. Доступ — по существующим проверкам группы
и разрешённых пользователей. Без каталога выводится предложение выбрать проект.

Меню: область/путь, заполнение, список записей, поиск, открытие по ключу,
карточка и история, обновление, глобальное включение/выключение.
Для открытия и поиска предусмотреть также `/memory get KEY [REVISION]` и
`/memory search QUERY`. Полный текст длинных записей доступен постранично,
не обрезается без возможности прочитать остаток. Лимиты сообщений соблюдаются,
содержимое экранируется как данные; источники автоматически не открываются.

Переключение из Telegram требует кнопки подтверждения, где явно написано
«для всех проектов и агентов этого приложения». Это защищает от случайного
глобального изменения из меню одной темы, а не является новым уровнем доступа.
Старые кнопки проверяют пользователя, тему и текущую область: после смены
каталога предлагают обновить меню и не читают старую область молча.

## Подключение и сохранение настройки

Предложение реализации: `[memory] enabled = true`, отсутствие настройки в старом
файле означает true. Это одна настройка приложения, не темы и не отдельного агента.
Оба интерфейса сохраняют её через общий механизм приложения; Telegram не пишет
settings.toml самостоятельно. Изменение не затирает несохранённые поля формы GUI:
форма должна слить внешнее изменение либо явно показать конфликт перед сохранением.
Неуспешное сохранение не показывается как успешно применённое отключение.

Применение — при следующем запуске процесса агента, в том числе с возобновлением
его сессии. Текущая работа не прерывается; уже запущенный процесс продолжает
с прежним подключением. Следующее сообщение в живой процесс само по себе
не гарантирует применения. Интерфейс объясняет: дождаться завершения процесса
или остановить задачу штатным способом, затем продолжить.

Показывать отдельно сохранённую настройку и фактическое состояние активных
процессов, если оно известно. Не называть память отключённой в работающем
процессе только по значению настройки. При отсутствии сведений — «неизвестно».

Проверяются Claude, Codex, Qwen, Hermes и OpenCode: новая и resumed-сессия,
включено → выключено → включено. При отключении не должно оставаться встроенного
сервера из возобновляемого состояния. Другие MCP, модели и настройки не меняются.
Ручные внешние CLI и их MCP не управляются переключателем хаба. Данные сохраняются;
просмотр доступен даже при отключённом подключении к агентам.

## Архитектурные границы

- hub-memory: общий API чтения области, статистики, списка/поиска, истории;
  чтение без создания хранилища. Существующие write/revision/locking-инварианты
  и формат данных сохраняются. Для поиска добавить ключ к индексируемому тексту,
  в том числе в MCP memory_search; прочие аргументы и ограничения MCP сохраняются.
- hub-core: настройка и команда /memory; hub-agent и backend-крейты: применение
  флага только к зарезервированному серверу agent-hub-memory.
- hub-app: асинхронный доступ, сохранение настройки, состояние подключений и GUI.
- hub-telegram: меню/команды и общий сервис чтения; сохранение настройки через
  существующий канал управления приложением либо минимальный типизированный порт.
  Точную раскладку модулей и типы определяет план после трассировки всех callers.

Путь проекта канонизируется тем же способом, что в существующем Store.
Telegram не принимает произвольный путь хранилища от пользователя в callback.
Desktop выбирает проект, не открывает произвольный JSON в обход валидации Store.
Источники и автор — данные, не доказательство одобрения человеком.

## Не входит

Редактирование и удаление записей, импорт/экспорт, очистка/архивирование,
перенос между каталогами, новая схема хранения, автоматическое исправление
статусов моделью, управление ручными MCP вне хаба — за пределами MEM-02.
Эти функции не требуются для просмотра и относятся к последующим этапам.

## Проверка готовности

Тесты: чтение без создания, поиск по ключу, пагинация и ревизии, статистика,
различимые ошибки, экранирование/длинный текст, устаревшие callbacks,
сохранение настройки и конфликт GUI, неизменность данных при переключении,
все пять backend-путей с new/resume и сохранением сторонних MCP.
Проверить штатное исключение памяти из служебной генерации /handoff.

Ручная проверка: найти mem01-pilot-quick-check и открыть r1/r4 с источниками
в обоих интерфейсах без модели; увидеть тестовую запись отдельного проекта;
выключить память, проверить следующий процесс доступного агента, включить и
прочитать прежние данные. Проверить запуск GUI без работающего Telegram.
Недоступные живые backend-проверки отмечать отдельно от автоматических тестов.

Следом — план реализации и проверки; commit, push и выпуск не выполняются
автоматически в рамках этого дизайна.
