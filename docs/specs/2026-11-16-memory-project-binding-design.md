# MEM-04: принадлежность памяти проекту

Продолжение [roadmap](../roadmap/2026-11-15-company-brain-roadmap.md).
Решения ниже приняты агентом в рамках поручения продолжать самостоятельно.

## Цель и подходы

После переноса checkout пользователь явно связывает новый каталог с прежней памятью.
Выбранный worktree может явно подключиться к той же памяти. Совпадение remote,
названия или скопированных файлов проекта ничего не объединяет.

Рассмотрены маркер UUID в репозитории (переносится автоматически, но копируется и
не выражает согласия), идентичность Git (не покрывает проекты без Git и смешивает
worktree), локальный реестр явных привязок. Выбран реестр в каталоге пользователя.
Автоматическое обнаружение физического перемещения не обещается: нужен один шаг
«Подключить прежнюю память». Это также работает после перемещения каталога.

## Контракт

- Без привязки сохраняется существующий хеш канонического пути.
- Стабильный ID — прежний хеш; в snapshot исходный путь остаётся идентичностью
  и происхождением, а выбранный рабочий каталог показывается отдельно.
- Реестр `<store-dir>/.projects/memory.json`, схема 1, отображает канонический
  рабочий путь в исходную идентичность. Ссылки прямые, без цепочек.
- Move подключает новый каталог и запрещает обращения по прежнему пути.
  Share оставляет оба пути подключёнными. Вся память, статусы, история, tombstones
  и политика очистки общие. Сессии, чаты, разрешения и настройки агентов не общие.
  Для выборочного копирования знаний используется существующий экспорт/импорт.
- После move прежний путь зарезервирован: его повторное использование не открывает
  прежнюю память. Автоматического отвязывания/переиспользования нет.
- Источник move может отсутствовать; тогда требуется его прежний абсолютный
  канонический путь. Источник share и назначение должны существовать.
- Целевая память с любым snapshot или существующей привязкой не замещается.
  Конфликт решается отдельно через экспорт/импорт, без скрытого объединения.
- Изменение только после preview: показаны оба пути, режим, ID и область общих данных.
  Подтверждение связано с реестром и токеном snapshot источника.
- Существующие Store/MemoryReader проверяют актуальность привязки при обращении;
  изменение назначения требует нового открытия. Межпроцессные блокировки источника,
  назначения и реестра исключают запись поверх смены привязки.
- Реестр атомарно заменяется, ограничен 1 МиБ/4096 путями. На Unix используются
  fsync файла, реестра и его родительского каталога, защита от symlink/hardlink,
  права 0700/0600. Windows наследует переносимый слой; равенство гарантий fsync
  каталогов и защиты от подмены ссылок не заявляется. При повреждении отказ,
  без отката к памяти по пути. Проектные файлы не читаются для выбора хранилища.

## Миграция и восстановление

Данные не перемещаются и не преобразуются: legacy v1/v2 остаются в прежнем месте.
Одно атомарное изменение реестра — точка публикации. До неё работает прежняя
привязка, после неё новая. Прерванный временный файл не меняет опубликованный
реестр. После ошибки fsync уже опубликованного реестра возвращается отдельная
ошибка неопределённого результата с целевым каталогом для проверки. Повтор после
успеха не создаёт второй snapshot и не теряет данные.
Резервное копирование должно включать весь store-dir, в том числе `.projects`.
Восстановление реестра вручную допустимо только при остановленных клиентах;
для восстановления содержимого доступны проверенный экспорт и импорт.

## Интерфейсы и проверки

Общий resolver в hub-memory используется Store и MemoryReader, поэтому GUI,
Telegram, пять адаптеров и самостоятельный `--memory-mcp` получают одну привязку.
Управление — GUI с preview и отдельный `--memory-project` CLI с токеном подтверждения.
MCP-инструменты изменения привязки не предоставляются.

Тесты: перенос после rename, share с записью из двух клиентов, изоляция третьего,
v1 без потери байтов, конфликт назначения, устаревший preview/Store/Reader,
повреждённый/небезопасный реестр, прерванная публикация, повтор операции.
GUI и CLI используют те же API и не выполняют I/O в потоке отрисовки.
