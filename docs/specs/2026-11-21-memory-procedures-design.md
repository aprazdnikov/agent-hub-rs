# MEM-06: первая переносимая процедура

Поручение: продолжить реализацию roadmap перед релизом. Пользователь ранее поручил
самостоятельную работу; выбор реализации ниже — решение агента, не отдельное
подтверждение продуктовых деталей пользователем.

Основание: в MEM-01 агент перенёс устаревший список незавершённых проверок.
Первая процедура `continue-work@1` задаёт проверяемое продолжение по памяти:
прочитать актуальную ревизию, проверить источники, выполнить разрешённый следующий
шаг, обновить фактический прогресс, явно различить результат и приёмку человеком.

## Подходы

- Документ в репозитории: минимален, но пользователь должен самостоятельно его искать.
- Встроенный версионируемый документ с просмотром/копированием в GUI и выдачей
  `/memory procedure` в Telegram: выбран, доступен обоим существующим интерфейсам.
- Автоматическая установка skills в пять CLI: не выбрана — затрагивает настройки
  разных harness и меняет приоритеты инструкций без потребности из пилота.

Один Markdown-источник включён в бинарник. Публичная константа в hub-memory;
GUI читает её напрямую, Telegram через существующий read-only dispatcher.
Текст короче 3500 UTF-16 единиц, чтобы передаваться одним сообщением.
Версия указана внутри текста; содержательные изменения требуют новой версии.
Нового MCP-инструмента, автоматического исполнения, каталога пользовательских
процедур, LLM-вызовов, записи в память или конфигурацию нет.

Процедура применима только при явном поручении пользователя и известных проекте,
ключе и границах работы. Отсутствие данных, источника или полномочий не заменяется
предположением. Пакет MEM-05 остаётся данными, процедура — отдельно выбранным шаблоном.
Разрешения прежней сессии не переносятся; native skills сохраняются.

Проверки: Telegram parser и отсутствие записи при чтении процедуры, одинаковый
текст в общей константе и выдаче, неизвестные аргументы отвергаются; GUI просмотр
и копирование. Живое сравнение до/после на Codex и Qwen — отдельный пилот: без него
не заявлять, что процедура устранила ошибки модели.
