# MEM-03: жизненный цикл и перенос памяти

Статус: утверждён пользователем 2026-11-15 («все ок»). Реализация описана
в [плане MEM-03](../plans/2026-11-15-memory-lifecycle.md); продуктовый код реализован, автоматические проверки пройдены; живая приёмка ожидается.

## Решение пользователя и подход

Оба механизма нужны: по умолчанию только явная очистка; автоматическая
очистка включается отдельно на риск пользователя. Это не разрешение очистить
существующую память сейчас.

Выбран комбинированный подход вместо только ручного обслуживания или
автоматического удаления по умолчанию. Сохраняем локальное JSON-хранилище,
атомарную запись и MCP. Перенос на другую СУБД для этого этапа не нужен.
Управление доступно из GUI и Telegram; автоматическая политика хранится
в области проекта, чтобы standalone CLI и хаб соблюдали одинаковые правила.

## Режимы очистки

**Ручной (по умолчанию).** Никакого автоматического удаления. При заполнении
операция возвращает понятную причину и способы освободить место. Пользователь
выбирает старые ревизии или записи, видит точный объём удаления и подтверждает.
Перед подтверждением доступен экспорт; удаление без экспорта требует явного
предупреждения о невозможности восстановления средствами приложения.

**Автоматический (явное включение).** Предлагаемая начальная политика:
сохранять последние 32 ревизии каждого ключа. При добавлении 33-й сохраняются
ревизии 2–33; счётчик не сбрасывается. Если превышены 8 МиБ, удаляются старейшие
исторические ревизии, но последняя ревизия каждой записи остаётся. При одинаковом
времени порядок определяется ключом и номером ревизии. Если этого недостаточно,
вся запись отклоняется без частичной очистки. При 500 ключах автоматического
удаления целых записей нет: нужна ручная очистка.

Включение показывает область проекта, условия удаления и предупреждение:
«Старые ревизии будут удаляться без дополнительного подтверждения.
Без экспорта восстановить их нельзя». Отдельная кнопка «Включить автоочистку».
Выключение прекращает будущую очистку, но не возвращает уже удалённую историю.
Первоначальное включение само ничего не удаляет: политика действует при
следующей записи, прочитанная под блокировкой, без перезапуска MCP.

Автоматические резервные копии при каждом удалении не создаём: иначе лимит
активного файла маскирует неограниченный рост копий. Экспорт остаётся явным.
В интерфейсе видны режим, число удалённых ревизий и время последней очистки.

## Состояния записей

- Активная: входит в обычный поиск и последние записи.
- Устаревшая: скрыта из поиска по умолчанию; доступна через фильтр и по ключу,
  с видимой отметкой. Отметка не является проверкой истинности содержания.
- Архивная: скрыта из обычного поиска, доступна в архиве и по ключу;
  не обновляется агентом, пока пользователь не вернёт её в активные.
- Удалённая: текст и история удалены после отдельного подтверждения.

Архивирование/устаревание не освобождают место. Автоматическая очистка старых
ревизий распространяется на все неудалённые записи, включая архивные; это явно
указывается при включении. Изменение состояния не переписывает содержимое
последней ревизии и не расходует слот истории.

Удалённый ключ оставляет компактную отметку с последним номером ревизии,
чтобы запоздалый memory_write не воскресил запись. Повторное создание того же
ключа обычным агентским write запрещено; восстановление возможно через явный
импорт под новым ключом. Предложенный предел таких отметок — 4096 на проект, они входят в 8 МиБ,
но не в лимит 500 неудалённых записей. При исчерпании предела удаление
отклоняется; отметки не вытесняются автоматически. Ограничение показывается в UI.
Для восстановления работоспособности доступно явное «Новое поколение хранилища»:
после проверенного экспорта пользователь выбирает сохраняемые неудалённые записи,
видит сбрасываемые отметки и подтверждает. Пересоздание атомарно сохраняет выбранные
записи и историю, очищает отметки и назначает новый случайный идентификатор поколения
(incarnation). Это не автоматическая очистка. Каждый MCP Store запоминает incarnation
при открытии и сверяет его под блокировкой перед изменениями; старый процесс после
сброса получает ошибку «хранилище пересоздано, запустите новую сессию», а не пишет
в новое поколение. При сбое экспорта/записи поколение не меняется. Нужен новый процесс
и новая агентская сессия: старый диалог может содержать уже удалённые сведения.

## История и конкурентные изменения

Лимит 32 означает число хранимых ревизий, а не максимальный номер. Номера
монотонные, до предела u32; переполнение возвращает ошибку. После очистки
старые номера не переиспользуются. GUI/Telegram показывают фактически доступные
номера; запрос удалённой версии сообщает, что история сокращена, а не что
запись потеряна. MCP сохраняет expected_revision и защиту от конфликтов.
Повтор write ищется по номеру ожидаемой ревизии + 1, не по индексу массива.
Повтор удалённого исторического результата не запускает новую запись.

Все изменения выполняются под существующей блокировкой. Просмотр перед
ручной операцией выдаёт поколение snapshot; подтверждение проверяет его заново.
Если данные изменились, пользователь обновляет предварительный просмотр.
Нет подтверждения старого списка, который уже не соответствует хранилищу.

## Экспорт и импорт

Экспорт — один JSON с версией переносимого формата, исходной областью,
записями, источниками, авторами, временем, доступной историей, состояниями
и отметками сокращённой/удалённой истории. Экспорт не обещает вернуть версии,
которых уже нет. Политика автоочистки передаётся как информация, но её импорт
никогда автоматически не включает. Целевой файл не перезаписывается без выбора.

GUI: выбор файла и предварительный просмотр. Telegram: экспорт по явной кнопке
отправляет файл в текущую разрешённую тему; импорт принимает JSON-вложение
только в специально начатом сценарии /memory import. Обычные вложения не
считаются импортом. Перед экспортом предупреждение, что содержимое станет
доступно участникам группы. Не допускаются архивы, исполнение содержимого,
скачивание указанных источников или извлечение произвольных путей.

Размер входного файла ограничен 16 МиБ до разбора (с учётом оболочки экспорта);
размер итогового хранилища по-прежнему ограничен 8 МиБ; проверяются схема, UTF-8,
лимиты полей/истории, уникальность ключей/ревизий и целевая область. Неизвестная
версия отклоняется. Импорт из другого каталога требует явного подтверждения
целевого проекта; это копирование данных, не изменение идентичности проекта.

Предварительный просмотр разделяет новые, идентичные и конфликтующие ключи.
По умолчанию конфликты пропускаются. Совпадающая история — no-op. Совместимое
продолжение истории добавляется только при совпадении пересекающихся ревизий;
нужна хотя бы одна общая совпадающая ревизия. Истории без пересечения нельзя
считать совместимыми только по номерам. Любое несовпадение содержимого/метаданных
или удалённая локальная запись — конфликт.
Для конфликта: оставить локальное либо сохранить входящее под новым ключом.
Замены существующего ключа расходящейся историей нет: она могла бы повторно
использовать старые номера ревизий и пропустить запоздалую запись агента.
Обе копии и список решений видны до подтверждения. Для копий под новым ключом сохраняется происхождение: SHA-256 канонического
экспортируемого объекта записи (включая исходную область и ключ) и выбранный
целевой ключ. Повтор того же объекта находит эту копию и предлагает no-op,
даже если локальная копия уже обновлена; изменённый входящий объект снова проходит
сверку и предварительный просмотр. Метаданные происхождения входят в общий лимит
и хранятся с записью/отметкой удаления, а не в неограниченном журнале.
Входящая отметка удаления не удаляет активную локальную запись: это конфликт.
Применяется целиком одна атомарная операция, либо
ничего; повтор импорта не создаёт новые ревизии или дубли. Автоочистка во время
импорта не запускается: превышение лимита требует явного решения до применения.

## Формат v2 и миграция

Нужен v2: состояния записей, политика, incarnation, поколение snapshot и метаданные
сокращённой истории не представимы текущим v1 без изменения схемы.
Чтение GUI поддерживает v1 без изменения файлов. Перед первой изменяющей
операцией в v2: под блокировкой сохранить проверенную резервную копию v1,
проверить её повторным чтением, затем атомарно записать v2. При ошибке копии
или миграции исходный файл остаётся действующим. Предыдущая копия не
перезаписывается молча; миграция повторяется идемпотентно после сбоя.

Перед переходом рекомендуется завершить работу агентов и обновить бинарник,
чтобы их операции не стали завершаться ошибкой несовместимого формата.
Старый writer получает блокировку, заново читает и проверяет схему; после
миграции он обязан отклонить v2, не перезаписать его. Старые сборки v2 не читают; downgrade возможен восстановлением сохранённой
копии v1 при остановленных агентах, с явной потерей изменений после миграции.
Миграция пользовательских данных не выполняется при разработке/тестах.

## Интерфейсы и границы

Вкладка «Память» и /memory получают фильтр состояний, действия архивирования,
пометки устаревания/возврата, предварительный просмотр очистки, экспорт/импорт
и настройку политики выбранного проекта. Все изменяющие callbacks проверяют
пользователя, чат, тему, область, поколение данных и актуальность подтверждения.

В MCP остаются чтение/поиск/запись; фильтр состояния поиска расширяется
обратно совместимо. Агент не получает инструменты удаления, смены политики,
импорта или автоматического подтверждения человеком. Ручная администрация
и содержание памяти не меняют права модели.

Не входит: синхронизация машин, общая идентичность worktree (MEM-04),
семантический поиск, автоматическое принятие решений, командные права.

## Проверки

Временные копии хранилищ: v1→v2, сбой до/после записи backup, неизвестная схема;
ручной режим не удаляет; автоматический режим удаляет только старую историю,
сохраняет последние записи и источники; номера/конфликты/повторы после очистки;
исчерпание каждого лимита и предела отметок; новое поколение после экспорта,
отказ старому MCP-процессу, сохранность при сбое; rollback всей операции при ошибке.
Импорт: идентичный повтор, несовпадающая история, удалённый ключ, другой проект,
чрезмерный размер, ошибки записи, stale preview, запрет скрытой автоочистки.
Оба интерфейса: подтверждения, фильтры, история с пропусками, ошибки, права,
экспорт/импорт без модели. Полный workspace test/clippy/fmt и сборка.

Точные типы API, раскладка модулей и тестовые команды — следующий план
после утверждения дизайна. Коммит, push и релиз отдельно не поручены.
