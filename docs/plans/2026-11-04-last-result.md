# AH-11: сохранение ответа и /last

> План и журнал завершённого этапа. Коммит: [67fcf4c](https://github.com/aprazdnikov/agent-hub-rs/commit/67fcf4c).
> [Каталог](../README.md) · [Порядок этапов](../history.md) · [Текущий статус и проверки](../roadmap/README.md).

Статус: выполнено и проверено, включено в локальный `main` этим коммитом.
AH-07 в `main`: `a4d9fa4`.

Цель: вернуть текст последнего успешно завершённого хода текущей темы после сбоя
отправки или перезапуска, без обращения к модели. AH-12 (автодоставка) — отдельный этап.

Архитектура: чистые записи/ограничения в `hub-core::results`, порт хранения и команда
в `hub-telegram::results`, файловый worker в `hub-app::results`. Rust/Tokio/serde,
существующий атомарный writer; новые зависимости не нужны. Изменение уровня Boundary:
Run/HubSetup/HubMessage, relay и конструктор TelegramConnector; все callers обновляются.

## Решения реализации

- Общий контракт всех пяти бэкендов: последние последовательные непустые AssistantText
  после последнего отображаемого ToolCall, завершённые Finished. Claude/Codex дают готовые блоки;
  Qwen/Hermes/OpenCode flush-ят накопленный текст перед инструментом и концом хода.
  Метка Finished подтверждает успех; служебные события рассуждений/инструментов и отдельные
  интерактивные сообщения вопросов/разрешений не архивируются. Скрытые send_file/ask_user
  не образуют ToolCall: соседние AssistantText могут объединиться и содержать пояснение
  перед вопросом/отправкой файла. Семантический финальный ответ протокол не гарантирует.
  Смысловую «финальность» по тексту не угадываем. Без ToolCall несколько текстовых блоков
  объединяются, поэтому в них могут остаться пояснения бэкенда.
- Relay задерживает эти блоки до ToolCall/Finished/Failed/закрытия потока. Сбор событий и запись отделены от сети:
  последовательная очередь доставки до 32 текстовых частей, до 64 КиБ каждая. Три места резервируются для ошибки сохранения, ответа и окончания. Переполнение
  не блокирует сохранение; пропуск сообщений отмечается предупреждением с указанием /last.
  Каждая отправка ограничена 65 с, остановка отменяет доставку. Перед инструментом
  отправляет их как промежуточные; при Finished сначала сохраняет, потом отправляет ответ.
  Failed и незавершённый поток сбрасывают накопленный текст в доставку, не заменяя старый
  результат; остановка отменяет доставку и запрещает ещё не принятые Hub записи.
- Буфер до 64 КиБ UTF-8 с разделителями. При превышении flush без усечения обычного вывода;
  до следующей границы запись отключена, Finished сообщает, что ответ не сохранён из-за размера.
  Для уже несохраняемой большой группы доставка использует backpressure и сохраняет полное
  Markdown-форматирование; при зависшей сети эта исключительная ветка может ждать доставки.
  Нет текста после инструмента — нет новой записи. Каждый Finished получает UUID хода.
- /last показывает время UTC, бэкенд, каталог и ID хода, затем исходный Markdown.
  Reset/смена проекта не удаляют результат темы; метаданные явно показывают его происхождение.
  Привязка включает chat+thread: результаты другой группы не выдаются.
- Не более 100 тем, по одному результату; 30 дней с окончания. Просроченное не выдаётся; физическая очистка при следующем сохранении; при превышении количества удаляются самые старые записи.
- Отдельный `topics.results.json`, версия 1, список записей: chat, thread, run UUID,
  completed_at Unix seconds, backend, cwd, session, text. Старые topics/settings не меняются.
  Ограниченное чтение файла и валидация; повреждённый файл не перезаписывается, бот работает,
  /last и сохранение показывают ошибку. Unix файл 0600, существующий symlink отклоняется.
- Один файловый worker на TelegramConnector, очередь до 16 запросов; сохраняется при
  перезапусках бота. Диск не блокирует Hub/GUI. Ожидание до 5 с; отменённые запросы из очереди
  пропускаются, уже начатая операция может завершиться позже. Один worker гарантирует порядок
  записей и ограничивает зависший I/O. Переполнение/ошибка явно сообщаются, обычный ответ отправляется.
- Hub допускает запись только от актуальной generation темы без уже обработанной отмены; вызывает порт синхронно при
  обработке сообщения, чтобы порядок enqueue совпадал с порядком Hub. /last имеет актуальный
  allowlist до и после load, максимум 4 запроса целиком (чтение + доставка), один на тему;
  deadline 65 с, запросы отменяются при shutdown.
- Для AH-12 пока нет retries/outbox. Файлы и вложения не сохраняются для повторной отправки.

## План и проверки

### 1. Формат записей и ограниченный текстовый буфер
Создать `crates/hub-core/src/results.rs`, экспорт в `lib.rs`.
`SavedResult::new(key, run, completed_at, session, text)` валидирует запись;
`Results::parse(raw, now)`, `dump()`, `save(record, now)`, `get(key)`.
RED: round-trip, границы размера/количества/TTL, повреждение и разделение тем.
GREEN: `cargo test -p hub-core --lib --locked results`.

### 2. Хранилище и worker
Создать `hub-telegram/src/results.rs`: `ResultStore` с `save`/`load` BoxFuture.
Создать `hub-app/src/results.rs`, экспорт в `lib.rs`; reader с Take(max+1), атомарный writer,
очередь worker. Обновить `connector.rs` и `main.rs` для долгоживущего shared store.
RED: save/load после пересоздания, права, повреждение без перезаписи, ошибка записи,
TTL/количество, зависший worker и переполнение очереди. Локальные tempdir/fakes.
GREEN: `cargo test -p hub-app --lib --locked results`.

### 3. Relay и /last
Изменить `hub-telegram/src/session.rs:Run/relay`, `hub.rs:HubSetup/HubMessage/command/launch`,
`hub-core/src/commands.rs`, тестовый MemoryResults в `testing.rs`.
Сохранение через сообщение Hub с generation и oneshot ответом до финальной отправки.
RED: /last без результата, успешный ответ после failed send и рестарта, промежуточный
текст/ошибка/остановка, последовательные Finished, устаревшая generation, ошибка диска,
длинный ответ, смена группы/allowlist, чтение без запуска модели/смены сессии.
GREEN: `cargo test -p hub-telegram --lib --locked last` и `results`.

### 4. Документация и завершение
Обновить README, этот план и usability-backlog; отметить проверенное отдельно от ограничений.
Отдельное ревью по requesting-code-review, исправить существенные замечания.
`cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
`cargo test --workspace --locked`, `cargo deny check`, `cargo build -p hub-app --locked`.
Старый формат не мигрирует; rollback игнорирует sidecar, его можно удалить для очистки.
Коммит в main только после согласования точного сообщения, без подписей и push.
