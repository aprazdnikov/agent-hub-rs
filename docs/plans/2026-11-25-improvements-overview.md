## Ветки и коммиты

- Ветка на задачу: `aprazdnikov/<topic>` от актуального `main`.
- Коммиты на русском, префиксы `fix(telegram):` / `feat(core|gui|telegram):` / `release:`.
- Каждый шаг плана заканчивается gate из `docs/development.md`
  (`cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  `cargo test --workspace --locked`, `cargo deny check`, `git diff --check`).

## Ревью Qwen Code — общий шаблон промпта

```
Ты ревьюер. Рабочая копия — чистый checkout ветки <branch> с base <main-sha>.
1. Прочитай план docs/plans/<файл>.md, секции Global Constraints и Review Focus.
2. Изучи git diff <main-base>...HEAD целиком.
3. Для каждого пункта Review Focus укажи: выполнено / не выполнено / требует живой
   проверки — со ссылкой на файл:строку или тест.
4. Отдельно проверь: разбор input на границах, обработку ошибок без паник и unwrap,
   атомарность записи файлов, отсутствие обращений вне каталогов хаба, регрессы
   сериализации topics.json/tasks.json/settings.toml на старых файлах.
5. Вынес вердикт: APPROVE / REQUEST_CHANGES со списком блокирующих замечаний.
```

## Решения, требующие подтверждения владельца

Прежде чем отдавать задачи в работу, подтвердите (или поправьте) выбранные варианты —
они помечены в планах как **D-N**:

- **D-1** (удаление проекта): каскад = задачи+очередь, правила, память проекта, ссылки в
  темах, список последних; НЕ трогаются папка проекта, worktree внутри неё, сами темы
  Telegram и снапшоты сессий.
- **D-2** (удаление проекта): подтверждение модалкой с вводом названия проекта.
- **D-3** (синхронизация тем): если Telegram подтвердил отсутствие темы, её удаляем даже
  при задачах в очереди — задачи остаются, но отвязываются от темы. Активные запуски —
  пропускаем и сообщаем.
- **D-4** (роли): глобальные роли = исполнитель и ревьюер задач; команда проверки остаётся
  на проекте. Проект: выключено / наследовать общие / свой выбор.
