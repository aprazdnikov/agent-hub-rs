# AH-07: проверка ресурсов проекта

Статус: выполнено и проверено, включено в локальный `main` этим коммитом.
AH-06 включён в `main` коммитом `6a79309`.

## Решение

В профиле до восьми именованных проверок: HTTP(S) GET с точным ожидаемым статусом
(200–599, по умолчанию 200) или TCP host/port. HTTP не следует редиректам, проверяет TLS,
не читает тело; URL без userinfo, query/fragment, токенов и произвольных заголовков.
HTTP-прокси не используются: запросы идут напрямую. TCP проверяет соединение, не вход в сервис. Приватные адреса допустимы: это ресурсы
проектов, которые пользователь задаёт локально. Telegram не принимает адреса для проверки.

`/doctor` в теме предлагает выбрать сохранённый проект. Это диагностика выбранного
профиля, без смены привязки и сброса контекста. Однозначный выбор кнопкой нужен потому,
что несколько профилей могут использовать одинаковые каталог и бэкенд. Карточка показывает
название проекта и время проверки UTC, каталог (границы workspace/симлинки), наличие
CLI (без его запуска и проверки входа), результаты HTTP/TCP, состояния связанных
пользовательских процессов. Состояние команды не объявляется состоянием VPN.
Недоступность ресурса не доказывает, что VPN отключён.

Кнопки «Повторить» и «Действия» доступны из отчёта. Вторая открывает существующее
меню `/actions`; команда запускается только отдельным нажатием пользователя. Проверка
не вызывает модель, не запускает VPN, не повторяет задачу и не меняет системную сеть.
При отсутствии профилей — подсказка добавить их на ПК; существующие профили без проверок
дают диагностику каталога/CLI/процессов и объяснение, как добавить ресурсы.

Каждая сетевая проверка ограничена 5 с, общий запрос — 10 с. Не более двух запросов
одновременно, один на тему; повторное нажатие не дублирует работающую проверку.
Синхронная проверка файловой системы/CLI вынесена с исполнительного потока в ограниченные
blocking jobs; их лимит сохраняется даже при тайм-ауте ожидания. DNS HTTP и TCP используют
общий resolver: до 16 вызовов системного DNS/NSS, permit удерживается внутри blocking
closure до возврата getaddrinfo даже после отмены. TCP подключается к готовым SocketAddr.
Лимиты файловой системы/DNS общие для перезапусков бота. Остановка бота отменяет
сетевые задачи. Буфер результатов ограничен числом проверок; тела ответов не скачиваются.

Кнопки одноразовые, TTL 15 минут, не более 256 токенов. Проверяются актуальный allowlist,
чат и неизменность профиля; после изменения настроек старые кнопки не проверяют новый
адрес. Завершившийся отчёт устаревшей конфигурации не публикуется как актуальный.
В ошибках HTTP показывается тип сбоя, а не строка ошибки с полным URL.

## Реализация и проверки

- [x] `crates/hub-core/src/doctor.rs`, `projects.rs`, `settings.rs`: типы/валидация
  проверок, необязательное поле `checks` в профиле, round-trip/старые настройки.
- [x] `crates/hub-app/src/gui/settings.rs`: добавление/удаление HTTP/TCP, поля условий
  успеха и ошибок; egui-тесты формы. Вложенный блок выделить в отдельную функцию.
- [x] `crates/hub-app/src/doctor.rs`: реальный runner, тайм-ауты, локальные TCP/HTTP
  fixtures без внешней сети, редирект/ошибочный статус/зависание/отказ соединения.
- [x] `crates/hub-telegram/src/doctor.rs`, `actions.rs`, `hub.rs`, `commands.rs`:
  команда, меню, bounded jobs/tokens, карточка, повтор и переход к действиям;
  fake-runner тесты авторизации, старых кнопок, занятости, отмены и отсутствия запуска модели.
- [x] `connector.rs`, README, журнал задач, независимое ревью, проверки.

Rust/egui/Tokio/reqwest; URL разбирается существующей в lockfile библиотекой `url`.
Изменение затрагивает конфигурацию и сетевую границу. Старые настройки дают пустой список
проверок. Для возврата к AH-06 удалить вложенные `[[projects.checks]]`; `topics.json`
и история проектов не меняются. Секреты и специальные VPN-интеграции вне этапа.

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo deny check
cargo build -p hub-app --locked
```

Коммит — после проверки и согласования точного сообщения; без служебных подписей и push.

## Выполнено и проверено — 2026-11-04

- Добавлены типы HTTP/TCP, валидация, поле `checks` и TOML round-trip. Старые профили
  без проверок читаются. В GUI доступны добавление, редактирование и удаление проверок.
- `/doctor` выбирает профиль без смены контекста, формирует отчёт с UTC, каталогом/CLI,
  ресурсами и состояниями связанных процессов; повтор и меню действий раздельны.
- Реализованы одноразовые UUID-кнопки, TTL/лимиты, актуальная авторизация и отбрасывание
  результата при изменении настроек. Остановка бота отменяет задачи диагностики.
- Добавлены 22 теста, расширены тесты формы и состояний процессов. Локальные fixtures
  проверяют HTTP/TCP, неожиданный статус, редирект без перехода, зависший ответ, ошибки
  файлов/симлинков, сохранение контекста, повтор, лимиты и отмену.
- Независимое ревью выявило накопление блокирующих DNS-вызовов после тайм-аута.
  Исправлено общим resolver с permit внутри blocking closure; регрессионный тест
  отменяет HTTP, проверяет отказ новых HTTP/TCP без новых lookup и освобождает worker.
  Повторное ревью: блокеров нет, 21 целевой тест прошёл независимо.
- `cargo test --workspace --locked`: **1408 passed, 12 ignored**, ошибок нет.
  `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
