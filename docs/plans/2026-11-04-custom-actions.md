## Объём

Пользователь выбрал универсальные именованные команды вместо отдельных интеграций VPN.
Команды могут завершаться самостоятельно или оставаться работать в foreground.

В GUI: «Настройки → Действия», добавление/удаление, название, многострочная команда,
необязательный каталог (по умолчанию домашний). Настройки сохраняются существующей кнопкой.
В Telegram: `/actions` в теме или общем чате, кнопки запуска/остановки, результат с кодом
завершения и ограниченным выводом. Запуск не вызывает агента.

Команды исполняются в `/bin/sh -c` на Unix и `cmd.exe /D /S /C` на Windows, с окружением
приложения, без терминала и интерактивного stdin. Нет автоматических повторов и ограничения
времени жизни постоянной команды. Один экземпляр каждого действия; остановка бота,
перезапуск или полный выход из приложения отменяют управляемые процессы. Сворачивание
в трей их сохраняет. Самостоятельно запущенные внешние системные сервисы хабом не управляются.

Кнопка означает явный запуск сохранённой команды от текущего пользователя ОС. Telegram
не задаёт команду или параметры: передаёт одноразовый идентификатор. Действует allowlist;
изменение определения делает старую кнопку запуска неактуальной. Редактирование или
удаление настройки не лишает уже работающий процесс возможности остановки через `/actions`.

## Реализация

1. `hub-core/src/actions.rs`, `settings.rs`, `commands.rs`: валидация и типы, аддитивный
   `[[actions]]`, общий реестр `/actions`. Пустой список не записывается; старые настройки
   читаются. Команды скрыты в Debug, но находятся открытым текстом в settings.toml.
2. `hub-app/src/actions.rs`: самостоятельный runner с ограниченным stdout/stderr,
   управлением деревом процессов и отменой. Реальные тесты только на безвредных subprocess.
3. `hub-telegram/src/actions.rs`, `hub.rs`: одноразовые кнопки, ограниченный реестр,
   параллельная с агентами работа, защита от повторов и устаревшей остановки, shutdown.
4. `hub-app/src/connector.rs`, `gui/settings.rs`: подключение runner и редактирование.
5. README и backlog: описание пользовательского сценария и новой очередности.

## Проверки

- RED: существующий parser отвергает `[[actions]]`, `/actions` отсутствует в меню.
- После реализации: TOML round-trip, старый формат, валидация, отсутствие команд в Debug.
- Контроллер: повторный callback, неверный пользователь, изменённая команда, истёкшая кнопка,
  удаление активного действия, остановка предыдущего запуска, shutdown.
- Runner: stdout/stderr, ненулевой код, большой вывод, длительный процесс, отмена дерева,
  drop, отсутствующий cwd; без запуска VPN и без пользовательских команд.
- GUI: отображение и сохранение редактируемого действия.

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

Тесты с настоящими агентами или VPN в этот набор не входят.
