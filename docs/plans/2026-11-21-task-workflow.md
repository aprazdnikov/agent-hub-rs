# Управление задачами — план реализации этапа 1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

Статус: этап 1 реализован; финальная проверка после ревью пройдена. Ручная проверка остаётся отдельно.

**Goal:** Отделить приёмку задачи от результата запуска и сделать историю доступной в обоих интерфейсах.

**Architecture:** Модель и переходы находятся в TaskBook. Существующий актор остаётся
единственным владельцем записи; GUI и Telegram отправляют ему одинаковые запросы.
Фильтрация не меняет данные и ограничена проектом выбранной темы.

**Tech Stack:** Rust, serde, egui, существующие Telegram actor и файловое хранилище.

**Spec:** [Проект решения и последующие этапы](../specs/2026-11-21-task-workflow-design.md).

## Global Constraints

- Интерфейс и сообщения ошибок на русском, включая выбранные значения списков.
- Архив не освобождает существующий лимит 100 задач.
- Перезапуск не повторяет внешние действия автоматически.
- Новых зависимостей, очереди и удалённого API нет.

## Review Focus

- Старый файл с попытками: появляется «Нужна проверка», история не меняется.
- Устаревшая карточка: изменение отклоняется без перезаписи новой ревизии.
- Активная попытка: архивирование и ручная смена статуса отклоняются.
- Другой проект: поиск, чтение попытки и изменения не раскрывают его задачи.
- Ошибка сохранения: GUI не показывает изменение как подтверждённое.
