Статус: реализовано и проверено автоматически; включено в `main` коммитом `c334342`.
Предыдущий этап AH-13 включён в `main` коммитом `1641c6e`.

## Решение

Цель: найти тему по названию или каталогу и открыть её в Telegram либо открыть каталог.
Остаются Rust/egui и существующая таблица. Состояние фильтров живёт во вкладке до закрытия
приложения, не меняет настройки/привязки и сохраняется при обновлении списка.

Над списком: текстовый поиск без учёта регистра (Unicode lowercase), фильтр по бэкенду,
фильтр «Все / Работают / Свободны», сброс и счётчик найденных тем. Пустой результат
отличается от отсутствия тем. Поиск также понимает отображаемый `#id` неизвестной темы.
Строка: кнопки Telegram, копирование ссылки, открытие каталога; прежние Stop/Reset
и подтверждение сброса сохраняются. Длинные названия/пути не прячут кнопки:
ограниченная ширина ячеек, полный текст по наведению, горизонтальная прокрутка.

Ссылки `https://t.me/c/<channel>/<thread>` строятся только из корректного ID супергруппы
и положительного ID темы. Некорректные старые записи не дают выдуманных ссылок.
Проверено по [документации ссылок Telegram](https://core.telegram.org/api/links#forum-topic-links)
и [преобразованию Bot API ID](https://core.telegram.org/api/bots/ids#supergroup-channel-ids).

Открытие использует существующие системные команды (`explorer`, `open`, `xdg-open`)
с отдельным аргументом, без shell и без интерпретации пути как команды. Проверка каталога
и запуск происходят в одном фоновом потоке; одновременно ожидается один запуск.
Запущенные процессы опрашиваются без блокировки UI, в том числе на других вкладках.
На Unix ненулевой код отображается как ошибка. Код завершения Windows Explorer
не интерпретируется: он бывает ненулевым после успешной передачи запроса; проверяются
существование каталога и успешный spawn.
Одновременно отслеживается не более восьми запусков: системная программа может жить
до закрытия своего окна. Файловый менеджер/браузер не завершаются при выходе из хаба.
Ошибка содержит путь/ссылку; копирование ссылки доступно независимо от запуска.
Успешный запуск обработчика не доказывает доступ к группе в Telegram.

Охват: модуль GUI плюс граница запуска процесса. Схемы данных и Telegram-команды
не меняются, новых зависимостей нет. Специальная интеграция с Telegram Desktop,
сохранение фильтров и поиск по истории сообщений не входят в этап.

## Шаги

- [x] `crates/hub-app/src/gui/topics.rs`: тест UI отсутствующих кнопок, затем строка
  фильтров и чистая фильтрация; тесты поиска по русскому названию/пути, сочетания
  фильтров, сброса и пустого результата. Команда: `cargo test -p hub-app --lib --locked gui::topics`.
- [x] `crates/hub-app/src/gui/look.rs`: `topic_url(TopicKey) -> Option<String>`;
  тесты валидных и граничных chat/thread ID, без переполнения. Команда:
  `cargo test -p hub-app --lib --locked gui::look`.
- [x] `crates/hub-app/src/gui/folder.rs`: фоновый запуск и ограниченное отслеживание
  процессов; отсутствующий/обычный файл вместо каталога, пути с пробелами/Unicode,
  ошибка spawn/exit и освобождение занятого запуска проверяются без открытия настоящих
  окон. Старый `open` для логов остаётся совместимым. Команда:
  `cargo test -p hub-app --lib --locked gui::folder`.
- [x] `crates/hub-app/src/gui/topics.rs`: кнопки переходов, буфер обмена и ошибки;
  egui-тесты с настоящими событиями мыши: копирование правильной ссылки, фильтры,
  Stop/Reset выбранной темы. Не открывать реальные проекты/Telegram в тестах.
- [x] README, журнал выполнения, независимое ревью и общие проверки.

Проверка RED → GREEN: сначала тест должен выявить отсутствующее поведение, затем
минимальная реализация. Для чистых новых функций допустим компилируемый stub до реализации.

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo deny check
cargo build -p hub-app --locked
```

Результат на Linux: все команды прошли; 1364 теста прошли, 12 live-тестов ignored.
Отдельно прошли 69 тестов GUI. Тесты воспроизвели отсутствие поиска/ссылок, ошибки
файловой системы и ненулевой код запуска до реализации соответствующего поведения.

Независимое ревью выявило два дефекта, оба исправлены:

- Сдвиг заголовков Grid из-за оборачивания всей строки в `push_id`: воспроизведён
  тестом геометрии egui; идентификаторы теперь задаются отдельным ячейкам.
- Ложная ошибка при ненулевом завершении Explorer: отделена политика Windows.
  Источник: [воспроизведение в Microsoft WSL](https://github.com/microsoft/WSL/issues/6565).

Повторное ревью не выявило блокеров. Проверены события мыши для поиска/фильтров,
сброса, копирования ссылки и Stop/Reset нужной темы; удалённый каталог; ошибки
spawn/exit; передача пути с пробелами, Unicode и shell-метасимволами одним аргументом;
защита от второго одновременного запуска. Настоящие окна/Telegram не открывались.

Ограничения: ручные переходы на Linux/Windows/macOS не проверялись. Нельзя подтвердить
доступ пользователя к группе по успешному запуску обработчика. Зависшая проверка
сетевого каталога может занять единственный слот запуска; UI продолжает работать,
новые фоновые потоки не накапливаются. Фильтры сбрасываются при закрытии приложения.
Коммит после согласования точного сообщения; без служебных подписей и без push.
