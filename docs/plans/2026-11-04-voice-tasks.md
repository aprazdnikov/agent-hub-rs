# AH-16: голосовые задачи

Статус: реализовано, проверено автоматически и включено в локальный `main`; ручные проверки реального распознавания остаются открытыми. Пользователь выбрал локальное распознавание и внешний API с переключением в настройках.

## Решение

- По умолчанию распознавание выключено. Локальный вариант: установленный пользователем Whisper.cpp (`whisper-cli`), модель и FFmpeg. Внешний: API, совместимый с `POST /audio/transcriptions`; адрес и модель настраиваются, ключ хранится отдельно в системном хранилище секретов. Переключение сохраняет настройки обоих вариантов.
- Обрабатываются голосовые сообщения Telegram в теме. До подтверждения текст не передаётся исполнителю. Видео-кружки остаются неподдержанными.
- Лимиты: 180 секунд, 10 МиБ фактически загруженного аудио, 180 секунд на загрузку и распознавание. Одновременно до двух распознаваний; до 32 черновиков. Текст до 3000 единиц UTF-16; превышение выдаёт ошибку без молчаливого обрезания. Черновик действует 10 минут.
- Предпросмотр: «Отправить», «Исправить», «Отмена». Исправление — ответ на конкретное сообщение бота и повторный предпросмотр. Обычные сообщения не поглощаются режимом исправления. Кнопки привязаны к автору и сообщению; повторная отправка невозможна.
- Изменение контекста темы, настроек распознавания или доступа аннулирует черновик. Перезапуск очищает все черновики. Ошибки предлагают отправить текст.
- Аудио не сохраняется в проект или историю. Для API используется память; локально OGG/WAV передаются через stdin/stdout, без аудиофайлов. Рабочий временный каталог процессов остаётся пустым и удаляется при завершении. Перенаправления API и автоматические повторы запросов отключены. В журналах нет аудио, текста, ключа и ответа сервиса.

## Проверка

Поддельное распознавание и локальные HTTP/process fixtures: до подтверждения нет запуска, повторная кнопка, чужой пользователь/чат/сообщение, исправление через reply и повторное подтверждение, отмена, лимиты, тайм-аут, смена контекста/настроек, очистка процессов/файлов. Проверки не вызывают реальные Telegram и платные API. Качество на настоящих голосовых и запуск установленных Whisper.cpp/FFmpeg на Windows/macOS остаются отдельной ручной проверкой.

Источники протоколов: [OpenAI transcription API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create), [Whisper.cpp](https://github.com/ggml-org/whisper.cpp/blob/master/README.md). Проверены 2026-11-04.

## Журнал реализации

- 2026-11-04/05: добавлены оба провайдера, выбор в GUI, отдельный ключ, метаданные Telegram и ограниченная загрузка, редактирование через ForceReply и подтверждение только автором.
- Решение: вместо временных аудиофайлов использовать OGG/WAV в стандартных потоках. Завершение процесса на Windows может опережать закрытие файлов; передача в памяти исключает остаточное аудио при отмене и аварийном закрытии.
- Ревью выявило подтверждение старого черновика после восстановления снимка той же сессии. Регрессионный тест сначала воспроизвёл ошибку, затем прошёл: черновики аннулируются при разрешении импорта и перепривязке; во время операции со снимком новое распознавание не начинается.
- Ограничение длительности внешнего варианта использует метаданные Telegram. Локальный адаптер дополнительно ограничивает реальный объём декодированного PCM (180 секунд).
- Ручная проверка качества распознавания и реальных CLI на целевых ОС ещё не выполнялась; платных запросов и отправки аудио внешним сервисам при разработке не было.

## Результаты проверки, 2026-11-05

- `cargo test --workspace --locked` — PASS: 1643 теста; 13 пропущены явно (12 живых интеграций и отдельный GUI/GIO fixture автозапуска, уже проверенный в AH-15).
- `cargo clippy --workspace --all-targets --locked -- -D warnings` — PASS.
- `cargo fmt --all -- --check`, `git diff --check`, `cargo deny check` — PASS.
- `cargo build -p hub-app --locked` — PASS на Linux.
- 24 теста адаптеров прошли ещё 20 раз при 24 тестовых потоках (480 случаев). Найденная нестабильность была `ETXTBSY` при параллельном создании shell fixtures и наследовании файловых дескрипторов при fork. Исправлена сериализацией только локальных тестовых fixtures; производственные запуски не повторяются автоматически.
- Rust-код адаптера проверен в изолированном harness для Windows GNU и macOS ARM64. В harness отключён TLS у reqwest: полная кросс-сборка TLS-зависимости `ring` требует отсутствующих здесь C toolchains. Это проверка условно компилируемого кода адаптера, а не сборка/запуск приложения на этих ОС.
- Независимое итоговое ревью: блокирующих замечаний нет. Регрессия восстановления снимка воспроизведена до исправления и прошла после него.
