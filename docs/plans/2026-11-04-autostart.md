# AH-15 — автозапуск при входе

> План и журнал завершённого этапа. Коммит: [fd23479](https://github.com/aprazdnikov/agent-hub-rs/commit/fd23479).
> [Каталог](../README.md) · [Порядок этапов](../history.md) · [Текущий статус и проверки](../roadmap/README.md).

Дата: 2026-11-04. Статус: реализация проверена локально и включена в локальный `main`;
ручной вход на целевых ОС остаётся непроверенным.
AH-10 включён в `main` коммитом `a57f600`.
Пользователь выбрал поддержку сразу Linux, Windows и macOS. Реализация разрешена;
точное сообщение коммита согласовано после проверок. Без push и служебных подписей.

## Дизайн

- Настройки приложения: отдельный блок автозапуска с фактическим состоянием ОС,
  включением, отключением и обновлением статуса. Операция применяется сразу, отдельно
  от Telegram и кнопки сохранения формы. По умолчанию ничего не регистрируется.
- Состояние не дублируется флагом в settings.toml. Неизвестное/изменённое состояние
  и ошибки показываются явно; после операции статус считывается заново.
- Linux: XDG autostart desktop entry для текущего пользователя, системные записи
  с тем же именем учитываются; отключение через Hidden перекрывает системную запись.
- Windows: HKCU Run через безопасный registry API, с проверкой StartupApproved;
  отключение пользователем через Windows не обходится автоматически.
- macOS: пользовательский LaunchAgent с отдельными аргументами, проверкой системного
  запрета через launchctl и разрешения фоновой работы через SMAppService.statusForLegacyURL.
- Регистрация использует абсолютный путь, сохранённый до self-replace, и --autostart.
  Пробелы/спецсимволы экранируются по правилам платформы; путь всегда передаётся как
  данные, не вставляется в исходный код скрипта.
  Перенос бинарника требует явного обновления регистрации; обновление на прежнем пути
  не меняет запись. Чужие/повреждённые файлы и ошибки доступа не считаются успехом.
- Обычный запуск открывает окно. Автозапуск с готовыми настройками: Linux сворачивает
  окно, Windows/macOS скрывают его только при доступном трее. Без настроек/трея окно
  доступно. Повторный --autostart тихо завершается по существующей блокировке экземпляра.
- Одна фоновая операция регистрации на интерфейс; GUI не ждёт диск/системные процессы.
  Внешние команды ограничены временем и объёмом вывода. VPN сам не подключается.

## Результаты и решения

- `cargo test --workspace --locked`: 1551 passed, 0 failed, 13 ignored. Из ignored
  12 — прежние live-тесты, один — отдельная проверка desktop-file-validate/gio.
  Последняя выполнена отдельно и прошла: запускается только временная программа,
  пользовательская регистрация автозапуска не меняется.
- `cargo fmt --all --check`, `git diff --check`,
  `cargo clippy --workspace --all-targets --locked`, `cargo build -p hub-app --locked`: PASS.
- `cargo deny check`: advisories, bans, licenses, sources — OK.
- Windows: 10 тестов модели; изолированная компиляция исходного адаптера для
  x86_64-pc-windows-gnu (Clippy all-targets) и x86_64-pc-windows-msvc (check all-targets).
- macOS: 21 fixture-тест на Linux; исходный адаптер и тесты проверены Clippy all-targets
  для aarch64-apple-darwin. Добавлена нативная read-only проверка JXA-моста на временном
  незарегистрированном plist: она запустится на macOS, здесь не выполнялась.
- Интеграционный тест запускает настоящий бинарник с --autostart и занятой блокировкой
  во временном XDG-каталоге: выход успешен без окна, логов и подключения бота.
- GUI-тест включает автозапуск с незаполненной Telegram-формой; команда Save не отправляется.
  Ошибка изменения приводит к повторному чтению ОС, параллельные операции не запускаются.
- Единственная новая зависимость — Windows-only winreg 0.56.0. Случайные изменения
  выбора прежних транзитивных зависимостей после cargo fetch отменены; --locked проходит.

Независимое ревью выявило два существенных дефекта Linux, оба исправлены с RED → GREEN:

1. `env --` интерпретировал путь с `=` как присваивание. Теперь фиксированный `/bin/sh -c`
   скрипт `exec "$@"` получает путь и --autostart отдельными аргументами; пользовательский
   путь не входит в код скрипта. Это также обходит проверку GLib до раскрытия `%%` в имени
   executable. Проверка через gio включает пробелы, Unicode, `=`, `%`, кавычки, backslash,
   backticks и `$(touch injected)`; запускается нужный файл, injected не создаётся.
2. Файл с именем регистрации мог быть чужим. Перед изменением требуется валидный
   Desktop Entry с `X-Agent-Hub-Autostart=1` и Type=Application; чужой/повреждённый файл
   сохраняется, ошибка видна. Устаревшую собственную запись можно обновить явно.

Дополнительно при внутренней проверке macOS добавлена проверка существования и права
исполнения бинарника перед Enable/Inspect; Disable работает и после удаления файла.
Проверки удаления и отсутствия execute bit также прошли RED → GREEN.

При итоговом повторном прогоне проявилась старая гонка теста `/doctor`: освобождённый
TCP-порт мог занять параллельный тест. Исправлена только fixture: TcpSocket удерживает
порт без listen до конца проверки отказа соединения. Production-код `/doctor` не менялся;
неустойчивый тест сначала упал в workspace-прогоне, после исправления проверен отдельно
и в полном наборе.

Ограничения: системная политика, разрешения пользователя и compositor могут влиять на
реальный вход/сворачивание. Нативные runtime Windows/macOS и logout/login всех трёх ОС
не выполнялись; перекрёстная компиляция их не заменяет. Реальные Telegram/VPN/модели,
пользовательские Run/LaunchAgents/XDG Autostart не изменялись. Чтение StartupApproved
консервативно: неизвестный формат требует проверки в ОС, приложение его не переписывает.

Согласованное сообщение: `feat: добавить автозапуск приложения при входе`.

## Проверка перед v0.8.0, 2026-11-05

В [CI на macOS](https://github.com/aprazdnikov/agent-hub-rs/actions/runs/41883363188)
нативный тест `native_authorization_bridge_queries_only_a_fixture_path` завершился
ошибкой `Unknown macOS version`: проверка полей `NSOperatingSystemVersion` через JXA
не дала ожидаемую версию. Проверка доступности `SMAppService` через `NSClassFromString`
заменяет разбор структуры версии. Отсутствие класса сохраняет режим legacy; неизвестный
ответ Service Management по-прежнему отклоняется. Основание для проверки nil —
[документация моста JXA](https://developer.apple.com/library/archive/releasenotes/InterapplicationCommunication/RN-JavaScriptForAutomation/Articles/OSX10-10.html).

Семь сценариев на поддельном мосте прошли после исправления (до него пять завершались
ошибкой), как и 21 локальный тест адаптера. Нативный тест оставлен включённым; его
повторный результат перед тегом фиксируется в [журнале выпуска](../releases/README.md).

## Исправление JXA перед v0.9.0, 2026-11-05

Следующий [прогон CI v0.8.0](https://github.com/aprazdnikov/agent-hub-rs/actions/runs/41886623816)
выявил `Invalid Service Management response` в том же нативном тесте.
[Диагностика на macOS 26.6.2](https://github.com/aprazdnikov/agent-hub-rs/actions/runs/42047873316)
подтвердила две причины: `statusForLegacyURL` возвращает строку `"0"`, а четыре
константы `$.SMAppServiceStatus…` имеют значение `undefined`. Прямой вызов через
`$.SMAppService` и `ObjC.unwrap` этого не меняют.

Скрипт вынесен в `macos-authorization.js` и по-прежнему встраивается в бинарник через
`include_str!`. Он сопоставляет только точные числовые или строковые значения 0–3
с состояниями из Apple `SMAppService.h`: not-registered, enabled, requires-approval,
not-found. Приведения произвольного ответа к числу нет; неизвестные значения и ошибки
API отклоняются. Отсутствие класса сохраняет прежний режим legacy. Путь plist остаётся
отдельным аргументом, общий таймаут и ограничения вывода команд не меняются.

`node --test scripts/test-macos-authorization.mjs` исполняет тот же скрипт с заменой
только границы Objective-C: 29 сценариев, включая оба типа четырёх статусов,
отсутствие API, ошибки API и некорректные ответы. До исправления восемь допустимых
ответов падали, после — все 29 сценариев проходят. Проверка добавлена в CI на всех ОС;
нативный Rust-тест остаётся включённым и использует настоящий `/usr/bin/osascript`.

В [финальной проверке](https://github.com/aprazdnikov/agent-hub-rs/actions/runs/42051535340)
прямой запрос на macOS вернул `not-registered` для отсутствующего тестового plist,
нативный Rust-тест и весь workspace прошли на macOS, Windows и Linux. Локально на Linux:
1717 Rust-тестов прошли, 13 пропущены; Clippy, форматирование и релизная сборка прошли.
Диагностика не регистрировала службу, не меняла пользовательские LaunchAgents и не
выполняла logout/login; проверка реального автозапуска при входе остаётся отдельной задачей.
