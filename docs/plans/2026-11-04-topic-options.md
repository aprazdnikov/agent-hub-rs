# AH-08: модель и режим работы для темы

Статус: выполнено и включено в локальный `main` с согласованным сообщением
`feat: добавить выбор модели и режима для тем`.
Предыдущий этап AH-12: `6411709`.

## Цель и решение

Выбирать параметры из Telegram, видеть их источник и не менять текущий ход молча.
Реализация на существующих Rust/Tokio/serde/egui; без новых зависимостей и сетевого
каталога моделей. Граница изменения: профили, состояние темы, запуск, меню и снимки.

- `/model` показывает параметры; `/model <id>` предлагает изменение, `/model inherit`
  снимает переопределение темы. ID ограничен 256 байтами, без пробелов, управляющих
  символов и начального `-`. Фактическую доступность ID проверяет установленный CLI;
  приложение не выдаёт заранее придуманный каталог за доступные модели.
- `/mode` показывает варианты текущего бэкенда и предлагает изменение кнопками;
  `/mode <значение>` и `/mode inherit` также поддерживаются.
- Модель доступна всем пяти бэкендам. Режимы: Claude — существующий PermissionMode;
  Codex — пара Sandbox/Approval (wire `sandbox/approval`); Qwen — QwenApproval.
  Hermes использует фиксированный default, OpenCode — конфигурацию CLI; изменение
  режима для них отклоняется. Ключи, адреса API, CLI, бюджеты и reasoning вне этапа.
- Приоритет по каждому полю: явное значение темы → копия настроек выбранного проекта
  → общие настройки. Копия проекта соответствует текущему контракту `/projects`:
  редактирование/удаление профиля не меняет существующие темы. Повторный выбор проекта
  обновляет копию и снимает переопределения темы, после обычного подтверждения сброса.
- Параметры запуска фиксируются до скачивания вложений и передаются в HubAgents.
  Живой процесс не меняет настройки. `/status`, `/model`, `/mode` и GUI показывают
  параметры текущего запуска; при отличии указывают параметры следующего запуска.
  Значение «выбор CLI» не объявляется фактически выбранной моделью.
- Изменять можно только свободную тему, вне сохранения/восстановления снимка. Всегда
  показаны новые параметры и кнопки подтверждения/отмены. Обычный выбор сохраняет
  историю; для Qwen текущий адаптер задаёт параметры через аргументы процесса, поэтому
  перед изменением значений требуется явно подтвердить новую сессию. Смена только
  источника при одинаковых значениях сохраняет историю. Пользователь подтвердил:
  «Сохранять историю, когда возможно».
- Ограничение Qwen касается явных изменений темы; унаследованные общие настройки
  сохраняют существующее поведение запуска. При загрузке Qwen-сессии показаны
  запрошенные параметры с примечанием: сессия может сохранить свои модель/режим.
  Отсутствие model не считается доказательством сброса модели сохранённой сессии.
- Старые кнопки, чужая группа/пользователь, изменение сессии/настроек и новый запуск
  отвергают подтверждение. Токены одноразовые, TTL 15 минут, не более 256. Отправка меню
  ограничена четырьмя задачами, одной на тему, с тайм-аутом и отменой при остановке.
- Сначала атомарная запись темы, затем обновление памяти. Ошибка диска сохраняет
  прежнюю привязку. `/reset` сохраняет настройки; `/new`, смена бэкенда и каталога
  начинают новую конфигурацию. `/save` и `/restore` сохраняют настройки вместе со снимком.
- `topics.json` и manifest читают v1/v2; v2 записывается только при наличии настроек.
  Старые данные без них остаются в v1. Предыдущая версия отказывается читать v2,
  защищая новые параметры от незаметной потери. Откат: копия, удалить `preferences`,
  установить version=1; для settings.toml удалить новые поля options у проектов.

## План реализации

### 1. Чистая модель параметров и приоритет

Создать `crates/hub-core/src/options.rs`, экспортировать из `lib.rs`; использовать
существующие enums в `settings.rs` без расширения протоколов бэкендов.
Типы: `OptionsDraft { model, mode }`, проверенный `Options`, `Mode`, `Preferences`
(переопределения и копия проекта), `Effective` (значения и источник каждого поля).
`Options::parse(backend, draft)`, `Preferences::resolve(backend, settings)` и
`Effective::apply(&mut Settings)`; не смешивать проверку ID с проверкой каталога модели.

RED: приоритет каждого поля, наследование, неподдерживаемый режим, неправильный ID,
все комбинации Codex, отсутствие секретов в представлении. Команда:
`cargo test -p hub-core --lib --locked options` — FAIL до реализации, PASS после.

### 2. Профили, привязки и снимки

Изменить `domain.rs`, `projects.rs`, `topics.rs`, `snapshot.rs`,
`crates/hub-telegram/src/transfer.rs`, конструкторы/fixtures по ошибкам компилятора.
TopicSession получает `preferences`; ProjectDraft — optional/default `options`.
На границе JSON/TOML использовать draft и проверять режим относительно backend.
Сохранять параметры снимка в его manifest и восстанавливать их вместе с привязкой.

RED: v1 сохраняет старую форму, v2 round-trip сохраняет оба слоя, неверный backend/mode
и future version отклоняются, проект копируется и не меняется вслед за профилем,
снимок восстанавливает параметры. Команды: `cargo test -p hub-core --lib --locked`,
`cargo test -p hub-telegram --lib --locked transfer`, затем `cargo check --workspace --tests --locked`.

### 3. Фиксация параметров при запуске

Изменить `hub.rs`, `session.rs`, `agents.rs`: передать снимок Settings через Agents::run;
наложить проверенные параметры до Run. Live/TopicView содержат текущие параметры,
публикация реагирует на обновления настроек. Изменить fake implementations вместе
с интерфейсом. Протоколы CLI остаются прежними.

RED: тема/проект/глобальные настройки дают разные реальные параметры запуска; изменения
общих настроек во время работы не меняют активный снимок. Проверить фактические CLI args/
RPC params существующими fake-протоколами всех бэкендов. Команды:
`cargo test -p hub-telegram --lib --locked`, тесты CLI/RPC в затронутых crates.

### 4. Telegram и GUI

Создать `crates/hub-telegram/src/options.rs`; изменить commands/lib/hub/projects/texts,
`crates/hub-app/src/gui/settings.rs` и `gui/topics.rs`. Меню возвращает подтверждение;
Hub проверяет занятость, актуальность, сохраняет новые настройки атомарно. Неизвестные
и неподдерживаемые значения дают объяснение, не запускают модель. Профиль показывает
model/mode и их будущий эффект перед выбором. GUI сохраняет параметры проекта и
показывает параметры темы без нарушения существующей таблицы.

RED: просмотр не создаёт сессию; отмена/no-op/busy/disk error ничего не меняют;
подтверждение сохраняет контекст, Qwen сбрасывает только после отдельного согласия;
старые/повторные/неавторизованные кнопки не применяются; ограничения задач и shutdown.
Команды: `cargo test -p hub-telegram -p hub-app --lib --locked`.
