# AH-09: подробные состояния задач

Статус: выполнено и включено в локальный `main` с согласованным сообщением
`feat: добавить подробные состояния задач`. Предыдущий этап AH-08: `7c0f794`.

Цель: GUI и `/status` показывают состояние текущего или последнего запуска, его
длительность и последнюю известную активность. Основание: AH-09 в
[журнале задач](2026-11-04-usability-backlog.md); пользователь поручил реализацию.
Исполнение: последовательно в текущем рабочем дереве, отдельное итоговое ревью.
Rust/Tokio/egui, без новых зависимостей и изменения файлов настроек.

## Решения и границы

- Состояния: нет данных, подготовка, выполнение, ожидание разрешения, ожидание ответа,
  фоновые задачи, завершение, остановка, завершено, остановлено, ошибка. Состояние
  «завершено» требует события результата; выход без него не выдаётся за успех.
- Занятость темы остаётся отдельным признаком: запрос разрешения, фон и завершение
  процесса также заняты. Stop/Reset и общий счётчик не зависят от текста состояния.
- Ожидание пользователя начинается после отправки карточки; заканчивается при ответе,
  тайм-ауте, отказе доставки или отмене future, до редактирования сообщения Telegram.
  Счётчики учитывают несколько запросов одновременно; разрешение имеет приоритет над
  вопросом, оба числа доступны в подробностях. Drop-guard снимает только свой запрос.
- Время монотонное (`std::time::Instant`), длительность фиксируется при окончании запуска.
  Последняя активность — типизированная метка, без текста ответа, команд и секретов.
- Состояния хранятся в памяти по одному на тему. После перезапуска — «нет данных»;
  снимки не переносят состояние процесса. Новый запуск заменяет старое состояние;
  сброс/смена контекста очищают его. Переименование и смена параметров с сохранением
  контекста оставляют последний результат.
- Каждый запуск имеет собственный watch-снимок прогресса; старые отправители не могут
  менять новый. Ended и сообщения привязки из Run проверяют generation. Прямые
  административные Bind сохраняют прежнюю возможность привязки без запущенного процесса.
- watch объединяет частые события без дополнительной очереди. Hub публикует изменения
  с интервалом 250 мс при активных запусках; `/status` читает текущий снимок сразу. GUI
  обновляет длительности раз в секунду. Никаких дополнительных сообщений в Telegram.
- Для Claude добавляется типизированное событие изменения числа фоновых задач из
  существующего Activity tracker, включая ноль после завершения. Не угадывать фон по
  тексту. Все пять бэкендов сообщают TurnStarted при отправке каждого нового хода,
  включая очередь в одном процессе; Claude также сообщает начало injected report turn.
- AH-10 (обновляемая карточка прогресса), история запусков на диске и новые протоколы
  CLI вне этапа. Один коммит после проверки и согласования точного сообщения.

## Review focus

1. Параллельные вопросы/разрешения закрываются в произвольном порядке.
2. Ответ и тайм-аут снимают ожидание до зависшего редактирования сообщения.
3. Stop, паника, ошибка скачивания и отсутствие Finished не оставляют ложный успех.
4. Поздние события/Ended/Bind старого поколения не меняют новую задачу.
5. Фон может закончиться без ещё одного Finished; после изменения контекста не должно
   остаться результата прежнего запуска. Подготовка и ожидания остаются занятыми в GUI.

## Журнал решений

- Утверждённая задача определяет состояния и гарантии; сроки хранения, watch-канал,
  интервал публикации и отдельный признак занятости — решения реализации.
- Новая модель изолирована от persistence и outbox: состояние доставки ответа не
  подменяет результат выполнения; недоставленные результаты по-прежнему видны в `/outbox`.

- Проверка плана: добавлен TurnStarted для следующих ходов всех бэкендов; Reporter
  меняет снимок атомарно через send_modify, без borrow+replace; очистка последнего
  состояния охватывает put, restore с прежними владельцами, выбор проекта и Qwen reset.
- Проверки модели и ожиданий прошли; интеграционные проверки Hub: фон/следующий ход,
  stop при разрешении, ошибки подготовки/паника, старое поколение, переименование,
  перезапуск и ошибка сохранения проекта — PASS.
