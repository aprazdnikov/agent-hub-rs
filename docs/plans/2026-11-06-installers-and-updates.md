# Установщики и безопасное обновление

Статус: реализация подготовлена и проверена локально; Windows/macOS и CI остаются
непроверенными. Основание: [исследование релиза](2026-11-06-release-readiness.md).

## Решение

Дополнить существующие архивы Windows x64 и Linux x64 установщиками для текущего
пользователя и Debian/Ubuntu соответственно. Сохранить имена и содержимое прежних
артефактов, используемых переносными установками и updater. Не менять и не удалять
пользовательские данные при удалении пакета.

Встроенная самозамена пригодна только для переносной копии. Для .deb, NSIS и
macOS `.app` предлагать перейти на страницу релизов с инструкцией, а не заменять
отдельный бинарник; установленный бандл может быть подписан целиком. Ошибки и
неизвестные признаки установки не должны приводить к ложному успешному обновлению.

Маркер NSIS `agent-hub.install-kind` рядом с исполняемым файлом содержит `nsis`.
Для .deb маркер `/usr/share/agent-hub/install-kind` содержит `deb` и применяется
только к системному бинарнику пакета. Маркер не является доказательством подлинности.
Определение macOS-бандла использует расположение бинарника внутри `.app/Contents/MacOS`.
Не использовать общий системный маркер для блокировки обновления произвольной
переносной копии из другого каталога. Подпись и нотарификация не включаются без
сертификатов и отдельной проверки их работы.

## Результаты

- Linux: `cargo test --workspace --locked` — 1794 прошли, 13 пропущены; Clippy,
  `cargo fmt --all -- --check`, `git diff --check` и локальная сборка — PASS.
- Свежая release-сборка и `scripts/test-deb-package.sh` — PASS: содержимое,
  права, архитектура, зависимости и отклонение некорректного ввода проверены без
  установки. `dpkg-shlibdeps` выдал предупреждения о локальных libc diversions.
- В одноразовом контейнере `ubuntu:26.04` пакет с локально собранным бинарником
  установлен через `apt`, повторно установлен и удалён через `dpkg -r`; зависимости
  разрешились, `ldd` не показал отсутствующих библиотек, тестовый файл в каталоге
  пользователя сохранился. Окно в этом сценарии не запускалось. Проверка не заменяет
  установку артефакта GitHub Actions или проверку других версий Ubuntu/Debian.
- В отдельном контейнере Ubuntu 26.04 установлен тот же локальный пакет и запущен
  через Xvfb в изолированном D-Bus; процесс оставался активным, снимок экрана показал
  вкладку настроек первого запуска. Кнопки и работу с ботом в этом сценарии не
  проверяли; Xvfb не заменяет проверку реального Wayland/X11 рабочего стола.
- В чистом контейнере Ubuntu 22.04 приложение собрано в release-режиме, пакет
  проверен и затем в другом таком контейнере установлен, переустановлен и удалён;
  зависимости разрешились и тестовый пользовательский файл сохранился. Окно также
  запущено под отдельным пользователем через Xvfb. Это не тест опубликованного CI
  артефакта или физического дисплея.
- В отдельном чистом Ubuntu 22.04 проверено обновление пакета с версии 0.9.0 на
  тестовую 0.9.1 и удаление: тестовый файл пользователя сохранился. Оба пакета
  содержали один и тот же бинарник; проверка устанавливает поведение пакетного
  менеджера, но не совместимость данных между разными выпусками программы.
- Минимальный образ Ubuntu 22.04 выявил неявную зависимость упаковочного теста от
  команды `file`. Проверка заголовка PNG переведена на уже требующийся Python 3;
  повторные release-сборка и проверка пакета в том же образе прошли без `file`.
- NSIS 3.10 с временным локальным toolchain: сборка и self-test PE-входа — PASS.
  Windows smoke test добавлен в CI, но Windows runner не запускался. Он собирает
  отдельный тестовый установщик с изолированными путями/разделом реестра, а не
  проверяет точный публикуемый экземпляр. Поведение установки и удаления на Windows
  пока не подтверждено.
- После дополнительного ревью Windows-установщик использует эксклюзивный файл в
  профиле пользователя для сериализации операций, сообщает об ошибках удаления и
  проверяет признаки восстановления в записи HKCU. При прерывании подготовки
  `uninstall-recovery.exe.staged` или обновления до фиксации результата нужны ручная
  проверка и восстановление: неоднозначные файлы не удаляются автоматически.
- YAML workflow разобран локально; GitHub Actions не запускался и релиз не публиковался.
  Подпись, нотарификация, macOS-запуск и нативные проверки символьных ссылок в
  Windows/macOS остаются открытыми. Контрольные суммы не заменяют подпись издателя.
