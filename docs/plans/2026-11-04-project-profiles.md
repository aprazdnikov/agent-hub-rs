## Решение и границы

Цель: выбрать именованный проект в теме Telegram без ввода пути и бэкенда.
Rust, egui, teloxide; существующие настройки и проверка каталогов. Схема `topics.json`
не меняется. Профиль хранится в `settings.toml`: стабильный ID, название, каталог,
бэкенд и ID связанных пользовательских действий (например, VPN). Связь — подсказка;
действия запускаются пользователем через `/actions`, автоматического запуска нет.

До 32 профилей. GUI создаёт UUID, редактирование его сохраняет. Названия уникальны,
1–80 символов; каталог обязателен, допускается путь относительно workspace или `~/…`.
При сохранении и при выборе проверяются существование, директория и канонические
границы workspace с разрешением симлинков. Старые настройки дают пустой список;
для возврата к прежней версии нужно удалить `[[projects]]` из настроек.
Редактирование профиля не меняет ранее созданные сессии. Новые пользовательские действия
тоже получают UUID: удалённый ID не переиспользуется и не подменяет связь проекта.
Проверки существования каталогов выполняются при сохранении в Supervisor/FileSettings,
а не на каждом кадре GUI; повторная проверка выбора остаётся в Telegram-контроллере.

`/projects` работает только в теме. Последние пять выбранных проектов показаны первыми,
остальные — в порядке настроек. Кнопка сначала показывает имя/путь/бэкенд и связанные
действия; «Выбрать и сбросить контекст» явно подтверждает новую привязку, «Отмена»
сохраняет её. Выбор никогда не запускает модель. Занятую тему или тему со снимком
переназначить нельзя. `/new`, `/cwd`, `/backend` сохраняют прежнее поведение.

Кнопки одноразовые, TTL 15 минут, не более 256 токенов. Токен содержит серверный снимок
профиля, ключ темы, исходную привязку и корень workspace. На нажатии повторно проверяются
allowlist, чат, актуальность профиля/корня/привязки и занятость. Подтверждения одной темы
сбрасываются при изменении её привязки, восстановлении снимка и начале нового хода; повтор/старое меню не сбрасывают новую сессию.
Пути повторно канонизируются на подтверждении и сравниваются с показанным пользователю.

Новая привязка сначала сохраняется на диск; при отказе исходная остаётся. История пяти
последних ID — отдельный необязательный `topics.projects.json`, атомарная запись,
ошибки видны. Повреждённый файл сохраняется и останавливает запуск с указанием пути.
Удалённые из настроек ID игнорируются в меню. История не меняет привязки.

## Результат проверки

На Linux все общие команды прошли: 1386 тестов passed, 12 live-тестов ignored;
форматирование, Clippy, cargo-deny и сборка — OK. В Cargo.lock добавлена только связь
`hub-app → uuid`, версии пакетов не менялись.

Проверены чтение старых настроек и round-trip профилей, отсутствующие ссылки на действия,
удалённые каталоги/симлинки, создание/удаление профилей и выбор действия через egui,
подтверждение/отмена выбора, занятость, allowlist, одноразовость/TTL/предел кнопок,
сохранение перед применением, ошибки записи привязки/истории и история после перезапуска.

Независимое ревью выявило два дефекта; оба воспроизведены падающими тестами и исправлены:

- Старое подтверждение после восстановления той же сессии: rebind инвалидирует кнопки
  целевой темы и прежних владельцев после успешной записи.
- Слишком длинная карточка: текст отправляется частями, кнопки — в последней;
  если предыдущая часть не доставлена, подтверждение не отправляется.

Повторное ревью: блокеров нет, независимый запуск 13 проектных тестов — PASS.
Для соблюдения лимита Clippy разбор CodexDraft вынесен в метод без изменения поведения;
существующие проверки настроек прошли.

Ограничения: настоящие Telegram/VPN/модели не запускались; Windows/macOS runtime не
проверен. Выбор проекта не включает VPN и не проверяет доступность ресурсов — это AH-07.
Коммит отдельный, после согласования точного сообщения, без служебных подписей и без push.
