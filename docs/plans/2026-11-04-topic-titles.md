# AH-13: сохранение и обновление названий тем

Статус: выполнено и проверено, сообщение коммита ожидает согласования.
Предыдущий этап: ACT-01/DEP-01, коммит `ec5037d`.

## Решение

Метаданные хранятся отдельно в `topics.titles.json` рядом с `topics.json`.
Формат привязок сессий не меняется: сохранена совместимость с прежними версиями и
Python-версией. Отсутствующий файл метаданных означает отсутствие известных названий.
При повреждённом файле старт явно завершается ошибкой с путём; исходный файл сохраняется,
как и при повреждении существующего `topics.json`.

Создание темы сохраняет название. `forum_topic_edited` с полем `name` обновляет его;
изменение одной иконки не стирает название. Переименование не создаёт ход и не меняет
привязку сессии. Если тема ещё не привязана, имя сохраняется до её первого сообщения.
После перезапуска известные названия поступают в GUI и снимки сессий. Для неизвестных
названий остаётся существующий `#id`; исторические названия без события не восстанавливаются.

Запись метаданных атомарная. При ошибке сохранения новое имя остаётся в памяти, а бот
сообщает, что оно не сохранено; последующие обновления позволяют повторить запись.
Файл названий и файл сессий записываются независимо: название не является частью сессии.

## Шаги и критерии

- [x] Формат названий в `crates/hub-core/src/topics.rs`: версия, ключ chat/thread,
  имя; round-trip, старый файл сессий без изменений, повреждённые данные.
- [x] Загрузка и атомарная запись в `crates/hub-app/src/topics.rs`; отсутствующий,
  повреждённый файл и реальный цикл сохранение → загрузка.
- [x] Передача начальных названий через `HubSetup` в `connector.rs` и `hub.rs`;
  создание/переименование сохраняет данные через `TopicStore`.
- [x] Событие переименования в `inbound.rs` и `telegram.rs`; тесты переименования,
  изменения только иконки и игнорирования события как пользовательского prompt.
- [x] Тесты hub: восстановление названий после перезапуска, переименование во время
  работы без сброса сессии, имя до первого сообщения, ошибка записи и повтор.
- [x] README, журнал выполнения, ревью и итоговые проверки.

## Проверки

Тест распознавания переименования сначала падал на `Content::Ignored`, затем прошёл
после реализации. Проверены цикл создание → переименование → перезапуск,
переименование во время хода, имя до привязки, ошибка записи и повторная попытка,
новое название в снимке сессии, чтение старого состояния без файла названий.

```bash
cargo test -p hub-core -p hub-app -p hub-telegram --lib --locked
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo deny check
cargo build -p hub-app --locked
```

Результат на Linux: все команды прошли. Полный набор: 1336 тестов прошли,
12 live-тестов оставлены ignored. После усиления сценария перезапуска повторно
прошли 145 тестов `hub-telegram`, форматирование, Clippy и сборка приложения.
Независимое ревью не выявило блокеров. Проверки не обращались к настоящим
Telegram/VPN/моделям; ручная проверка Telegram и запуск на Windows/macOS не выполнялись.

Исторические названия, события о которых бот не получил, остаются неизвестными.
Прежние версии читают привязки, но не поддерживают актуальность файла названий.
При повреждении файла нужен разбор ошибки пользователем, автоматического сброса нет.
Коммит создаётся отдельно после согласования сообщения с пользователем.
