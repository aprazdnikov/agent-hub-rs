# Автоматическая регистрация slash-команд

## Цель и контракт

Отдельный коммит в `feat/hermes-backend`: при подключении бота исходники хаба полностью заменяют меню команд настроенной группы. Списки Telegram/BotFather не объединяются с исходниками. Запись проверяется через `getMyCommands`; ошибка меню не блокирует запуск бота. Права доступа не меняются.

Реестр `hub-core::commands::Command` содержит канонические имена, описания и аргументы. Парсер, Telegram-меню и `/help` используют его; `/start` остаётся алиасом `/help`, без отдельной записи в меню.

Управляемые цели: группа, её администраторы, разрешённые пользователи из текущего allowlist; для каждой — общий язык, `ru`, `en`. Все цели получают полный одинаковый список через `setMyCommands`, затем читаются обратно с теми же scope/language. Предварительное удаление не требуется: замена целиком не создаёт промежуточного пустого меню. Другие группы и глобальные scopes не меняются. Произвольные ранее созданные языковые и пользовательские scopes нельзя перечислить через Bot API; они вне управляемого набора.

## Реализация и проверки

1. `crates/hub-core/src/commands.rs`: канонический реестр и метаданные; тесты уникальности, Bot API-ограничений и разбора всех имён/алиаса.
2. `crates/hub-telegram/src/texts.rs`: справка из реестра, сохранить текущие аргументы и тексты; тест полноты.
3. `crates/hub-telegram/src/menu.rs`, `src/lib.rs`, `src/telegram.rs`: операция полной замены/проверки с общим ограничением 30 с, безопасные структурные ошибки без токена/API URL. Мягкий вызов в `hub-app/src/connector.rs` до polling.
4. Детерминированные loopback Bot API-тесты в `crates/hub-telegram/tests/`: старые/лишние команды исчезают, повторная регистрация идемпотентна, точные scopes/languages, mismatch, отказ записи и тайм-аут. RED на no-op регистрации, затем GREEN с настоящими HTTP-вызовами SDK.
5. README и `docs/superpowers/spec/2026-10-09-telegram-command-menu-design.md`: область владения, замена с нуля, ошибки, ограничения локализации.

Gates: `cargo fmt --all --check`, `cargo test --workspace --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo build -p hub-app --locked`, `git diff --check`.

После gates — отдельный commit, push в fork, readback SHA. Реальное меню можно синхронизировать и прочитать обратно без запросов к модели. Перезапуск работающего хаба не нужен для одноразовой синхронизации и не выполняется без необходимости.
