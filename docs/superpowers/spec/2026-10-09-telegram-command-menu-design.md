# Автоматическое меню команд Telegram

## Контракт

Исходники хаба — авторитетный список slash-команд. Каждое подключение бота заново записывает полный список; существующее меню Telegram/BotFather не участвует в построении payload. Команда, удалённая из реестра, исчезает из управляемых меню после успешной синхронизации.

Меню не даёт права выполнять команды: фильтрация настроенной группы, темы и allowlist остаётся в существующем обработчике обновлений. Внутренние команды агентов в меню хаба не попадают.

План: [telegram-command-menu](../plans/2026-10-09-telegram-command-menu.md).

## Источник и подключение

- `hub-core::commands::Command::ALL`, `name`, `description`, `arguments`: порядок, канонические имена, русские описания и шаблоны справки. Метаданные исчерпывающе сопоставлены enum; список используется парсером, `/help` и регистрацией. `/start` остаётся алиасом `/help`, вне меню.
- `hub-telegram::menu`: транспорт полной замены и проверки; публичный вход `telegram::synchronize_commands(&Bot, &TelegramSettings)` для startup и одноразового обслуживания.
- `hub-app::connector`: после подключения, до hub/polling вызывает синхронизацию. Неуспех логируется предупреждением, соединение остаётся рабочим.

## Замена и область владения

Управляемые scopes: `Chat` настроенной группы, `ChatAdministrators` той же группы, `ChatMember` для каждого пользователя текущего allowlist. Для каждого scope записываются языки `""`, `ru`, `en`; описания во всех трёх случаях русские. Узкие меню не могут перекрыть общий актуальный список устаревшими командами в этих управляемых целях.

Для каждой пары scope/language:

1. `setMyCommands` получает весь список из реестра с явно заданными scope/language.
2. `getMyCommands` получает те же scope/language.
3. Полный ответ сравнивается с реестром, включая порядок и описания.

`setMyCommands` заменяет список, поэтому предварительное удаление не нужно и не создаётся промежуточное пустое меню. Синхронизация идемпотентна. Несколько scopes не являются одной транзакцией: ошибка может оставить часть целей уже обновлённой; повторное подключение повторяет полную запись.

Общий бюджет синхронизации — 30 с, включая все записи/readback. В ошибках `MenuError` остаются только операция/тайм-аут/mismatch: исходный `RequestError` не логируется, поскольку может содержать URL с токеном. Ошибка readback не считается успехом.

## Границы

Глобальные scopes, другие группы, пользователи вне текущего allowlist и произвольные иные языковые scopes не изменяются. Bot API не предоставляет перечня всех ранее созданных scopes/languages: обещание очистить любые неизвестные overrides было бы недостоверным. Бот должен быть администратором группы, как уже требуется настройкой хаба.

При недоступности Telegram, недостатке прав, отсутствии разрешённого пользователя в группе или большой очереди целей возможна частичная синхронизация; это warning, а не отказ запуска. Существующее меню до успешной записи сохраняется. Синхронизация не запускает модель, не меняет credentials или настройки профилей агентов.

## Проверки

Core-тест проверяет уникальность, Bot API-ограничения имён/описаний и разбор каждого канонического имени. Справка проверяется на полноту и сохранение аргументов.

Loopback Bot API-тесты используют настоящий SDK: полная замена предварительно заполненных старых списков, точные scopes/languages, неизменность чужого глобального меню, идемпотентность, отказ/false записи, отказ readback, mismatch и общий тайм-аут. Платные live-тесты агентов в эту функцию не входят.
