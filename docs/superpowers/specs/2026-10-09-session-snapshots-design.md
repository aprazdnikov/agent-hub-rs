# Снимки сессий

## Цель

Одной командой сохранить всё о сессии темы — данные хаба и историю самого агента — в каталог снимков, посмотреть список снимков и развернуть снимок в новой теме, продолжив работу. Работает для всех бэкендов: Claude, Codex, Qwen, Hermes. Выходит в релизе 0.5.0.

## Решения

| Вопрос | Решение |
|---|---|
| Что в снимке | Бэкенд, рабочий каталог, id сессии, название темы, дата, версия агента и копия файлов истории агента. Файлы проекта не сохраняются |
| Семантика восстановления | Перенос: одна сессия — одна тема. Если другая тема ещё привязана к этой сессии, она сбрасывается (как `/reset`) и получает уведомление |
| Как восстанавливать | Пользователь сам создаёт тему и пишет в ней `/restore <имя>`; бот темы не создаёт |
| Формат | Каталог на снимок: `manifest.json` + `agent/`; без архивов и отправки в Telegram |
| Где хранить | `[snapshots] dir` в настройках, по умолчанию `~/.agent-hub`; снимки — в `<dir>/snapshots/<имя>/` |
| Данные агента при восстановлении | Не перезаписываются: если сессия у агента есть — только перепривязка; файлы из снимка возвращаются, только если сессии у агента нет |
| Hermes | Полный перенос строк `state.db` через Python-API самого Hermes |
| Во время хода | `/save` и `/restore` отказывают; пока снимок пишется или возвращается, в теме не стартует ход и отказывают `/new`, `/cwd`, `/reset`, `/backend` |

## Команды

| Команда | Поведение |
|---|---|
| `/save [имя]` | Снимок сессии темы. Имя по умолчанию — `<название темы>-ГГГГММДД-ЧЧММ` (местное время), транслитерированное и приведённое к `[a-z0-9._-]`, не длиннее 64 символов; название темы хаб знает только из `forum_topic_created` текущего запуска — без него вместо названия имя бэкенда (`claude-20261009-1530`). Занятое имя — отказ. Нет сессии — «Нечего сохранять: в теме ещё нет сессии». Успех — «💾 Сохранено: <имя> · <бэкенд> · <каталог>» |
| `/saves` | Не больше 30 снимков, новые сверху: имя, бэкенд, каталог, дата, исходное название темы. Пусто — «Снимков пока нет» |
| `/restore <имя> [каталог]` | Привязывает тему к сессии из снимка. Каталог — из снимка или указанный (разрешается как у `/new`, должен существовать и быть внутри `workspace_root`). Старой теме — «Сессия перенесена в другую тему». Успех — «♻️ Восстановлено: <имя> · <бэкенд> · <каталог>» |

Все три — только внутри темы. Во время хода — «Дождитесь конца хода или /stop». Если к концу `/restore` тема-владелец сессии выполняет ход, привязки не меняются (сессия занята в другой теме); уже возвращённые агенту файлы остаются, повтор `/restore` только перепривяжет. Команды попадают в `/help` и меню бота через `Command::ALL`.

## Снимок на диске

```
<dir>/snapshots/<имя>/
  manifest.json
  agent/…
```

`manifest.json`:

```json
{
  "version": 1,
  "name": "fix-tests-20261009-1530",
  "created_at": "2026-10-09T15:30:12Z",
  "title": "Починить тесты",          // null, если название неизвестно
  "backend": "claude",
  "cwd": "/home/me/Projects/shop",
  "session_id": "…",
  "agent_version": "2.1.292",
  "backend_data": {"kind": "claude", "project": "-home-me-Projects-shop"},
  "files": ["projects/-home-me-Projects-shop/<id>.jsonl", "…"]
}
```

- `backend_data` — по варианту на бэкенд: Claude `{project}`, Codex `{}`, Qwen `{}`, Hermes `{profile: Option<String>}` (информационно: возврат идёт в текущий профиль из настроек). `backend` выводится из `backend_data.kind`, несовпадение — ошибка разбора.
- `created_at` — UTC; `files` — не больше 10 000.
- `files` — относительные пути внутри `agent/`, без `..` и абсолютных путей.
- Запись атомарна: `snapshots/.tmp-<uuid>/` → `rename` в `snapshots/<имя>/`. Ошибка — временный каталог удаляется.
- Права (Unix): `snapshots/` и каталоги снимков `0700`, файлы `0600`.

## Бэкенды

Корень хранилища агента вычисляет отдельная функция (окружение ∨ значение по умолчанию) и передаёт в `SessionArchive` явно. Копируется только перечисленное (белый список), символьные ссылки пропускаются.

| Бэкенд | Выгрузка в `agent/` | `present` | Возврат |
|---|---|---|---|
| Claude (`$CLAUDE_CONFIG_DIR` ∨ `~/.claude`) | `projects/<P>/<id>.jsonl` и `projects/<P>/<id>/` (субагенты, tool-results). `<P>` — поиском `projects/*/<id>.jsonl` (кодирование длинных путей включает хэш, хаб его не вычисляет); записывается в манифест. `file-history/` не берётся | ровно один `projects/*/<id>.jsonl` | В `projects/<P из манифеста>/`. Claude ≥ 2.1.223 ищет id по всем проектам, поэтому новый `cwd` не мешает. Больше одной копии — отказ |
| Codex (`$CODEX_HOME` ∨ `~/.codex`) | все `sessions/**/rollout-*-<id>*.jsonl[.zst]`; базы SQLite не трогаются | файл в `sessions/`; только в `archived_sessions/` — ошибка «Сессия в архиве Codex: выполните `codex unarchive <id>`» | В `sessions/ГГГГ/ММ/ДД/` по дате из имени файла, имя прежнее. Codex находит файл по id и сам создаёт запись в базе |
| Qwen (`$QWEN_RUNTIME_DIR` ∨ `$QWEN_HOME` ∨ `~/.qwen`; относительные значения — отказ) | `projects/<san(cwd)>/chats/<id>.jsonl` и спутники `<id>.*`, кроме `.runtime.json` и `.worktree.json`; `projects/<san(cwd)>/subagents/<id>/`; `todos/<id>.json` | файл в `projects/<san(cwd назначения)>/chats/` | Тот же `cwd` — как есть. Другой — поле `cwd` верхнего уровня переписывается во всех записях JSONL чата и субагентов, файлы кладутся под `san(новый cwd)`. `san`: каждая кодовая единица UTF-16 вне `[A-Za-z0-9]` → `-`; на Windows сначала нижний регистр. Настройка Qwen `advanced.runtimeOutputDir` не поддерживается |
| Hermes (каталог выбирает сам Hermes: `HERMES_HOME`, `--profile`, «липкий» `active_profile`) | `hermes-session.json` — `SessionDB.export_session_lineage(id, include_inactive=True)`: словарь со списком `segments` (линия сжатия) | `get_session(id)` в `state.db` профиля | `SessionDB.import_sessions([сегменты])`, в каждом сегменте подставлены `cwd` и `model_config.cwd`. Лимиты Hermes: ≤ 10 000 сообщений и ≤ 5 МиБ на сессию, ≤ 25 МиБ всего |

### Hermes

- Встроенный в хаб Python-скрипт с подкомандами `present`, `export`, `import`; аргументы — списком, без оболочки; данные — через файлы.
- Запускается окружением самого Hermes (голый интерпретатор не видит его зависимостей):
  - текущие установщики (POSIX-обёртка `hermes`, `hermes.exe`/`hermes.cmd`) — `hermes --run-module cProfile -o <tmp>/profile.out <скрипт> <op> …`; `cProfile` проглатывает код выхода, поэтому результат возвращается только файлом `--result`;
  - классический консольный скрипт pip/uv (shebang с абсолютным путём к `python*`) или `python.exe` рядом с `hermes.exe` — `<python> -I <скрипт> <op> …`.
- Каталог данных скрипт выбирает функциями самого Hermes (как `hermes [--profile P] acp`); хаб передаёт только `--profile` из настроек.
- Скрипт сверяет версию схемы — константу кода и `schema_version` в `state.db` — с проверенной (31); иначе — «Hermes <версия> не поддерживается для переноса».
- Это внутренний API Hermes: поддерживаемые версии ограничены проверенной, есть живой тест.

## Архитектура

### `hub-core`

- `SnapshotName` — newtype, `parse` проверяет `[a-z0-9._-]{1,64}`, не начинается и не заканчивается точкой, основа до первой точки — не имя устройства Windows (`con`, `prn`, `aux`, `nul`, `com1`…`com9`, `lpt1`…`lpt9`).
- `default_name(title, now) -> SnapshotName` — транслитерация кириллицы, обрезка, суффикс времени.
- `Manifest { version, name, created_at, title, backend, cwd, session_id, agent_version, backend_data: BackendData, files: Vec<RelPath> }`; `RelPath` — newtype без `..` и абсолютных путей; `BackendData` — enum по бэкенду.
- `Command::{Save, Saves, Restore}`, разбор аргументов, тексты.

### `hub-agent`

- Трейт `SessionArchive`:
  - `export(&self, session: &SessionId, cwd: &AbsolutePath, dest: &Path) -> Result<Exported, ArchiveError>` — `Exported { files, backend_data, agent_version }`;
  - `present(&self, session, cwd, data: &BackendData) -> Result<bool, ArchiveError>`;
  - `import(&self, session, data, files, src: &Path, cwd) -> Result<(), ArchiveError>`.
- `ArchiveError` (`thiserror`): `NotFound`, `Ambiguous`, `Archived`, `Unsupported(String)`, `Io(io::Error)`, `Malformed(String)`.
- Помощник копирования по белому списку: только обычные файлы, без симлинков, с правами `0600`.

### `hub-claude`, `hub-codex`, `hub-qwen`, `hub-hermes`

По реализации `SessionArchive` по таблице выше; функция корня хранилища — отдельно.

### `hub-app`

- Настройка `[snapshots] dir` (необязательная, `~` разрешена); `Settings.snapshots_dir: PathBuf` с умолчанием `~/.agent-hub`; поле «Каталог снимков» с выбором папки в GUI.

### `hub-telegram`

- Модуль `snapshots`: `SnapshotStore { root }` — `save(name, fill)` (сам создаёт staging-каталог, отдаёт `agent/` замыканию, пишет `manifest.json`, переименовывает, убирает мусор при любой ошибке), `list() -> Vec<Manifest>` (повреждённые пропускаются с `warn`), `load(name)`. Живёт здесь, а не в `hub-app`: его вызывает `Hub`, а `hub-app` зависит от `hub-telegram`; корень читается из `Settings` на каждую операцию.
- `Hub` обрабатывает три команды.
- `/save`: отказ во время хода → `SessionArchive::export` во временный каталог хранилища → манифест → атомарное переименование.
- `/restore`: отказ во время хода → чтение и проверка манифеста → проверка каталога → `present` → `import`, если сессии нет → **только затем** перепривязка тем (снятие с прежней темы и привязка к текущей — одна операция над `Topics`, затем `put()`) → уведомление прежней теме без гарантии доставки.
- Ошибка импорта — темы не меняются.

## Безопасность

- В снимок не попадают файлы авторизации (`.credentials.json`, `~/.claude.json`, `auth.json`, `oauth_creds.json`, `mcp-oauth-tokens.json`, `.env`, `settings.json`) и базы целиком — по белому списку.
- Истории — открытый текст (вывод команд, содержимое файлов): права `0700`/`0600`, в логи только имена и размеры.
- Имя снимка и пути в манифесте проверяются: выхода за пределы каталога нет.
- Каталог восстановления — внутри `workspace_root`.

## Тесты

- `hub-core`: имя по умолчанию и транслитерация, таблица проверки имени, `RelPath`, манифест туда-обратно и неизвестная версия, разбор команд.
- Бэкенды — на временных «домашних» каталогах: экспорт, `present`, возврат; Qwen — переписывание `cwd`; Claude — две копии → `Ambiguous`; Codex — архивная сессия; Hermes — поддельный интерпретатор и живой тест.
- `SnapshotStore` (`hub-telegram`): атомарная запись и отсутствие мусора при сбое, права, сортировка, повреждённый манифест пропускается.
- `hub-app`: настройка `[snapshots] dir`, старый `settings.toml` без неё читается.
- `hub-telegram`: `/save` → `/restore` в `Hub`, перенос из прежней темы, отказ во время хода, каталог вне `root`, неизвестное имя.
- Живые тесты на каждый бэкенд (`#[ignore]`): сохранить → удалить сессию у агента → восстановить → ход видит прежнюю историю.
