# v1.1.2 — надёжная синхронизация тем, удаление проектов, роли агентов

Патч-выпуск с тремя доработками поверх v1.1.1: синхронизация тем Telegram теперь достоверно распознаёт удалённые темы и не упирается в лимиты, проект удаляется из хаба вместе с его данными, а исполнитель и ревьюер настраиваются один раз для всех проектов.

## Синхронизация тем Telegram

- Кнопка **«Синхронизировать»** проверяет каждую тему обращением, который Telegram достоверно отвергает для удалённых тем: исчезнувшие темы убираются из списка, живые остаются нетронутыми.
- Обход идёт с паузами и запоминает уже подтверждённые живые темы: повторное нажатие не упирается в «Telegram просит подождать», а начинает с непроверенного остатка.
- Отчёт честный: сколько тем удалено, сколько живых, сколько пропущено из-за активного запуска и сколько не удалось проверить. Неопределённый ответ API никогда не удаляет тему.
- Доказанно отсутствующая тема чистится даже с задачами в очереди: задачи отвязываются от темы и остаются в хабе, не теряются.
- Удаление темы, которой уже нет в Telegram, кнопкой «Удалить» проходит без ошибки API.

## Удаление проекта с данными

- Новый пункт **«Удалить проект»** убирает проект из хаба целиком: задачи с историей, правила, память проекта и привязки тем. Подтверждение — вводом названия проекта.
- Каталог проекта, его worktree и сами темы Telegram не затрагиваются: темы лишь отвязываются от проекта и остаются в группе.

## Общие роли агентов

- На странице «Агенты» — исполнитель и ревьюер по умолчанию для всех проектов.
- Workflow проекта — три режима: выключен, наследовать общие роли, собственный набор. Старые файлы задач читаются без изменений: отсутствие поля означает выключенный workflow.

## Обновление с v1.1.1

Завершите работу агентов и закройте хаб через меню трея. **Перед обновлением сделайте копию файла задач `topics.tasks.json` вместе с каталогом `task-files/`** (пути зависят от системы; см. таблицу ниже).

v1.1.2 добавляет в файл задач новые поля (workflow проекта и запуска). Файл читается со строгой схемой, поэтому **файл, записанный v1.1.2 после включения workflow, прежние версии прочитать не смогут: возврат на версию до v1.1.2 в этом случае не поддерживается**. Для возврата восстановите копию, сделанную до обновления, при закрытом приложении.

| Система | Настройки | Данные |
|---|---|---|
| Windows | `%APPDATA%\agent-hub\config` | `%APPDATA%\agent-hub\data` |
| macOS | `~/Library/Application Support/agent-hub/` | тот же каталог |
| Linux | `~/.config/agent-hub/` | `~/.local/share/agent-hub/` |

На Linux при заданных `XDG_CONFIG_HOME` и `XDG_DATA_HOME` используйте каталог `agent-hub/` внутри соответствующего пути. [Настройки, пути и обновление](https://github.com/aprazdnikov/agent-hub-rs/blob/v1.1.2/docs/guide/settings.md)

В каталоге загрузки проверьте сумму перед установкой. Подставьте имя выбранного файла.

- **Linux** — `sha256sum -c agent-hub-x86_64-unknown-linux-gnu.deb.sha256`. Ожидаемый результат — `OK`.
- **macOS** — `shasum -a 256 -c agent-hub-aarch64-apple-darwin.app.zip.sha256`. После `OK` распакуйте архив и замените весь `agent-hub.app`.
- **Windows PowerShell** — следующие команды вернут `True` при совпадении.

  ```powershell
  $file = 'agent-hub-x86_64-pc-windows-msvc-setup.exe'
  $expected = ((Get-Content -Raw -LiteralPath "$file.sha256") -split '\s+')[0]
  (Get-FileHash -Algorithm SHA256 -LiteralPath $file).Hash -eq $expected
  ```
