# v0.11.0 — одобрения Hermes как у остальных агентов

У Hermes появилась настройка режимов одобрений — такая же, как у Claude, Codex и Qwen.
Раньше хаб всегда спрашивал подтверждения и принудительно возвращал сессию в `default`.

## Режим одобрений Hermes

В «Настройки → Агенты → Hermes» и командой `/mode` в теме:

- **`default`** (по умолчанию) — спрашивает перед каждой правкой файла;
- **`accept_edits`** — правки в рабочем каталоге и во временных директориях без вопроса;
- **`dont_ask`** — правки файлов без вопроса на всю сессию;
- **`yolo`** — `dont_ask` плюс запуск Hermes с глобальной опцией `--yolo`, которая снимает
  вопросы об опасных командах.

Режим применяется при каждом запуске сессии, включая восстановленную по `session/load`, —
ранее выбранный режим не переживает перезапуск молча. Выбор темы (`/mode`) действует, пока
не снят командой `/mode inherit`.

## Что остаётся под вопросом

Ни один режим не отменяет подтверждений, которые задает сам Hermes: чувствительные пути
(`.git`, `.ssh`, файлы с секретами) и его правила запрета спрашиваются всегда, поэтому
кнопки разрешений в Telegram остаются и при `yolo`. Хаб по-прежнему выбирает только
разовое разрешение, «разрешить всегда» не предлагается. Вход, провайдер и конфигурация
Hermes не затрагиваются: в процесс не передаются секреты, `--yolo` — единственный флаг,
который хаб умеет добавлять.

`yolo` убирает вопросы перед опасными командами. Не включайте его на рабочей машине, если
агент может изменить не тот каталог.

## Совместимость

Режимы `accept_edits` и `dont_ask` есть в Hermes 0.22.3 и новее. Если установленной сборке
режим недоступен, разговор прекращается с перечислением доступных режимов вместо неясной
ошибки ACP. Значение по умолчанию не изменилось: прежнее поведение (спрашивать всё)
сохраняется для всех настроек, в которых ключ `approval` не задан.
