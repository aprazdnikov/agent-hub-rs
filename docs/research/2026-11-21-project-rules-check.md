# Проверка правил проекта — шаг 2.2а

Реализованы сохраняемые инструкции проекта: явное включение, редакции с защитой
от устаревшей записи, общий текст для задач каталога, предпросмотр, снимок правил
в истории каждой новой попытки. Старые попытки не получают выдуманную редакцию.
GUI-запуск проверяет актуальность просмотренной редакции. Telegram-запуск читает
текущую редакцию на момент команды. Существующие правила выключены по умолчанию:
до настройки используется редакция 0 без отдельной записи.

Сохраняет тот же actor в существующий файл задач. Отдельного writer нет.
Секреты не добавляются автоматически; пользовательский текст включённых правил
будет передан выбранному CLI вместе с поручением. Лимит 16 КиБ на текст,
100 каталогов; прежний общий лимит файла задач сохраняется.

Git-команды этот шаг не исполняет. Проверяемые fetch, fast-forward и создание
ветки — следующий шаг 2.2б. Настольный режим без Telegram остаётся этапом 3.

## Автоматические сценарии

- Разные каталоги имеют разные правила, устаревшая запись не меняет книгу задач.
- Выключенные правила не включаются в prompt; история старого запуска сохраняет
  прежний текст после изменения правил.
- Перезапуск actor сохраняет редакцию; фактический prompt совпадает с preview.
- GUI отказывает в запуске с устаревшей редакцией до создания попытки и модели.
- Ошибка записи не подтверждает правила и блокирует запуск.
- Ввод в GUI сохраняет фокус и позицию курсора во время фонового чтения;
  несохранённые правила блокируют запуск; после подтверждения отправляется
  StartChecked с новой редакцией.
- Старые полные файлы задач остаются читаемыми и восстановимыми.

Независимая проверка нашла общий egui ID редактора, позволявший перенести текст
между проектами через отмену ввода. Регрессионный тест сначала обнаружил одинаковые
ID, затем прошёл с ID, включающим каталог. Ctrl+Z в другом проекте не возвращает
прежний черновик. Фоновое обновление того же проекта сохраняет ID и фокус.

Неблокирующее отложенное замечание: `/task rules` дублирует текст включённых
правил в ответе Telegram. Содержимое корректно; возможны лишние части сообщения.
GUI и фактическое поручение агента этого дублирования не имеют.

Проверки завершены: `cargo test --workspace` — 2016 прошли, 15 проигнорированы,
49 наборов; `cargo fmt --check`, workspace Clippy с `-D warnings`, `git diff --check`
и `cargo build -p hub-app` успешны. Обновлён `target/debug/agent-hub`.
Коммитов и push в этом шаге нет.

## Ручная проверка новой сборки

1. Полностью завершите старый экземпляр приложения и запустите `target/debug/agent-hub`.
2. В «Задачи» выберите тему нужного проекта, раскройте «Правила проекта».
3. Введите краткую инструкцию, включите «Добавлять правила к каждому запуску»,
   нажмите «Сохранить правила». Проверьте новую редакцию и текст в контексте задачи.
4. Создайте или продолжите безопасную задачу. В истории попытки проверьте редакцию
   и правила; измените правила и убедитесь, что прежняя история не поменялась.
5. Проверьте сохранность после перезапуска. В другом каталоге правила должны быть
   отдельными; Ctrl+Z в его редакторе не должен возвращать текст первого проекта.
