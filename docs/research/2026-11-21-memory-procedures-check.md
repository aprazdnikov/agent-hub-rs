## Реализовано

Один Markdown включён в бинарник, доступен для просмотра и явного копирования
во вкладке памяти GUI. Telegram `/memory procedure` выдаёт тот же текст одним
сообщением, без статуса сессии или меню действий. В теме не требуется заранее
выбранный проект. Существующая авторизация входящих команд сохраняется.

Процедура описывает чтение актуальной ревизии, проверку источников, выполнение
разрешённого шага и обновление фактического статуса с expected_revision.
Просмотр и копирование не создают память, не вызывают модель, не меняют native
skills или настройки CLI. Запись progress требует отдельного разрешения в задаче.

  Оба исправлены в одной итерации: проверка без проекта и точная выдача в связанной

- Полный `cargo test --workspace --locked`: 1952 passed, 0 failed, 15 ignored.

- Финальные Clippy (`--workspace --all-targets --locked -- -D warnings`),
  `cargo fmt --all -- --check`, `git diff --check` и сборка hub-app — PASS.
- На этапе реализации модельных запросов не было. Фактическое сравнение
  Codex/Qwen выполнено позднее 2026-11-21; результаты и ограничения приведены ниже.

Решения: один шаблон вместо каталога/автоустановки skills; текст выдаётся явно и

полномочий. Дополнительные пользовательские процедуры и автоматический выбор
не входят в первую реализацию.

## Сравнение в двух harness перед закрытием MEM-06

Использовать Codex и Qwen с доступными пользователю моделями, по две свежие сессии
каждого. Фиксировать реальные версии/модели; авто-выбор Qwen обозначать auto.
Для сравнения давать одинаковое короткое задание и тестовые данные, не историю чата.

Подготовить отдельную тестовую запись: «проверить существование README.md и его
первый заголовок; ещё не выполнено». В том же тестовом проекте выполнить шаг,
обновить запись фактом выполнения и оставить следующий шаг: проверить существование
Cargo.toml. Дополнительно оставить явно неподтверждённое предположение о приёмке.

1. Контрольная сессия: попросить прочитать запись, выполнить оставшийся шаг,
   обновить прогресс и назвать остаток. Запись разрешена только в тестовый ключ;
   файлы, настройки, commit/push запрещены.
2. Восстановить эквивалентное исходное тестовое состояние под новым ключом.
   Свежей сессии того же harness передать процедуру из GUI/Telegram и такое же
   поручение. Повторить для второго harness.
3. Сравнить: фактически прочитанная ревизия; повторялся ли уже выполненный шаг;
   проверен ли следующий шаг; записан ли актуальный остаток; сохранена ли граница
   неподтверждённой приёмки; сколько коррекций потребовалось пользователю.
4. Сохранить краткие результаты и ссылки на тестовые записи, без полной переписки.
   Если оба контрольных прогона уже успешны, не заявлять доказанное улучшение:
   зафиксировать отсутствие регрессии и ограничение размера выборки.

## Фактическое сравнение — 2026-11-21

Выполнены четыре свежие CLI-сессии: Codex 0.166.0, модель `gpt-6.1-terra`,
reasoning `low`; Qwen Code 0.27.4, выбор модели `auto`. Конкретная модель за
маршрутизацией Qwen не установлена. По одному контрольному и одному прогону с
`continue-work@1` на клиент. Пользователь разрешил сравнение; корректирующих
сообщений моделям во время прогонов не передавалось.

### Условия и наблюдаемость

- Изолированный проект `/tmp/mem06-pilot-20261121/project`, отдельное хранилище
  `/tmp/mem06-pilot-20261121/store`. Рабочая память agent-hub-rs не использовалась.
- В проекте три синтетических файла: README.md с заголовком
  `# MEM-06 synthetic fixture`, Cargo.toml с пакетом `mem06-fixture` версии `0.0.0`
  и evidence.md с результатом прежней проверки README и отсутствием приёмки.
- Четыре эквивалентных ключа созданы штатными `memory_write`: r1 содержит план,
  r2 — реально проверенный координатором README и оставшийся Cargo.toml.
  Клиенты получают имя только своего ключа. История r1 доступна, актуальное состояние r2.
- Общее поручение: прочитать актуальную запись, выполнить оставшийся шаг, обновить
  только свой ключ и назвать остаток; файлы/настройки/другие ключи не менять,
  commit/push и запуск других агентов запрещены. В экспериментальный вариант
  добавлен точный текст процедуры из её Markdown-источника. Копирование кнопкой
  GUI/выдача Telegram здесь повторно не проверялись.
- MCP `project-memory` подключён параметрами одного запуска к собранному бинарнику
  `agent-hub --memory-mcp --project-dir … --store-dir … --actor …`.
  Постоянные настройки не редактировались; посторонние MCP на эти вызовы отключены.
  Codex: read-only sandbox, ephemeral session. Qwen: chat recording отключён,
  сохранены штатные инструкции/skills; чтение файлов и тестовый MCP разрешены.
- Наблюдались события инструментов, ответы `memory_write` и финальные ответы.
  После завершения всех моделей координатор независимо прочитал четыре записи
  через новый MCP-процесс. Содержимое трёх файлов совпало с исходным побайтно,
  других файлов внутри тестового проекта не появилось.

Во всех четырёх итоговых записях Cargo.toml закрыт фактической проверкой; старый

Запись выполнена с `expected_revision: 2`; Qwen без процедуры затем перечитал r3
и самостоятельно исправил искажённую фразу и обозначение «s2» через

а не повторная команда пользователя.

Повторное чтение README было в трёх прогонах; это сверка уже выполненного шага,
а не восстановление его в списке невыполненного. Уменьшение числа чтений не показано.
Qwen в обоих вариантах прочитал файлы до `memory_get`: порядок пунктов процедуры
не соблюдён буквально, хотя запись прогресса опирается на актуальную r2.

### Ошибки и ограничения

- Codex оба раза завершился с кодом 0 (15,2 и 14,8 с).
- Qwen выдал `result: success`, `is_error: false` (64,732 и 68,326 с), но процессы
  после результата оставались живы. Координатор завершил только эти два процесса
  SIGTERM; итоговый код CLI — 130. Это успешное выполнение задания с проблемой
  завершения CLI, не чистый exit 0. Причина удержания процесса не установлена;
  дефект agent-hub из этого наблюдения не выводится.
- В Qwen с процедурой три обращения к native `skill` отклонены: неинтерактивный
  режим не может запросить подтверждение. Агент сообщил ограничение и не обходил
  запрет; MCP-чтение/запись и чтение файлов прошли. Полную совместимость всех
  native skills этот прогон не подтверждает.
- Qwen предупредил о возможном расходе памяти в Node.js 24.21.0. Среда не менялась.
- Qwen без процедуры утверждал отсутствие приёмки в r1–r3, хотя r1 не читал;
  evidence.md и актуальная r2 действительно подтверждают лишь текущую
  неподтверждённость. Это неточность основания, а не доказательство проверки истории.
- По одному наблюдению на вариант недостаточно для вывода об устойчивом улучшении.
  Оба контроля уже успешны: основной результат — отсутствие регрессии проверяемого
  прогресса и границы приёмки, а не доказанное сокращение ручной работы.
