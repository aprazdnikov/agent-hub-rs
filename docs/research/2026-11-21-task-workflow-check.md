# Управление задачами — проверки этапа 1

Ветка: `feat/task-workflow`, база `dfc535e`. Результаты относятся к исходникам
этой ветки; выпущенный 1.0.0 не содержит новых возможностей.

## Автоматические проверки

- Модель: 9 тестов, включая старые файлы, ревизии, приёмку, архив и восстановление
  заполненного компактного файла с 100 задачами. Все прошли.
- Telegram: 3 теста команд и 13 тестов управляемых задач прошли. Проверены
  запрет чужого проекта, ошибка записи, сохранение после перезапуска, чтение
  прежней попытки без изменения истории.
- GUI: 7 тестов прошли. Проверены смена проекта, сброс поиска/фильтра,
  сохранение формы и старого статуса при ошибке, запрет двойной отправки.
- Финальный `cargo test --workspace`: 1993 прошли, 15 проигнорированы, ошибок нет.
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`
  и `cargo build -p hub-app` прошли. Бинарник: `target/debug/agent-hub`.

Новые проверки сначала запускались до реализации и падали из-за отсутствующего
API. Отдельный тест заполненного компактного файла воспроизвёл ошибку объёма:
новые поля переполняли прежний файл. Исправлено сохранением только тех полей,
которые отличаются от восстанавливаемых значений по умолчанию; лимиты не увеличены.

## Ручная проверка новой сборки

Пользователь сообщил, что остальные проверки этапа успешны, кроме мигания формы
«Создать задачу» и сброса курсора. Это подтверждение пользователя, не независимое
наблюдение агента. Повторная ручная проверка исправленной формы пока не подтверждена.

1. В GUI запустите бота, откройте «Задачи», выберите тему своего проекта.
   Создайте «Проверка статусов» с поручением «Прочитай первый заголовок README.md.
   Файлы не меняй». До запуска статус — «Запланирована».
2. Запустите задачу. Пока она выполняется, статус и архив менять нельзя.
   После окончания ожидается «Нужна проверка», независимо от успеха попытки.
3. Выберите «Принята». И список вариантов, и выбранное значение должны быть
   по-русски. Запуск недоступен. Верните «Запланирована», укажите следующий шаг
   «Повтори чтение заголовка и сравни с предыдущим ответом. Файлы не меняй».
   Выполните вторую попытку.
4. В поиске введите «ПРОВЕРКА СТАТУСОВ» — задача должна найтись. Проверьте
   фильтры «Нужна проверка», «Принята», «Все, включая архив».
5. Нажмите «В архив» — задача исчезнет из обычного списка. Выберите «Архив»:
   обе попытки и их полный текст должны остаться. Восстановите задачу.
6. В Telegram той же темы выполните `/task list all`, затем `/task get ID`
   и `/task attempt ID 1`. Последняя команда показывает именно первую попытку,
   а не последнюю. `/task attempt ID 999` даёт понятную ошибку.
7. Возьмите текущую ревизию из карточки. Выполните `/task status ID REV accepted`.
   Повторите команду с той же старой ревизией: ожидается отказ и просьба обновить
   карточку. Новая ревизия и статус видны в GUI.
8. Перезапустите приложение и бота. Проверьте статус, архив и обе попытки.
   Новых запусков без вашего действия быть не должно.
9. В теме другого каталога `/task list all` не показывает эту задачу;
   `/task get ID` и `/task attempt ID 1` отказывают в доступе.

Не проверяйте ошибку записи изменением прав или повреждением рабочего файла:
этот сценарий покрыт автоматическими тестами на изолированном хранилище.

## Ревью и принятые решения

Независимое ревью: `task_workflow_review`. Проверены модель, границы проекта,
обработка ответов GUI, команды Telegram и сохранение полного старого файла.
Два важных замечания исправлены с регрессионными тестами: поиск без фильтра
и редактирование неактивной задачи при занятой теме. Замечание о `status: null`
повышено до важного: повреждённое значение должно давать ошибку, а не возвращать
задачу в доступный для запуска статус. Наличие проблемы подтверждено падающим тестом; после исправления тест прошёл.

Решения исполнения:
- Работа в существующем checkout, в отдельной ветке после обновления main;
  отдельный worktree не создавался. Цена: изменения разделяют рабочий каталог.
- GUI получает задачи своего проекта одним запросом и фильтрует локально.
  Это устраняет запросы на каждый символ; объём ограничен прежними 100 задачами.
- Добавлены необязательные поля формата v1, производные значения не записываются.
  Это сохраняет возможность восстановления заполненного старого файла.
  Цена: старый 1.0.0 не читает явно сохранённые новые поля; нужен backup для отката.

Отложенное небольшое замечание: ответы о несуществующем ID и ID другого проекта
различаются. Это уже существующее поведение чтения; содержимое чужой задачи
не раскрывается. Приложение локальное, для одного пользователя ОС и его разрешённых
Telegram-пользователей; межпроектная скрытность самого факта существования ID
не обеспечивается. Возможное улучшение — единая ошибка «Задача не найдена».

Остальные живые проверки Telegram/GUI подтверждены пользователем после этапа 1. Этапы 2–3 не входят в это ревью.

## Исправление формы создания после ручной проверки

Сообщение пользователя: раздел «Создать задачу» мигает, курсор сбрасывается;
остальное проверено успешно.

Причина: каждые три секунды запрос обновления списка устанавливал `pending`,
а вся панель с полями находилась внутри `add_enabled_ui(!busy)`. При отключении
TextEdit egui терял фокус. Запрос чтения больше не отключает раскрывающийся раздел
и редакторы. Кнопки отправки защищены от повторных запросов; поля замораживаются
только на время сохранения именно создаваемой задачи, чтобы подтверждение
не удалило набранный после отправки текст.

Регрессионный тест `automatic_refresh_preserves_creation_focus_cursor_and_typing`
воспроизвёл потерю фокуса до исправления и прошёл после него. Он открывает форму,
кликает в каждое поле, вводит текст, инициирует автообновление и продолжает ввод
до и после ответа. Проверяются сохранение фокуса и позиции вставки.

Повторная ручная проверка: запустить обновлённый `target/debug/agent-hub`, раскрыть
«Создать задачу», непрерывно вводить название и многострочное поручение хотя бы
10 секунд. Автообновление должно продолжаться без мигания формы и сброса курсора.

После исправления формы: `cargo test -p hub-app` — 367 прошли, 1 проигнорирован;
`cargo fmt --check`, `cargo clippy -p hub-app --all-targets -- -D warnings`
и `cargo build -p hub-app` завершились успешно. Обновлён `target/debug/agent-hub`.
Полный workspace после этой локальной GUI-правки повторно не запускался.

## Исправление мерцания кнопок

Пользователь сообщил об оставшемся мерцании кнопок. Причина: их доступность
по-прежнему зависела от любого `pending`, включая периодическое чтение списка.
Теперь кнопки блокируются только на время изменяющего действия; фоновое чтение
не меняет их доступность. Нажатие во время чтения заменяет ожидаемый ответ:
старый receiver отбрасывается, поэтому поздний снимок не затирает результат записи.
Повторные действия во время записи и повторные запросы чтения не отправляются.

Тест `refresh_keeps_buttons_usable_and_user_action_supersedes_stale_read` сначала
упал на отключённых кнопках, затем прошёл. Он проверяет доступность действий,
нажатие «Сохранить задачу без запуска» при незавершённом чтении, отбрасывание
старого ответа, отсутствие двойной записи и сохранение обеих задач в списке.
Ручная проверка этой поправки пока не подтверждена: оставить вкладку открытой
на 10–15 секунд и проверить кнопки формы и карточек при автообновлении.

После поправки кнопок: `cargo test -p hub-app` — 368 прошли, 1 проигнорирован.
Форматирование, Clippy с `-D warnings` и сборка `hub-app` прошли.
Обновлён `target/debug/agent-hub`.
