## Задача и эталон

Небольшая реальная задача: подготовить русскую Markdown-памятку
`docs/research/memory-quick-check.md`. Codex сохраняет план, Qwen создаёт черновик,
Hermes сверяет его с руководством. Все работают в одном каноническом каталоге
`/home/aprazdnikov/Projects/aprazdnikov/agent-hub-rs`.

Эталон подготовлен до пилота и хранится отдельно от проекта:
`~/mem-01-review/2026-11-15-memory-pilot-reference.md`.
Последующим агентам не передавались эталон и полная предыдущая переписка.

Подтверждённые ограничения: русский язык, Markdown, указанный путь результата;
не менять код, зависимости и настройки; без commit, push и публикации;
без секретов и полных диалогов в памяти. Предположение о необходимости кнопки
экспорта в GUI явно не утверждено пользователем.

## Ошибки и ручные действия

1. **Поиск по префиксу ключа:** запрос mem01-pilot- вернул пустой список.
   По объяснению Qwen поиск проверяет title/body/sources, а не key. Qwen нашёл
   запись через пустой запрос и прочитал её. Это обнаруженное неудобство;
   реализация поиска в рамках отчёта независимо не проверялась и не менялась.
2. **Устаревший статус:** Hermes в r3 оставил цепочку Codex → Qwen → Hermes
   невыполненной, хотя завершил её последний этап. Пользователь сообщил факт
   выполнения, после чего появилась r4. Последующая целевая проверка показала
   корректное обновление прогресса без ручного исправления при явном поручении
   выполнить следующий шаг и обновить статус (результат ниже).
3. **Неполная видимость результатов:** поздние read-only сессии и CLI читали r4,
   куда ещё не внесены выполненные перезапуск, изоляция и тесты противоречий.
   Их осторожное «не установлено» не считается потерей сохранённых данных:
   новые результаты им не были записаны.
4. **Диагностика CLI:** Qwen не подтвердил способ подключения по settings.json.
   Пользователь подтвердил запуск через --mcp-config; для дальнейшей диагностики
   нужно учитывать параметры процесса, а не только постоянные настройки.

Пользователь вручную переключал свежие сессии и каталоги, полностью перезапускал
хаб, запускал самостоятельный CLI и передавал результаты проверок. Пересказа
самой задачи не потребовалось. Потребовалось одно явное исправление статуса
цепочки. Оценка удобства положительная; сравнение с обычной передачей сводки
субъективное, отдельный контрольный прогон и замер времени не выполнялись.

## Целевая проверка обновления статуса

По переданному пользователем ответу Hermes прочитал `mem01-status-recheck@1`
с задачей проверить наличие памятки и её первый заголовок, статусом «не выполнено»
и следующим шагом выполнить проверку. Затем проверил файл и записал r2
с `expected_revision=1`: файл существует, первый заголовок —
`# Памятка первого запуска общей памяти`, задача выполнена, других шагов
по исходной формулировке не осталось. Приёмку документа не объявил состоявшейся.
Пользователь не корректировал результат. По отчёту агента файлы не менялись.

Целевой сценарий пройден. Сырые вызовы инструментов независимо не проверялись.
Этот результат не отменяет наблюдение об устаревшем статусе в основной цепочке
и не является доказательством исправления программного дефекта.
