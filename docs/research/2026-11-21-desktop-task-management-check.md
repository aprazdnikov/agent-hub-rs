# Проверка локального управления задачами — этап 3.1

Дата: 2026-11-21. Ручная приёмка этого этапа пользователем пока не подтверждена.

## Реализовано

Во вкладке «Задачи» добавлен режим «Локально»: выбор папки и агента, создание,
назначение, статусы, архив, поиск, правила и история без токена, бота и темы.
Один сервис владеет книгой задач и записью файла. Изменения GUI и результаты
Telegram сохраняются последовательными операциями над актуальной книгой.
Git временно блокирует изменения, чтение остаётся доступным. Запуск моделей,
Git-подготовка, вопросы и разрешения без Telegram относятся к этапу 3.2.

Формат и расположение `topics.tasks.json` не изменены этим этапом. Ошибка записи
блокирует оба клиента до полного перезапуска приложения. Известный отказ проверки
или лимита не блокирует чтение. Ошибка чтения настроек блокирует локальные запросы,
чтобы неизвестный корень проектов не превращался в отсутствие ограничения.

## Автоматические проверки

- TaskService: конкурентное создание задач и запись результатов без потерь;
  временная блокировка Git; отказ хранения без публикации изменений.
- Локальный порт: сохранение после пересоздания сервиса, старая ревизия,
  изоляция проектов и ограничение настроенным корнем.
- Supervisor: управление без настроек/учётных данных/подключения бота;
  отказ локального запуска без создания попытки; блокировка при повреждённых
  настройках и восстановление после явного сохранения исправленных настроек.
- GUI без окна: открытие проекта, создание без темы, отсутствие автоматического
  переключения режима при подключении бота; прежние проверки фокуса и старых ответов.
- Telegram: создание из GUI одновременно с получением результата; общая блокировка
  Git; отказ подготовки при старой редакции правил; ответ из одного снимка правил.

Независимая проверка исходников выявила три проблемы. Исправлены: сохранение прежнего
проекта после неудачного переключения (также отклоняются относительные пути),
снятие ограничения корня при ошибке загрузки настроек, повторное чтение правил при
формировании Telegram-ответа. Добавлены тесты; исходные ошибки воспроизведены до
правок, тест нового форматировщика сначала не компилировался до его реализации.
Отложенных замечаний этого этапа нет.

Итог: `cargo test --workspace` — 2045 успешно, 15 пропущено, 0 ошибок (52 набора).
`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo build -p hub-app --bin agent-hub` и `git diff --check` прошли.
Собран `target/debug/agent-hub`. Коммита и push этого этапа не было.

## Что проверить вручную

1. Полностью закройте старое приложение, включая значок в трее. Запустите
   `target/debug/agent-hub`. Остановите бота, откройте «Задачи» → «Локально».
2. Выберите существующую папку. При вводе пути вручную нажмите «Открыть проект».
   Выберите Qwen, создайте задачу «Проверка локального режима» с поручением
   «Прочитать README, ничего не менять». Сохранение не должно запускать агента.
3. Назначьте другого агента, измените статус, отправьте в архив и восстановите.
   Проверьте поиск и отображение выбранного статуса на русском.
4. Сохраните тестовое правило, раскройте контекст задачи. После полного перезапуска
   приложения откройте ту же папку: задача, назначение и правило должны сохраниться.
5. Откройте другую папку: задачи и правила первого проекта не должны появляться.
   Введите несуществующий путь и нажмите «Открыть проект»: должна появиться ошибка,
   а операции над прежним проектом должны исчезнуть.
6. Подключите бота: локальный режим и ввод не должны переключиться автоматически.
   Выберите «В теме Telegram» и тему того же каталога: задача должна быть той же.
   Вернитесь в локальный режим — продолжайте редактировать без мерцания и потери курсора.
7. Если настроен корень проектов, попробуйте папку снаружи: ожидается понятный отказ.

Локальный запуск агента пока не является проверкой этого этапа. Не удаляйте рабочие
настройки ради теста; режим без токена проверен автоматически на временном хранилище.
