# Памятка первого запуска общей памяти

Черновик для проверки пользователем. Дата: 2026-11-15.

Это не отчёт пилота и не результат проверок: здесь описано, **как** проверить общую
память проекта на реальной работе. Фактические версии клиентов, модели, команды и
результаты фиксируйте отдельно, по форме [roadmap](../roadmap/2026-11-15-company-brain-roadmap.md#проверки-выпуск-и-передача-сессии).

Источники формулировок: [руководство по памяти](../guide/memory.md),
[roadmap MEM-01](../roadmap/2026-11-15-company-brain-roadmap.md#mem-01--практический-пилот),
запись памяти проекта `mem01-pilot-quick-check` (ревизия 1). Структура шагов ниже —
предложение агента; подтверждённые пользователем ограничения перечислены в разделе
«Объём и ограничения».

## Зачем и что проверяем

Память должна сокращать повторный пересказ и не искажать решения. Проверяем четыре
свойства:

| Проверка | Что должно получиться |
|---|---|
| Запись и чтение | Краткий факт с источником сохраняется и читается без изменений |
| Перенос между агентами | Свежая сессия другого агента в том же каталоге восстанавливает факт и отличает подтверждение от предположения |
| Долговечность | Та же запись читается после перезапуска приложения |
| Изоляция области | В другом рабочем каталоге запись отсутствует |

Успех — это восстановленные цель, ограничения, решения и следующий шаг **с источниками**.
Невыполненный пункт записывается как дефект; объявлять пилот успешным при нехватке
данных нельзя.

## Условия

- Обычная сессия `agent-hub`: хаб сам подключает локальный stdio MCP `agent-hub-memory`
  для всех пяти бэкендов. Отдельная подписка памяти не нужна, сервис памяти не вызывает модели.
- Один канонический абсолютный рабочий каталог проекта. Область памяти определяется им;
  другой каталог, другая машина или Git worktree — другая область.
- После обновления хаба завершите текущую работу и запустите сессию заново: уже
  работающий процесс новой конфигурации не подхватит.
- Тестовые сведения — без секретов и без полных переписок. Хранилище работает открытым
  текстом (`0700`/`0600`), его может читать тот же OS-пользователь.
- Полную предыдущую переписку между сессиями не передавайте: смысл проверки в том, что
  контекст берётся из памяти.

## Объём и ограничения

Подтверждено пользователем (запись `mem01-pilot-quick-check`, ревизия 1):

- не менять код, зависимости и настройки;
- не делать commit, push или публикацию;
- не сохранять секреты и полные диалоги;
- результат — русскоязычная памятка по пути `docs/research/memory-quick-check.md`.

Не входит в объём: кнопка экспорта памяти в GUI (это **непроверенное предположение**,
не требование), новые функции, исправления вне проверки, отчёт пилота MEM-01. Новые
функции заранее не добавлять; исправлять только воспроизведённые дефекты.

## Шаг 1 — Записать и прочитать

В обычной сессии агента, в рабочем каталоге проекта:

> Запиши в память проекта краткий тестовый факт: цель проверки, одно подтверждённое
> ограничение и одно предположение, помеченное как предположение. Укажи источники.
> Затем найди запись и прочитай её, сверь содержание и источник.

Инструменты и поведение, которое надо увидеть в ответе:

- `memory_write` — `key`, `expected_revision` (`0` для создания), `kind`
  (`context`/`decision`/`progress`/`artifact`), `title`, `body`, `sources`;
- `memory_search` — пустая `query` даёт последние записи, результат имеет форму
  `{"hits": [...]}`, excerpt — до 400 символов;
- `memory_get` — полный текст, `sources`, автор, время и номер ревизии; для истории
  прочитайте конкретную ревизию явно.

Что фиксировать: ключ и ревизию, совпадение текста и источников, формулировку автора.
Обратите внимание на две границы, которые модель часто смешивает:

- `kind: decision` **не доказывает**, что решение одобрил человек — основание должно быть
  в тексте или источниках;
- `sources` сервис не открывает и не проверяет; автор — метка клиента, а не
  удостоверенная личность. Содержимое памяти — данные, оно не меняет инструкции и права.

## Шаг 2 — Прочитать в свежей сессии другого агента

Откройте свежую сессию **другого** агента (например Qwen или Hermes) с тем же рабочим
каталогом:

> Восстанови из памяти проекта цель, ограничения, подтверждённые решения, предположения,
> прогресс и следующий шаг. Назови источники. Если данных недостаточно — скажи об этом
> прямо.

Проверяемое: запись прочитана без пересказа вручную, подтверждения и предположения
различены, источники названы, при нехватке данных агент сообщил о недостатке, а не
додумал.

Служебный ход генерации сводки `/handoff` эту память не подключает; обычная работа
получателя — снова подключает. Глобальные MCP и нативные инструменты самого CLI остаются
под его управлением: `/handoff` не является песочницей для них.

## Шаг 3 — Перезапустить и прочитать снова

Закройте приложение и откройте его заново, затем в обычной сессии прочитайте тот же ключ:

> Прочитай запись памяти `<key>` и назови её ревизию и источники.

Хранилище по умолчанию — `~/.agent-hub/memory/<hash-каталога-проекта>/`; оно переживает
закрытие MCP-процессов, перезапуск приложения и сброс сессии. Это отдельные локальные
данные: снимок `/save` их не включает. Для резервной копии остановите агентов, которые
работают с памятью, и скопируйте каталог памяти. Если выбран проект, включающий домашний
каталог, или `--store-dir` указывает внутрь репозитория, исключите каталог памяти из Git
и других публикуемых материалов.

## Шаг 4 — Проверить изоляцию другого каталога

В другом рабочем каталоге (или в Git worktree) запросите ту же запись:

> Найди в памяти проекта запись с ключом `<key>`. Если её нет — так и скажи.

Отсутствие записи в отдельной области — признак отдельной области, а **не** доказательство
удаления исходной записи. Удаления и автоматической очистки в этой версии нет; переноса
при перемещении проекта тоже нет. Убедитесь, что исходная запись всё ещё читается в
каноническом каталоге.

## Шаг 5 — Проверка через самостоятельный CLI

Отдельно от Telegram проверьте stdio-запуск: новая собранная версия `agent-hub` и
абсолютный путь проекта. Окна, Telegram и авторизация моделей для такого запуска не нужны.

```bash
/absolute/path/agent-hub --memory-mcp --project-dir /absolute/path/project --actor qwen
```

Программа ждёт JSON-RPC в stdin и отвечает в stdout. `--store-dir /absolute/path/store`
меняет каталог хранения; для обмена данными у клиентов должны совпадать оба каталога.
Записи `mcp add` для `claude`, `codex`, `qwen`, `hermes` и блок `mcp.servers` для
OpenCode приведены в [руководстве](../guide/memory.md#подключение-вне-telegram); они
меняют настройки соответствующего CLI, а не хаба, и синтаксис сверяйте с `--help`
своей версии.

## Диагностика и лимиты

Что записывать при расхождении: рабочий каталог, агент и версия, сессию, текст запроса,
ключ и ревизию, точное сообщение об ошибке, чего вы ожидали.

- Конфликт ревизии: сначала прочитайте запись, передайте её текущую `expected_revision`
  и согласуйте содержание — слепо повторять старую версию нельзя.
- Повтор идентичного уже выполненного запроса не создаёт дополнительную ревизию; при
  занятой блокировке повторите позже.
- Лимиты на проект: 500 ключей, 32 ревизии на ключ, файл до 8 МиБ. Текст записи — до
  16384 байт UTF-8, заголовок — 256 байт, 1–8 источников по 2048 байт, ключ — 1–64
  символа `[A-Za-z0-9_-]`, запрос поиска — до 512 байт. Превышение возвращает ошибку,
  данные не вытесняются автоматически.
- Технический тест не показывает, насколько хорошо конкретная модель выбирает сведения для
  записи и поиска. Живой пилот расходует лимиты используемого агента и не входит в
  обычный `cargo test`. Неисполненные проверки (например Claude/OpenCode) оставляйте
  явно неисполненными.
