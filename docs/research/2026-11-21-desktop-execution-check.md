# Настольный запуск задач — проверка этапа 3.2

Дата: 2026-11-21. Ручная приёмка пользователем ещё не подтверждена.

## Что реализовано

- Запуск и продолжение задачи без токена и подключения Telegram: используются
  назначенный агент, сохранённые настройки CLI и общий TaskService.
- Каждый запуск — свежая CLI-сессия с контекстом задачи. Полный диалог предыдущей
  CLI-сессии не переносится; история попыток и итоговые ответы сохраняются.
- Подготовка и проверка Git через прежний LocalGitRunner, с текущими ревизиями
  задачи и правил. Ошибка проверки не создаёт попытку модели.
- Панель локальной работы над выбором проекта: статус, остановка, разрешения
  «один раз»/отказ, вопросы с вариантами и свободным ответом.
- Идентификаторы запуска и запроса проверяются при ответе. После отмены или
  абсолютного срока ожидания разрешение отклоняется, даже если обработчик таймера
  ещё не получил процессорное время.
- Бот и локальное выполнение взаимоисключающие. Остановка бота обязательна перед
  локальным запуском; запуск бота во время локальной операции отклоняется.
- Смена сохранённых настроек останавливает локальную работу. Выход ждёт остановку
  с ограничением времени; авария не приводит к автоматическому повтору.

## Границы

Редактор общих настроек пока требует Telegram-реквизиты для сохранения. Сам локальный
исполнитель их не требует: без файла настроек использует CLI из PATH и значения по
умолчанию, при наличии файла — сохранённую конфигурацию агентов. Вход в аккаунт
провайдера выполняется средствами CLI. Передача файлов в GUI пока явно отклоняется;
агент может вывести путь. Автоматическая очередь и параллельный запуск не добавлены.
Настроенные режимы разрешений CLI сохраняются: если пользователь выбрал режим без
вопросов, CLI может не отправлять запрос разрешения в приложение.

## Автоматические проверки и обзор

Проверены: конфигурация без Telegram, явное разрешение и отказ старому ID, таймаут,
запуск/результат/продолжение со старой ревизией, отмена ожидания, ошибка записи без
запуска модели, ошибка Git без попытки, выход без учётных данных, блокировка старта
бота, локальные кнопки GUI, отказ слишком длинному UTF-8 ответу и повтор после ошибки
доставки. CLI-модели за счёт пользователя не вызывались: используются fake executor
и временные хранилища, прежние тесты реальных процессных адаптеров входят в workspace.

Независимая проверка выявила четыре проблемы; все исправлены одним проходом:

1. Stop во время сохранения намерения мог впервые запустить CLI в ветке отмены.
   Тест с блокировкой записи увидел один запуск до правки и ноль после неё.
2. Разрешение после дедлайна могло обогнать обработчик таймаута. Тест с остановленным
   виртуальным временем воспроизвёл принятие позднего ответа; теперь он отклоняется.
3. Первый Save настроек во время локальной работы оставлял ложный Starting; подавленный
   retry тоже оставлял старый статус. При подавлении подключения публикуется Stopped.
4. 9000 кириллических букв проходили ограничение GUI в символах, но превышали 16 КиБ;
   отказ блокировал редактор. Теперь проверяются байты, показывается причина и
   подтверждается доставка ответа; при отказе/потере канала можно повторить или отказаться.

Отложенных замечаний обзора нет. `cargo test --workspace`: 2059 успешно, 15 пропущено,
0 ошибок (52 набора). После выделения метода отображения вопросов повторён
`cargo test -p hub-app --lib`: 353 успешно, 1 пропущено. `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets -- -D warnings`, `git diff --check` и
`cargo build -p hub-app --bin agent-hub` прошли. Собран `target/debug/agent-hub`.
Коммит и push не выполнялись.

## Проверить вручную

1. Полностью закройте старое приложение вместе с треем. Запустите собранный
   `target/debug/agent-hub`. Остановите бота.
2. Откройте «Задачи» → «Локально», выберите тестовую папку с README.md и агента Qwen.
   Создайте задачу: «Прочитай README.md и назови первый заголовок. Ничего не меняй».
3. Проверьте контекст и нажмите «Запустить локально». Ожидается состояние работы,
   затем ответ в истории попытки. Telegram не должен требоваться или подключаться.
4. Для проверки вопроса создайте задачу: «До чтения файлов вызови инструмент
   ask_user_question: спроси, какой файл прочитать — README.md или другой. Дождись
   ответа, затем назови первый заголовок. Файлы не меняй». Ответьте в панели сверху.
   Если агент просто написал вопрос текстом, это не проверка интерактивного канала —
   зафиксируйте этот факт отдельно.
5. Если CLI запросит разрешение, проверьте «Отклонить» и отдельным новым запуском
   «Разрешить один раз». Режим автоматического разрешения CLI ради теста не включайте.
6. Запустите задачу с ожиданием вопроса и нажмите «Остановить локальную работу».
   Запрос должен исчезнуть; попытка — стать прерванной. После полного перезапуска
   попытка остаётся в истории и сама не возобновляется.
7. Укажите новый шаг «Перепроверь прежний ответ» и нажмите «Продолжить локально».
   Должна добавиться новая попытка с прежним контекстом, без повторения старого запуска.
8. Во время локальной работы попробуйте запустить бота — ожидается понятный отказ.
   После остановки локальной работы запустите бота вручную и проверьте ту же задачу
   в теме того же проекта: ID и история совпадают.
9. Git-подготовку проверяйте только в отдельном чистом тестовом репозитории с remote
   и явно указанной базой. Подготовьте новую ветку отдельной кнопкой, затем отдельно
   запустите задачу; при ошибке подготовки модель не должна запускаться.

Форма результата: запуск/результат; вопрос/ответ; отказ разрешения; остановка;
перезапуск без повтора; продолжение; переключение на Telegram; Git; удобство GUI.
