## Результат

Реализован read-only пакет выбранных точных ревизий и краткого поручения.
GUI: выбор из открытой записи, поля поручения, источники, byte budget, полный
preview, проверка свежести и копирование. Telegram: форма `/memory context`,
preview, повторная проверка и выдача нумерованными частями. Пакет вручную передаётся
любому выбранному агенту, без запуска новой модели сервисом памяти.

Сборка использует один snapshot; все записи/источники/ограничения сохраняются целиком.
Бюджет 1024–65536 байт UTF-8, default 16384. Переполнение даёт ошибку с нужным размером.
Отсутствующая версия не заменяется latest и не пропускается. Исторические/stale/archived
записи имеют предупреждения; источники не открываются и помечены непроверенными.
Пакет явно не переносит полномочия и не удостоверяет пользовательское согласие.

Новые автоматические сценарии:

- Полнота текста/источников и точная граница byte budget с кириллицей.
- Источник с отсутствующим файлом остаётся ссылкой; файл не создаётся и не открывается.
- Историческая/stale запись явно отмечена; удалённая ревизия останавливает сборку.
- Выдача пакета другого cwd, после новой записи и после Move отклоняется.
- Дубли ключей, пустые ограничения и недопустимый бюджет не создают память.
- Telegram форма не игнорирует неизвестные/повторные поля; проверяется scope выдачи.
- Разделение Telegram сохраняет все байты, включая переносы и Unicode; каждая часть
  до 3500 единиц UTF-16. Ошибка второй части прекращает отправку без ложного успеха.
- GUI selection сохраняется при новом поиске и очищается при смене проекта.
- GUI блокирует старый пакет после изменения ограничений и удаления записи из состава;
  после пересборки содержит новое ограничение и снова доступен для копирования.

Реальные пользовательские данные и процессы не изменялись. OS clipboard проверен
путём вызова egui, не живым вставлением в другое приложение. Реальный Telegram и
поведение моделей в этой сессии не проверялись. Нативные Windows/macOS не запускались.

## Ревью и принятые решения

Независимое read-only ревью gpt-6-astra high: один Important, без Critical/Minor.
Ошибка: правки формы после сборки не мешали скопировать старые ограничения.
Исправлено сравнением immutable входа пакета с текущей формой перед показом кнопки
и перед обработкой результата копирования. Regression
`editing_constraints_blocks_copy_until_packet_is_rebuilt`: runtime RED → GREEN,
после исправления полная suite зелёная. Начальные RED новых API были ошибками
отсутствующего интерфейса при компиляции; строгий runtime RED для них не заявляется.
Один тест приватной GUI-формы использует временное хранилище inline, чтобы проверить
реальную сборку непрозрачного ContextPacket без расширения публичного API ради теста.

Решения агента по поручению продолжать самостоятельно:

- Явный состав и поручение вместо автоматической LLM-сводки: пользователь выбирает
  ревизии и заполняет поля; скрытой интерпретации/потери ограничений нет.
- Передача копированием/пересылкой выбранному агенту: автоматический старт и /handoff
  не меняются; пользователю остаётся вставить сообщение в выбранную сессию.
- Byte budget вместо оценки токенов; источники только ссылки. Получатель проверяет
  актуальность и содержание, лимит своего harness и контекстное окно.
- Telegram выдаёт точные нумерованные части вместо обычного best-effort Sender.text.
  Использовать нужно все части одной выдачи. Таймаут 30 с и отмена не отзывают
  уже доставленное; успех возможен только после подтверждения всех отправок.
- MEM-04 не перепроверялся независимым reviewer повторно: его тесты сохранены в полной
  suite, а новый reviewer проверил MEM-05 и интеграции. Общие проверки выполнил основной агент.

## Что проверить пользователю на MEM-01

1. Перезапустить новую сборку. В «Память» открыть реальную запись MEM-01 и добавить
   нужную текущую ревизию. При необходимости добавить запись самостоятельного CLI
   и результаты проверок, проверив их источники.
2. В блоке пакета написать цель продолжения, подтверждённые ограничения, текущее
   состояние и следующий шаг; указать источники этих полей.
3. Собрать пакет. Убедиться, что неподтверждённые предположения не превратились
   в требования, а все выбранные записи/источники и ограничения присутствуют.
4. Проверить и скопировать; вставить в свежую сессию другого агента. Попросить назвать
   цель, ограничения, подтверждённые/неподтверждённые сведения и следующий шаг;
   проверить существенные источники перед действием.
5. Оценить, понадобилось ли меньше ручного восстановления контекста, чем в исходном
   пилоте. Без этого подтверждения практический критерий MEM-05 остаётся открытым.

Дополнительно: после preview изменить ограничение — копирование должно потребовать
пересборку. После записи другой ревизии в память старый пакет не должен выдаваться.
Изменения не закоммичены и не отправлены; выпуск не выполнялся.
