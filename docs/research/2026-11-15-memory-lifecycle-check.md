## Что реализовано

- Формат v2, чтение v1 без миграции; перед изменением — проверенная атомарная
  резервная копия v1 без перезаписи существующего файла.
- Статусы, фильтр, разреженная история, ручная очистка и отметки удаления.
- Автоочистка до 32 хранимых ревизий и 8 МиБ; последняя версия каждого ключа
  сохраняется. Если места не хватает, операция не меняет хранилище.
- JSON-экспорт и атомарный импорт, конфликты и копирование под новым ключом;
  безопасный повтор, запрет скрытого включения автоочистки.
- Новое поколение после проверенного полного экспорта, выбор сохраняемых ключей,
  запрет записи из старого MCP-процесса.
- Управление через вкладку «Память» и `/memory`, без вызовов модели.

## Решения при реализации

- Работа продолжена в текущем checkout, чтобы сохранить существующие изменения
  MEM-01/MEM-02. Коммитов, push и публикаций нет.
- Данные ревизий оставлены в карте history; состояние и происхождение хранятся
  в отдельной карте metadata. Файловые операции вынесены в отдельный модуль,
  определение snapshot осталось рядом с владельцем транзакции.
- Начальное incarnation стабильно для проекта, после пересоздания случайное.
  Для v1 token дополнительно учитывает содержимое файла, чтобы старый писатель
  инвалидировал предварительный просмотр.
- Экспорт разделяет неизменяемый snapshot через Arc. Telegram хранит один
  актуальный предпросмотр переноса; кнопки конфликтов/выбора ограничены,
  произвольные ключи доступны через `copy` и `reset-keep`.
- Политика очистки хранится в проектном файле и не зависит от подключения MCP.

## Что проверить пользователю

Используйте отдельный тестовый проект, особенно для удаления и пересоздания.

1. Запустите новую сборку, откройте «Память», выберите каталог и нажмите
   «Показать состояние и записи». У нового проекта режим ручной.
2. На тестовой записи проверьте архив/возврат, фильтр и просмотр версий.
   Сделайте экспорт в новый JSON-файл.
3. Импортируйте файл в другой тестовый каталог: проверьте целевой путь в preview,
   подтвердите и повторите импорт — новых дублей быть не должно.
4. Включите автоочистку только после предупреждения. При 33-й версии должны
   остаться r2–r33; после выключения автоочистки старые версии не возвращаются.
5. В Telegram проверьте `/memory status`, `/memory export` и `/memory import`.
   Экспорт отправляется только после подтверждения; импорт — только после preview.

### Границы решений

MCP get получил дополнительные поля без удаления прежних: сторонние строгие
клиенты должны разрешать расширение ответа. Точное сравнение snapshot и поколение
защищают от запоздалых писателей; ручная внешняя замена файлов при работающих
агентах не является поддерживаемым способом переноса. Подготовленные экспорты
для Telegram временные и удаляются после освобождения сценария; доставленный
файл пользователь сохраняет самостоятельно. Запуск обычной фоновой записи после
её подтверждения не является отменяемой транзакцией: cancel отменяет ожидающие
сценарии и публикацию результатов, но не откатывает уже сохранённые изменения.
