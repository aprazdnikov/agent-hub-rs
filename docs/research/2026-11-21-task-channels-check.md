# Общая задача в GUI и Telegram — проверка

Дата: 2026-11-21. Этап 3.3. Живой Telegram и модели при разработке не вызывались.
Ручные результаты предыдущих этапов не являются приёмкой этого изменения.

## Что изменилось

Один исполнитель и одна книга задач для GUI и Telegram. Подписка `/task follow ID`
не создаёт попытку; результат, запрос разрешения и вопрос относятся к тому же
процессу. Остановка/переподключение бота не отменяют задачу. При выходе приложения
задача останавливается; после перезапуска продолжение ручное.

## Автоматические проверки

Регрессионные тесты воспроизвели и проверили исправления:

- другой разрешённый пользователь не отвечает на карточку подписчика;
- ответ на вопрос из Telegram принимается ровно один раз и закрывает общий запрос;
- скрытый из-за размера вопрос нельзя подтвердить текстом без чтения в GUI;
- смена проекта через выбор проекта отменяет ожидающую доставку немедленно;
- ошибка отправки вызывает ограниченный повтор карточки, без повторного запуска;
- завершение задачи остаётся доступным после быстрого старта другой задачи;
- ошибка предварительной проверки не выдаёт результат прежней попытки за новый;
- команда остановки повторно проверяет текущий доступ пользователя.

Также проверяются запуск одновременно из двух интерфейсов, отказ обычному чату
во время общей задачи, продолжение через `/task resume`, перезапуск бота,
устаревшие кнопки, другая тема и прекращение выдачи частей после отзыва доступа.
Все проверки используют подставные CLI/транспорт; они не заменяют живую проверку.

Проверки сборки: `cargo test --workspace` — 2073 passed, 15 ignored, 52 suites;
`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo build -p hub-app --bin agent-hub` — успешно. Бинарник: `target/debug/agent-hub`.

## Ручная проверка

1. Перезапустите собранное настольное приложение. В «Задачи» → «Локально» откройте
   тестовый проект, выберите Qwen с рабочей моделью. Создайте задачу: «Прочитай README,
   перед итогом задай мне вопрос о желаемом формате ответа. Файлы не меняй».
   Проверьте контекст и запустите. Запишите ID задачи и номер попытки.
2. Подключите бота во время выполнения. В Telegram в теме того же каталога отправьте
   `/task follow ID`. Ожидается текущий запрос/статус, в истории всё ещё одна попытка.
3. Ответьте на вопрос ответом на последнюю карточку в Telegram. Проверьте, что вопрос
   исчез в GUI и появился итог. Если агент не задал вопрос, отметьте этот пункт как
   непроверенный и повторите с агентом/поручением, использующим инструмент вопросов.
4. В другой попытке ответьте через GUI, затем нажмите старую кнопку Telegram.
   Ожидается понятный отказ; второго эффекта или запуска нет. Запрос разрешения
   проверяйте в режиме CLI, который действительно спрашивает подтверждение.
5. Пока задача ждёт ответа, остановите только бота, затем запустите бота снова.
   Исполнитель должен продолжать работу. Повторите `/task follow ID`, ответьте.
   Номер попытки должен остаться прежним.
6. Прочитайте `/task get ID`, затем `/task resume ID РЕВИЗИЯ Назови итог одним предложением`.
   Новая попытка появляется и в GUI; результат приходит в Telegram.
7. Попробуйте `/task follow ID` из темы другого проекта: ожидается отказ.
   Подписавшись в правильной теме, смените её проект: старые кнопки больше не действуют.
8. Проверьте остановку кнопкой и `/stop` из темы того же проекта. Отдельно проверьте
   `/task unfollow`: он отключает доставку, но не задачу.

Компьютер, приложение и интернет должны оставаться доступными. При закрытии
приложения работа не переносится на сервер. Подписку после перезапуска бота нужно
включить заново. После трёх неудачных отправок повторите `/task follow ID` вручную.
При неопределённом сетевом результате возможна лишняя копия карточки; повтор эффекта
агента не допускается. Telegram-сообщение, уже принятое сервисом, отозвать нельзя.

## Решения по финальному review

`/stop` сознательно действует в пределах проекта для разрешённого пользователя,
включая другую тему того же проекта без подписки. Кнопки и ответы остаются привязаны
к подписчику и конкретной карточке. `/task git-stop` отменяет подготовку либо проверку
перед запуском, пока удерживается общая резервация. Это не команда остановки любой
уже выполняющейся агентной работы; для неё есть `/stop`.

Commit, push и публикация не выполнялись.
