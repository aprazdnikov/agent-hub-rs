# Передача задачи и предпросмотр — этап 2.1

Ветка `feat/task-workflow`. Изменения продолжают этап 1 и исправления мерцания;
в релиз 1.0.0 пока не опубликованы.

## Реализовано

- Назначение другого агента у той же задачи с проверкой ревизии и состояния.
  Запись подтверждается до обновления GUI; назначение само не запускает модель.
- История хранит исполнителя каждой новой попытки. Перед первым переназначением
  старые попытки без исполнителя привязываются к прежнему агенту задачи.
- `/task assign ID REV AGENT`, `/task preview ID [STEP]`, исполнитель в карточке
  и в ответе `/task attempt`.
- GUI: кнопка назначения агенту выбранной темы того же каталога и раскрываемый
  «Контекст следующего запуска» перед запуском/продолжением.
- Предпросмотр и фактическое поручение используют один генератор. В нём цель,
  следующий шаг, предыдущий результат как данные, назначенный агент и ограничения.

Предпросмотр — текст поручения хаба, не весь сетевой запрос модели: CLI может
добавить свои инструкции, tools и историю выбранной сессии. Разрешения прежней
темы не копируются. Смена темы сама по себе не меняет назначение задачи.

## Ручная проверка новой сборки

Пользователь подтвердил, что функции работают, и сообщил о неудобном порядке
действий в GUI. Результаты каждого пункта отдельно не переданы; обновлённая
компоновка ещё не подтверждена пользователем.

1. В теме исходного агента создайте задачу «Проверить README»: «Прочитай первый
   заголовок README.md. Не меняй файлы». Раскройте предпросмотр перед запуском.
2. Запустите, дождитесь результата. Запомните ID задачи и исполнителя попытки 1.
3. Введите черновик следующего шага. Создайте/выберите тему того же каталога с другим агентом, например Qwen.
   Задача должна остаться с прежним назначением, пока вы не нажали
   «Назначить агенту выбранной темы: qwen».
4. Нажмите назначение. ID и первая попытка остаются прежними. Модель не запускается.
   Черновик следующего шага должен сохраниться после смены темы и после назначения.
5. Введите следующий шаг «Проверь предыдущий ответ по README, затем назови второй
   заголовок. Файлы не меняй». Раскройте контекст: проверьте поручение, новый шаг,
   прежний ответ и нового агента. Нажмите продолжение.
6. После завершения попытка 1 принадлежит прежнему агенту, попытка 2 — новому.
   Перезапустите приложение/бота: ID, назначение, авторство и ответы сохраняются.
7. В Telegram проверьте `/task get ID`, `/task attempt ID 1`, `/task attempt ID 2`.
   Для непродолженной задачи `/task preview ID` не запускает модель. Для задачи
   с историей нужен `/task preview ID ТЕКСТ_СЛЕДУЮЩЕГО_ШАГА`.
8. По актуальной ревизии `/task assign ID REV hermes` передаёт задачу без запуска.
   Повтор со старой ревизией даёт отказ. В чужом каталоге assign/preview дают отказ.

Версионируемые правила проекта и проверяемая подготовка Git: fetch, обновление

## Независимое ревью и решения

Ревью `task_transfer_review` выполнено по снимку файлов перед этапом 2.1,
чтобы не смешивать изменения с уже проверенным этапом 1.

- Исправлена потеря следующего шага при смене темы того же проекта и при
  назначении другого агента. Регрессионный тест сначала воспроизвёл потерю текста,
  затем прошёл. Сохранение черновика учитывает эквивалентную фиксацию автора старых
  попыток; новый запуск или изменение истории по-прежнему сбрасывают старый шаг.
- Неполная доставка preview повышена с minor до важной: человек должен понимать,
  весь ли текст он получил перед запуском. Части теперь пронумерованы; проверены
  восстановление исходного текста и лимит Telegram, включая emoji.
- Live Telegram/desktop/CLI не объявляются проверенными автоматически. Эти сценарии
  оставлены ручному чек-листу; шаги 2.2 и 3 не входят в текущую поставку.

Решения реализации: этап 2 разделён на независимые шаги 2.1 и 2.2; назначение GUI
использует агента выбранной темы, поэтому перед передачей нужно выбрать принимающую
тему того же проекта. Это сохраняет видимыми каталог и место следующего запуска.

Отложенное небольшое замечание: прямой вызов core `assign` принимает имя вроде
`QwEn`, но сохраняет его в таком регистре; последующий запуск сравнивает с `qwen`.
GUI и Telegram передают каноническое `BackendKind::name()`, поэтому через них этот
случай недоступен. Для будущих независимых клиентов core нужен нормализующий шаг.

## Упрощение порядка действий в GUI

Уточнение пользователя: непонятен порядок назначения, ввода шага, просмотра
контекста и запуска. Карточка теперь показывает три раздела сверху вниз:
«1. Исполнитель», «2. Следующий шаг» (или «2. Поручение» для новой задачи),
«3. Проверка и запуск». Назначение находится в первом разделе. Прежний результат
добавляется автоматически, это объяснено возле ввода. У недоступной кнопки
запуска показана конкретная причина и нужное действие.

История и изменение статуса/архива перемещены в раскрываемые разделы ниже.
Текущая тема приложения и автоматическое обновление сохранены. Рассмотрены
отдельный мастер и одна карточка; выбрана одна карточка, чтобы не добавлять
переходов между экранами. Механизм запуска, ревизии и разрешения не изменены.

Регрессионный тест порядка разделов сначала упал на отсутствующих шагах,
затем прошёл. Старые проверки фокуса, кнопок, сохранения черновика, явного
назначения и точного предпросмотра также проходят.

После изменения GUI: `cargo test -p hub-app` — 372 прошли, 1 проигнорирован;
fmt, Clippy с `-D warnings` и сборка успешны. Обновлён `target/debug/agent-hub`.

## Прямой выбор агента в карточке

Пользователь не нашёл возможности нажать кнопку назначения: прежняя кнопка
появлялась только при несовпадении агента задачи и выбранной темы. Это условие
убрано. Теперь в «1. Исполнитель» всегда видны список «Агент» и «Назначить».
Для назначения выбирать другую тему не требуется. Тема назначенного агента
понадобится только для запуска; отдельная подсказка объясняет это различие.

Выбор хранится как черновик с ревизией задачи. Он переживает фоновое чтение,
сбрасывается при смене проекта или ревизии; при ошибке записи не заменяет
подтверждённое назначение. Запуск с несохранённым выбором запрещён. Активная,
архивная, принятая или отложенная задача показывает причину недоступности кнопки.

Тест прямого выбора сначала упал на отсутствии списка, затем прошёл весь сценарий:
выбрать Codex в теме Qwen, убедиться, что выбор ещё ничего не отправил, нажать
«Назначить», получить подтверждение и сохранить текущую тему Qwen. Отдельный
тест проверяет видимость отключённой кнопки у выполняющейся задачи.

Эта поправка заменяет прежнее решение об обязательном выборе принимающей темы
перед назначением. Ручная проверка: в карточке выбрать другого агента и нажать
«Назначить», оставаясь в прежней теме; проверить новое назначение и подсказку
о выборе подходящей темы для запуска.

После прямого выбора агента: `cargo test -p hub-app` — 374 прошли, 1 проигнорирован;
fmt, Clippy и сборка успешны. Обновлён `target/debug/agent-hub`.

Пользователь подтвердил успешную ручную проверку прямого выбора агента и остальных изменений. Это подтверждение пользователя, не независимая GUI-проверка агента.
